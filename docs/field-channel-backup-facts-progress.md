# 现场完整归档：事实扫描基础

新增完整归档事实扫描，覆盖当前 Acme 基础的 31 张 public 表、1 个派生视图，以及 idms_field 的迁移、点、回执 3 张表。扫描核对编译迁移/权限、完整业务根和审计，记录关系类型、列和生成表达式、视图定义、全部行数/规范文本字节/SHA，以及序列定义和值。

扫描必须由真实显式 REPEATABLE READ 或 SERIALIZABLE 事务调用；仅设置会话默认隔离级别不够。序列值由独立只读备份账号读取，并核对其数据库、服务地址、只读事务和快照与应用读取一致。实际测试使用 pg_export_snapshot/SET TRANSACTION SNAPSHOT。应用账号权限保持原样。

真实最小角色 PostgreSQL 接收测试中已有非空现场点和回执；扫描重复结果保持，同一 RR 不混入随后创建的 schema，新快照发现未知 schema 时拒绝。另以真实 nextval 证明：即使数据行和 RR 快照不变，序列仍可推进，事实摘要也应变化。后续归档必须停写并核对这些非 MVCC 状态，不能把扫描通过当作任意并发下备份一致性的证明。

485 项既有核心单元测试通过，新增构件后 206 项构建/语法及类型检查通过，真实 SQL 接收/恢复围栏故障回归与上述事实检查通过。原 4010 未部署或重启；原企业数据、基础迁移和现场 schema 状态保持，旧 66 份完整文件契约与十轮双份冻结 SHA 保持。

目前只完成事实基础。尚未实现新的完整流式加密容器、同快照 pg_dump、目标数据库恢复、源业务维护停写或恢复计划独立审批。单行规范 JSON 暂限 64MiB，超限拒绝；整体容量和运行资源还须验收。详细后续设计见 `docs/superpowers/specs/2026-10-17--field-full-backup.md`。完整方案 A 继续。
