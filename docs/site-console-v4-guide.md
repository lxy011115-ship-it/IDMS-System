# v4 统一工作台

新入口组合现有数据/模板/审计和维修工作台，提供同源登录、导航与退出。当前通过隔离双企业验证；尚未部署原4010或云端主站，也不是完整商业验收。

## 运行配置

先按既有流程准备各企业的治理与维修 HTTP 配置。新宿主以显式私密文件启动，例如 `node scripts/site-console-v4.mjs C:\IDMS-Private\site.private.json`。文件应存放在仓库外，结构如下：

```json
{
  "format": 1,
  "purpose": "SITE_CONSOLE_HTTP",
  "host": "127.0.0.1",
  "port": 4012,
  "members": [
    {
      "governanceRuntimeFile": "./acme-governance-http.private.json",
      "maintenanceRuntimeFile": "./acme-maintenance-http.private.json"
    },
    {
      "governanceRuntimeFile": "./sandbox-governance-http.private.json",
      "maintenanceRuntimeFile": "./sandbox-maintenance-http.private.json"
    }
  ]
}
```

相对路径按配置文件所在目录解析。最多32个注册企业，当前实际验证2个，不据此承诺32企业容量。各成员必须是HTTP模式，仅持该企业QI、READER、作业密钥与共享认证材料；治理和维修的业务读取配置必须相同。所有企业使用完全相同的OIDC配置、共享认证文件、认证部署和认证审计绑定。启动复用原有数据库目录、角色与隔离核对；逐企业关闭临时校验用认证连接，只保留一个站点认证池和过期扫描器。

HTTP配置拒绝worker、Flowable、AI服务材料及未知字段；浏览器的企业头不能选择数据库。私密API要求tenant和actor头均与实际会话一致，再按会话身份选择注册企业；原领域API继续核对当前权限、范围及CSRF。未注册/挂起企业无法创建新会话。

后台沿用独立治理、维修、AI及认证审计产品入口。新宿主不拥有业务APP或审计投递权限，也不自动创建库、角色或运行后台。认证投递使用 `scripts/auth-audit-worker-v4.mjs` 的专用私密配置与派生outbox密钥，把登录/退出事件写入相应企业审计链。后台授权引用与站点共享同一个会话源，退出后原作业须按既有本人重授流程恢复。

## 页面与路由

- `/`：当前企业、数据与审计入口、维修入口及统一退出。
- `/governance/`：现有模板、资料导入、作业恢复和审计追溯。
- `/maintenance/`：现有维修处理与恢复。
- `/api/v4/site/context`：当前已验证身份对应的企业与工作区状态。
- `/api/v4/site/health`：公共简要存活响应，不返回注册表或私密运行数据。

两控制台的导航由新宿主生成，原冻结HTML/JS/CSS不覆盖。首页不把任何维修正文、审计记录或凭据写入浏览器存储。退出在所有工作区生效。
