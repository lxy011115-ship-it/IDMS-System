# 企业模板、上传映射与插件治理

更新：2026-10-15。本批是可运行的产品增量，不等于完整低代码平台或商用生产验收。

## 使用入口与角色

网站：`http://127.0.0.1:4010/?view=templates`。`tenantadmin` 是模板设计者；`approver` 是业务终审员；`technician` 执行维修。账户密码仅在受限本机账户文件中，不要共享账户或把凭据加入交付包。

1. 管理员在“企业模板”新建模板。`maintenance-form`驱动维修工单字段；新增purpose=import-mapping的模板供CSV/XLSX上传显式选择，使用独立编码和同一发布流程，详见`import-field-mapping-guide.md`。其他非支持用途不改变业务。
2. 设置版本和行业，编辑 manifest 中的字段；保存后可编辑草稿。系统校验 schema、版本、字段及安全策略，不执行脚本。
3. 提交时必须匹配草稿修订号与摘要。提交后冻结，创建人、任何编辑人和提交人即使叠加终审角色，也不能批准该版本。
4. 独立终审员检查字段、相对当前版本的差异和安全边界，填写意见后发布、退回或驳回。退回也保留冻结版本，需要复制为更高版本修改。
5. 新发布版替代当前路由，旧版内容不变并保留历史发布状态。只有之后创建的工单使用新模板，旧工单继续按创建时的字段验收。
6. 维修人员填写基础原因/措施/复测证据和企业字段；服务端校验类型、必填、范围及枚举。终审前再次核对冻结模板与证据摘要。

本批不会自动修改现有企业模板或工单。没有发布过 `maintenance-form` 的企业仍使用标准维修表单；原工单不补造模板和审批历史。

## 字段及安全策略

每个维修模板支持最多12项扩展字段：TEXT（最大2000字）、NUMBER（有限数及上下界）、BOOLEAN、SELECT（1–20个不重复选项）。机器字段编码唯一，不能使用状态、审批、签名、租户或原型等保留编码。表达式、HTML执行、任意脚本和控制指令不支持。

`schemaVersion=1`，`minPlatformVersion` 不得高于当前平台；`policy.finalApproval=INDEPENDENT_HUMAN` 与 `policy.deviceAccess=READ_ONLY` 强制保留。字段约束只能增加企业资料要求，不能覆盖基础维修证据和独立关单要求。

示例包位于 `template-packages/maintenance-form-1.0.0.json`。其中数值范围仅为表单演示，不是厂商或ISO健康阈值，不代表振动达到范围即可安全放行。

## 导入、导出、版本与回滚

- 已发布或历史发布版可以导出 `idms-template-v1` JSON 包。包只含内容和摘要，不含企业ID、账号、审批身份或发布状态。
- 导入验证摘要和schema，创建目标企业草稿，必须重新独立批准。摘要证明一致性，不代表可信来源或批准。
- `parent` 是稳定的 `templateKey@version` 引用。存在依赖时先导入并批准父版本；当前采用完整有效manifest与父版本血缘，不是自动差异继承引擎。
- 不覆盖同版本、不降级发布。回滚通过复制旧内容为更高版本，重新审批；在途/历史工单不静默迁移。
- 业务工单保存模板ID、版本、内容摘要、字段快照及绑定摘要；输入值、模板摘要一起纳入维修证据摘要。

## 当前接口

所有接口加 `/api/v1`，写入要求可信身份、同源/CSRF（浏览器）、幂等键与关联ID。角色由OIDC令牌取得，不能传入permissions自授权限。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | /templates | 本企业版本、验证状态、字段及审批 |
| POST | /templates | 创建草稿 |
| POST | /templates/{id}/edit | 编辑草稿manifest；需expectedRevision/expectedDigest |
| POST | /templates/{id}/submit | 冻结版本；需预期修订与摘要 |
| POST | /templates/{id}/approval | 独立人工发布/退回/驳回；需预期修订、摘要、意见 |
| GET | /templates/{id}/export | 导出发布过的模板内容 |
| POST | /templates/import | 校验导出的包，创建本企业草稿 |
| GET | /plugins | 历史状态及重新计算的清单验签状态；执行始终BLOCKED |
| POST | /plugins | 登记有界清单；不安装、不执行制品 |
| POST | /plugins/{id}/certify | 仅平台认证员可尝试；完整制品流水线未验收时503 |
| POST | /plugins/{id}/activate | 仅独立人工终审身份可尝试；执行隔离未验收时503 |

维修提交可附 `customFields`，值必须与该工单冻结的类型一致；不能自行指定另一模板或把未知字段作为已验证资料。

## 插件信任与未完成边界

上传者不能提供自己的公钥当成信任根。管理员通过部署侧 `IDMS_PLUGIN_TRUST_CONFIG` 指向受控文件，格式是 version=1、keys数组；每项含 keyId、Ed25519 DER/SPKI base64公钥、允许pluginTypes、permissions、tenantIds、expiresAt、revoked。不提供写入该文件的企业API。运维必须限制文件权限；信任配置异常时失败关闭。

清单签名绑定企业、插件名称/类型/版本、权限、签名密钥ID以及完整manifest。manifest包含最低平台版本、artifactSha256、HTTPS网络目标和内存限额。每次验证重算摘要，检查算法、编码、权限范围、有效期与吊销；信任文件每次读取，吊销不必重启核心。

当前只验证清单来源与完整性，没有下载/执行清单中的网络目标，没有完成制品字节验证、恶意代码/依赖扫描、厂商认证流水线、运行沙箱、资源及网络隔离。因此，即使清单签名有效，认证和激活也仍失败关闭；不把签名包装为“安全插件”。历史 `ACTIVE/signed=true` 仅保留原事实，API与界面明确显示未验证且不可执行。本机模拟采集是独立内置服务，不由这个插件注册表加载。

`platform-certifier` 与租户管理员分离，初始化只建立角色，不给任何现有账户自动授予。`system-admin` 当前只读；即使与终审角色叠加，也不会获得业务最终审批/发布或插件认证权限。
