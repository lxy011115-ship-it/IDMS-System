# 设备数据SQL存储与迁移

更新日期：2026-10-15。用于方案A开发平台；多类型设备数据管理优先，生产门禁继续保留。

## 当前数据表

| 表 | 用途及约束 |
|---|---|
| managed_import_rows | 所有已批准上传行的来源索引：企业、顺序、原批次/物理行号、类型、来源系统/记录ID、冻结摘要和原始规范化行。企业/来源/类型/记录ID唯一，批次/物理行号唯一。 |
| managed_assets | 设备编码/名称、工厂/产线、类型、品牌/型号、序列号、关键度。设备在企业内唯一，外键关联DEVICE来源行。 |
| managed_point_definitions | 每设备测点编码/名称、单位、有限物理范围、可选记录间隔。设备/测点唯一，关联设备和POINT_DEFINITION来源行。 |
| managed_measurements | 设备/测点、带时区采样时间、有限数值、单位和GOOD/BAD/UNCERTAIN质量。设备/测点/采样时间唯一，关联设备及MEASUREMENT来源行。 |
| managed_projection_state | 迁移版本1、已投影记录数量及历史前缀摘要。后续写入只能追加，不允许删除或改写已批准历史。 |

设备范围、测点时间、质量/时间及全局时间查询有索引；原行JSON作为证据保留，实际筛选列采用PostgreSQL类型，不以JSON全文扫描代替设备/时间过滤。这些表不会加入预置展示设备，只有真实批准上传才能进入。

自定义测点仍由业务服务在批准前校验定义和单位/范围；原三项工程字典兼容不改变。当前历史定义行为与原接口一致，企业定义不可覆盖；完整字典更正及测点定义版本绑定仍是后续需求。

## 迁移与事务

建表和原已批准记录回填已移动至独立版本迁移命令，由专用migrator显式切换NOLOGIN owner执行；业务启动仅只读检查，不执行DDL或自动补造投影。原批次、原始文件、审批人、业务记录和业务摘要不改写，不改变runtime_state版本号来伪造业务变更。角色及升级步骤见[数据库权限分离](database-role-separation-guide.md)。

已有迁移记录时，逐行核对来源、原行、顺序、记录ID及冻结摘要，检查领域表计数和类型列与原证据一致。投影缺失、被修改或含其他企业数据会阻断启动，不静默覆盖或修复。重复启动只核对，不重复插入。首次迁移失败会回滚DDL和投影写入。

之后每次批准，来源行与领域表在原业务快照、审批、审计和幂等事务内追加；外键、唯一约束或领域表写入失败会一起回滚。四张事实表通过触发器和低权限app授权拒绝UPDATE/DELETE/TRUNCATE。管理员和owner仍可改变DDL，不能宣称数据库所有者无法篡改，独立审计保管仍未完成。

## 查询与兼容

PostgreSQL模式的`/api/v1/data-management/overview`和`/api/v1/data-management/measurements`已使用参数化SQL、稳定排序、LIMIT/OFFSET和只读REPEATABLE READ事务，保证同一返回中的计数、分页与定义来自一致视图。仍限制pageSize≤100。租户来自签名身份，独立连接池与每条SQL的tenant_id谓词同时生效，不接收外部数据库或租户覆盖参数。

文件Demo继续使用同契约的内存实现，测试对类型/工厂/关键词/时间/质量、空结果和多页结果作逐字段比较。时间查询拒绝不存在日期、24点、缺少秒/时区、倒置区间、未知/重复/超长参数。

`/api/v1/health`中的`dataManagementQueries`为`typed-sql-read-model`或`file-snapshot`。这是当前实现路径标记，不是性能或完整性认证；必须同时核对运行代码、实际表数据和浏览器/API验证。

## 验证与备份

`npm run data:verify`在临时真实OIDC/PostgreSQL环境覆盖SQL/文件契约一致、SQL注入探测、领域表写入失败整批回滚、追加保护、旧快照回填、重启及投影损坏时启动阻断。所有破坏/修复只针对本次合成QA数据库，不能在企业库上复用故障注入。

`npm run data:live:verify`只读检查实际4010、新查询路径、领域表与原记录计数、真实登录、桌面/手机和原业务摘要。保留原acme6批/0工单，不为了演示添加虚构设备或工单。证据见`outputs/data-management-verification.json`及`outputs/live-data-management-verification.json`。

原`backup:create`已自动覆盖新增全部公共表，升级前后均有真实备份/隔离恢复验证。备份恢复边界仍见`backup-recovery-guide.md`，不会因新表而自动包含Flowable、身份等独立服务。
