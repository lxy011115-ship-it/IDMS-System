# 数据质量工作台与设备范围

设备运行计划与采样覆盖已单列实现，见[运行日历与计划覆盖](plan-coverage-guide.md)；以下观测质量规则保留，不用日历静默抹去原始异常。

已新增[设备采集质量视图](telemetry-quality-guide.md)，与批准上传分别检查；覆盖当前授权来源的完整窗口、拒收及点表外历史记录。下文原上传规则仍适用于“批准上传”来源，不能将模拟或未批准采集定义视为企业批准依据。

更新：2026-10-16。原本机平台已恢复，入口为 http://127.0.0.1:4010/?view=data-quality 。本节是开发集成进度，完整商用方案A目标仍进行中。

## 使用方法

进入“数据质量工作台”，按设备、测点、带时区起止时间及质量结论查询。默认最近24小时，单次窗口最多31天，结果分页默认50条、最多100条；页面使用20条。这里评估的是已批准有效上传数据，包含已批准更正，不是设备采集页的实时遥测。

页面显示非GOOD记录、相邻记录内部缺口、截至所选窗口末尾的最新记录年龄、企业定义/间隔缺失及待处理批次。可以查看当前定义、版本、原批次和物理行号，定位校验失败、退回或驳回批次的错误明细。批次列表最多显示20项。

## 规则与解释

规则算法版本`upload-data-quality-1.0.0`。以下1.5、3、300是默认参数；绑定设备类型的测点使用当前有效定义批次冻结的质量参数，页面明确展示类型/版本和倍数，详见[设备类型指南](equipment-profiles-guide.md)：

- BAD/UNCERTAIN为数据质量问题，不推断设备故障。
- 没有批准记录时明确显示窗口无数据，不给出健康结论。
- 没有企业批准定义时显示条件不足；旧工程字典单独标识，不冒充企业定义。
- 检查无效时间、超前5分钟的时间、单位不一致、当前物理录入范围和重复采样时间。时间异常检查该测点全部可见有效记录，其余数值/质量规则针对查询窗口。正常上传已拦截这些结构错误，诊断仍保留检查。
- 有声明间隔时，相邻时间差超过间隔1.5倍视为观察到的内部缺口；缺失数量是估计，不包含窗口边界、停产日历或精确计划覆盖率。
- 截至所选窗口末尾，最新记录年龄超过声明间隔3倍时提示时效问题。历史窗口按历史截止时间评估，不当作当前在线状态。
- 未声明间隔时不推断时效和精确缺失数量。物理范围不是报警阈值。

结论分为“有数据问题”“条件不足”“所选规则未见问题”。最后一项也不表示设备健康、质量放行或预测准确。GOOD占比是实际记录的比例，没有虚构综合健康分。所有检查只读，不修改原记录、审批、工单或模型。

## 统一设备范围

受信任OIDC声明中的工厂、产线、设备范围按交集执行。数组与逗号文本声明统一去除外侧空格并去重，仍拒绝非法编码；声明只能由身份管理员维护。HTTP缺少必需范围时拒绝登录，不能用请求头或查询参数覆盖。

已上线设备关联入口增加统一检查：上传报表、批次列表/详情/原文件/错误/差异、预测概览/健康/告警/分析/建议批准、旧报警读写、工单列表/详情/历史/执行/终审/恢复、采集接口及设备关联审计。实际工厂/产线从当前有效批准设备台账解析，旧样例只作有据可查的兼容；归属无法确认时受限身份失败关闭。

报表只汇总授权事实。混合范围批次的原文件、摘要和审批不能安全局部裁剪，因此受限账号须整批可见才可读取或审批。授权记录仍可出现在筛选后的数据中心与质量结果中，但来源会提示“原文件不可见”。批次计数仅包含整批可见批次，所以可能与可见事实数量不成简单比例。无法确定设备归属的失败批次需要企业范围账号排查；系统不会猜测归属来放宽文件权限。

工单还执行operator的本人任务限制。服务端核验完整企业审计链后只返回授权事件，响应`verificationScope=SERVER_FULL_TENANT_CHAIN`及`partialView`；筛选后的事件不能独立重建完整链。租户公共模板、插件目录和连接状态属于公共配置，保持租户级访问；不据此宣称全平台生产安全已经验收。

越权测点上传在读取其他工厂字典前终止该行校验，避免通过单位错误消息探测隐藏配置。未经授权的写操作不改变快照或审计。

## API与验证

```text
GET /api/v1/data-management/quality?deviceCode=&tagCode=&status=ALL&from=&to=&page=1&pageSize=50
npm run quality:verify
```

`status`为ALL/ISSUE/UNKNOWN/CLEAN，禁止未知、重复参数或租户切换。返回窗口、规则版本、测点发现、来源及待处理批次。

真实Keycloak/PKCE/PostgreSQL回归覆盖工厂/产线/设备/跨企业、混合批次、报表、预测、旧报警、工单、本人任务、审计、非法写入回滚、质量规则、批准更正后质量更新、来源/错误抽屉、重启及320/390手机。证据`outputs/quality-scope-verification.json`。原文件上传、多设备SQL、真实Flowable和更正流程也已回归。

质量评估当前使用业务进程中同事务维护的有效快照；不是独立时序质量计算服务。全量业务规范化、多实例、规模性能、现场采集质量、企业日历、可配置规则及生产安全验收继续推进。
