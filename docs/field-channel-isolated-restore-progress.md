# 现场归档隔离恢复与目标准备

本阶段已完成真实非空数据的隔离恢复实验、事务阶段标记和正式 `prepare-target` 命令。正式数据段进程登记、全流程恢复命令、目标唯一核验审计、维护实例和独立终审继续开发。原 4010 未部署 FIELD。

## 新归档的恢复上下文

新操作使用清单 `idms-field-full-backup-v3`，保留原有 facts-v1 的语义，增加经完整GCM认证的 `captureContext`：数据库编码、locale provider、LC_COLLATE/LC_CTYPE、ICU参数、实际排序规则版本，以及事实扫描的六项SQL会话设置。新归档意图v2固定上下文SHA，导出前后一起复核；排序规则版本不一致时拒绝。

v1/v2清单仍按原边界解析，原v1意图/v2归档的重复执行继续复用旧密文。它们未记录完整恢复上下文，`prepare-target` 明确拒绝自动推断；补充可信源上下文和独立复核仍待实现。不得通过改变旧facts解释或忽略行摘要让核验通过。

新的数据库从template0创建，按归档明确的编码和locale参数建立，再核验实际排序规则版本，不伪造旧版本号。相关语法和连接门槛参照 [PostgreSQL 16 CREATE DATABASE](https://www.postgresql.org/docs/16/sql-createdatabase.html)，实际实现另有隔离数据库验证。

## 正式目标准备命令

完成原操作的 `begin`、`freeze-source`、`archive` 后，使用同一 `operation-id`：

```powershell
node scripts/field-recovery.mjs --action prepare-target `
  --authority-config <私密部署配置> --runtime-config <私密源运行配置> `
  --tenant <企业标识> --control-file <私密恢复控制文件> `
  --operation-id <原恢复操作UUID> --backup-file <正式v3加密归档> `
  --key-file <原独立现场备份密钥> `
  --target-runtime-config <原计划对应的新目标运行配置> `
  --target-migration-config <新目标迁移配置> `
  --target-backup-config <新目标只读备份配置>
```

该命令完整认证归档及dump、核对原恢复/冻结/归档记录后，才建立目标。新目标必须匹配先前冻结的连接绑定；四角色互异，不能复用源角色，私密配置摘要持久绑定。错密钥、已有目标、变化的配置或阶段记录不自动接管。

先持久恢复意图，再在一个事务创建四个NOLOGIN最小角色，角色注释绑定原操作、意图摘要和随机provision nonce；精确OID另存。新DB初建禁止连接，在事务里完成ACL和EMPTY阶段注释后才允许连接。只允许被该操作角色能力证明的新目标，未知对象不删除。相同参数重试保留已提交角色/DB OID，SQL提交与外部记录之间的中断由真实catalog、角色能力和库内阶段重验。

准备结束时是空数据库，owner/app/backup/migrator均为NOLOGIN，状态保持RESTORING；输出 `targetDataRestored=false`。它尚未执行数据恢复或激活。源库无需能够连接：实验中将自有源QA库临时改名后，实际准备和后续恢复仍通过。

## 已验证的恢复内核

真实最小迁移身份使用固定PG16工具，依次恢复pre-data、data、post-data。生成的每段SQL与最后的数据库阶段注释由psql单事务执行。提交前错误使表数据及标记回滚；实际服务器COMMIT完成消息被自有本机代理丢弃后，psql虽报错，库内已提交标记仍可辨认，不能再次COPY。序列不是事务数据；失败的数据段可能已经设置序列，必须禁止其他消费者并在最终完整事实中复核，不能宣称序列也随ROLLBACK回退。

原始35关系对象、完整根、审计整链、业务/原件/投影、列和视图定义、序列先全部匹配，再受控重绑定两套迁移表的owner/app/backup。校验时只在不提交的savepoint暂时投影元数据和编译权限，回滚后扫描原文。真正重绑定保留原时间、校验和及所有其他字段，并保留迁移触发器原有的普通或ALWAYS模式；旧审计、点和回执签名原文不更改。

实验包含2点/2回执、非UTC源会话、实际不可连接的源库、错误会话摘要拒绝、最小迁移身份及备份账号真实登录。恢复实验的部署写入由自有QA驱动；正式命令目前只覆盖目标准备。不能将实验通过当作正式数据恢复协调器、独立终审或真实设备验收。
