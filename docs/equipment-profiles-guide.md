# 设备类型模板、继承与冻结配置

更新：2026-10-16。入口：http://127.0.0.1:4010/?view=equipment-profiles 。这是完整商用方案A的一项开发进展。

## 页面操作

1. 企业管理员进入“设备类型模板”，新建类型，填写模板编码、版本、类型编码/名称、扩展字段、测点和数据质量参数。字段支持文本、数字、选择、布尔；测点声明单位、物理范围及可选记录间隔。页面提供结构化表单。
2. 保存草稿并提交。服务端解析固定父版本、冻结继承结果和摘要。未参与创建、编辑、提交的授权终审员核对后批准；退回或驳回保留冻结版本，需复制为新版本修改。
3. 上传员选择已发布类型，填写来源系统、来源记录ID、设备名称/编码、工厂、产线和类型扩展值，提交台账批次。另一人终审后，设备才成为有效台账。
4. 输入已批准的设备编码，生成该设备冻结类型的测点定义批次。生成仍需独立批准；使用历史已批准设备的退役配置也会保留原版本。
5. 上传测点记录后，在数据质量工作台查看缺口、时效和规则来源。展开“定义与评估依据”，可以看到类型编码、版本和具体倍数。

类型管理使用`tenant-admin`的编辑/提交权限，发布使用`final-approver`。台账/测点提交使用`upload`，入库使用独立`approve`。工厂、产线、设备范围由管理员分配的签名声明执行；不能由文件或请求头指定权限。平台管理员不能通过叠加角色获得业务审批职责。

## 固定父版本与声明边界

父类型必须为本企业已发布或退役的具体`模板编码@版本`，最多5层，拒绝循环、未发布父类型或其他用途。子版本声明同编码项时覆盖该项；未声明项沿用固定父版本。显式填写“移除父字段/测点”才会删除继承项，删除不存在项报错。解析结果要求1至64个测点、最多12项扩展字段。

字段编码和测点编码使用小写字母开头、数字/下划线，拒绝保留名称。字段支持必填、数字范围、文本长度和选择项；不执行脚本或表达式。同一模板编码不能变更用途或设备类型编码。物理范围用于输入有效性，不能当作故障阈值；旧工程样板测点的单位和范围不可重定义。

质量参数允许部分继承：内部缺口倍数1.1至20；窗口末尾时效倍数1至100；未来时间容差0至300整数秒。无父类型且留空时使用1.5、3、300。没有声明记录间隔时不推断时效或精确缺失数量。规则只评估上传数据，不产生健康、RUL或质量放行结论。

## 版本升级与更正

发布新版只改变新绑定的可选版本，不改写已有台账、测点、待审批次、历史分析或工单。原版本退役后，旧待审批次仍可按冻结配置终审；普通新上传不能重新选择退役版本。生成测点使用已批准设备的冻结类型，因此台账尚未升级时仍使用原配置。

在数据中心或已入库批次行打开“历史/更正”，默认保持原类型。显式选择同设备类型编码的已发布新版，才创建配置升级的下一记录版本，并再次独立审批。设备扩展值使用新版本的结构化字段表单。新增必填字段、类型名称变动等可能要求先更正设备台账，再升级测点；否则测点校验失败。修改物理范围仍需保证所有依赖数据有效。只升级质量参数也会形成明确的来源配置变更，不能悄悄改变旧定义。

原值、文件、审批、行号、父链和摘要保留；批准前旧版本有效。退回/驳回、更正冲突或SQL写入失败不切换有效值。重复生成已有测点沿用原有判重/冲突规则，不能覆盖已批准的不同配置。

## API与文件

`GET /api/v1/equipment-profiles`返回本企业类型版本。模板生命周期和包导出/导入沿用`/templates`接口。跨企业需先导入并独立发布父包，再导入子包；不会复制原企业ID或审批状态，也不提供自动打包整条父链。

`POST /api/v1/equipment-profiles/points`仅接受`{"deviceCode":"PUMP-01"}`，生成`PROFILE_GENERATED`待审批次。它不接受调用方自带的解析结果、类型绑定或审批身份。所有写请求需幂等键；浏览器会话还需同源Origin和CSRF，上传接口需UUID关联ID。返回成功不代表已经批准入库。

CSV/XLSX文件上传的`equipmentProfileRef`为JSON文本，JSON records请求则为对象：`{templateId,version,contentDigest}`。仅设备台账/测点定义支持。可同时选择企业表头映射，映射后仍做类型和值校验，原文件不改写。JSON records不接受表头映射。

设备扩展值在标准`profile_values`单元格中使用JSON对象文本，数字和布尔值必须为对应JSON类型。页面建档表单会生成该字段。`source_profile_ref`由服务端生成；普通文件可以留空，不能伪造另一个版本。没有类型绑定的普通标准上传仍兼容，空的类型列不触发绑定。

批次冻结`equipmentProfileBinding`、解析结果、父版本摘要和接收审计；原文件摘要/物理行号进入输入摘要。删除/篡改绑定、父链、类型内容或审计锚点会在审批、启动及备份校验时被拒绝。类型配置保存在现有模板/运行快照和JSONB领域记录中，本批没有引入新的SQL结构迁移；不代表全业务规范化或多实例已经完成。

幂等回放前重新核对当前请求的有效身份权限及数据范围，在串行写队列内读取回执前也重检，防止等待期间设备归属变化导致旧回执泄露。身份角色仍遵循令牌/会话刷新机制；这项修复不宣称外部身份撤权能瞬时注销所有旧令牌。

## 验证与后续

`npm run equipment:verify`使用独立临时企业数据库、OIDC客户端和账号，验证结构化页面、继承、四种字段、独立审批、JSON/CSV/XLSX及组合映射、退役与旧批次、显式升级、事务回滚、权限/范围变化后的幂等重试、重启、绑定篡改、加密备份/隔离恢复和桌面/320/390手机。测试不向原客户企业写入样例。

结果见`outputs/equipment-profiles-verification.json`。完整商用方案A仍需多实例并发、全业务规范化、时序/对象/搜索/事件基础设施、现场接入、预测模型/标签/RUL、生产安全、跨服务灾备与发布/授权验收。生产门禁继续关闭。
