# 本地真实 AI 网关与上传影子审核

适用：方案 A 本机开发集成。更新于 2026-10-15。完整商用目标和生产启动门禁不变。

## 安装与边界

- 便携 Ollama 0.40.4，安装包比对官方发布 SHA-256：`7485a1172f8527db4342a63521b9342fc466185ff0855da378cc864ecf6354cf`。
- 本地 `qwen3:4b`，固定 manifest：`sha256:359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`。每个官方模型层分别验证大小和 SHA-256；标签变更不会静默更新。
- `/api/show` 返回的模型许可已核对为 Apache-2.0；原文与摘要保存在受限 `.local/ai/model-manifest.json`。这不是整个产品的法律或商用许可审计结论。
- 运行时及模型位于 `%LOCALAPPDATA%/IDMS/`；没有修改系统 PATH、安装全局服务或设置开机启动。Ollama 初次启动会在当前用户的 `.ollama` 中建立运行时身份密钥，不得打包或分享私钥。
- Ollama 仅监听 `127.0.0.1:11435`，网关仅监听 `127.0.0.1:4018`。`OLLAMA_NO_CLOUD=1`。本批不发送企业数据到云模型，也不搜索或读取外部密钥。
- 部分代理将官方对象存储解析为 fake-IP，Ollama 自身下载保护会拒绝该跳转。`ai:setup` 使用明确的官方 HTTPS 地址下载固定 manifest 和分层文件，逐层校验后离线置入模型缓存；不关闭 Ollama 的地址校验。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-runtime.ps1 -Component ollama
npm run ai:setup
npm run platform:start
```

当前平台默认要求已安装的固定本地模型；缺少模型会明确报错，不会退回模拟并声称真实 AI 已连接。平台只管理本次启动的进程，已被占用且身份未验证的端口不会被替换。Windows 退出时清理本次拥有的 Ollama 进程树，避免遗留推理子进程占用 GPU。

## 实际业务链路

1. 用户通过真实 OIDC 登录后上传 CSV/XLSX/JSON。客户端无法用 `aiMode=demo` 绕过服务端真实审核策略。
2. 确定性校验覆盖整批字段、主数据和数值规则；格式错误停留在校验失败。全量字段出现可疑指令信号时直接人工复核，启发式检测不代表已解决所有提示注入。
3. 有效新批次进入 `AI_PENDING`。批次、请求幂等、审计及 `ai_review_outbox` 在同一企业 PostgreSQL 事务提交。没有事务就不接受真实 AI 任务。
4. 后台在事务之外向网关投递冻结请求。仅发送规则摘要、范围说明和最多 12 行分布式抽样摘要，限定字段长度；没有任意 URL、SQL、文件、控制设备或业务写入工具。
5. 网关校验企业服务身份、请求摘要和证据摘要，固定模型和提示/策略版本后执行真实本地推理。输出只能选择限定结论、风险、证据 ID 和问题代码，不接受自由生成的业务批准或寿命预测字段。
6. 第二校验器拒绝结构错误、伪造证据、结论风险冲突、未覆盖数据却宣称通过等情况。模型自报置信度记录在回执中，但未经校准；业务 `confidence` 保持 `null`。
7. 真实推理和失败策略均产生绑定企业、输入、对象和请求的 HMAC 回执。每企业独立 SQLite/WAL 保留输入摘要、原始模型输出与回执；响应前持久化，相同请求取得同一回执。它是本机开发日志，不是生产不可变审计或多实例存储。
8. 业务端再次验签并核对模型 pin、冻结版本、内容摘要和证据引用，将结果、任务及审计同事务提交。
9. 默认全部进入 `HUMAN_REVIEW`：授权独立用户必须填写人工复核依据及终审意见，才能批准入库。上传人即使叠加终审角色也不能自审。处理中禁止批准；AI 或服务凭据不能最终批准。

语义审阅始终明确为抽样/摘要，不能声称逐行完整审核。旧导入批次不重新推理、不改写模型标记，不伪造真实 AI 历史。

## 故障行为

| 情况 | 行为 |
|---|---|
| 模型不可用、输出错误、注入信号、证据冲突 | 有原因的人工复核回执；不自动批准 |
| 模型已完成但网络响应丢失 | 重发原请求 ID，取得原持久回执，不创建第二个业务结果 |
| 网关在已接受但未完成时退出 | 重启后产生 `GATEWAY_RESTART_INTERRUPTED` 人工回执，不补造推理成功 |
| 网关超时/容量不足 | 有界原请求重试，耗尽后人工队列；不换请求 ID 绕过 |
| 回执已完成、业务 SQL 提交失败 | 保留原 outbox，重读相同回执后再事务提交，不将 SQL 失败解释成 AI 已完成入库 |
| 签名、企业、模型版本或冻结输入不匹配 | 不采用该回执，进入人工复核或冲突审计 |
| 重启缺少已有批次所需的网关配置 | 拒绝启动，不能静默退回演示 |

## 接口与页面

- 业务侧 `GET /api/v1/ai/status`：继承业务 OIDC、租户和只读权限；返回实际网关与固定模型可用状态、影子模式及最后回执摘要。就绪不等于已执行真实推理，也不等于模型精度已验证。
- 既有 `POST /api/v1/data-imports`、`/data-imports/records`、批次查询和 `/approval` 保持版本化。`AI_PENDING`、`aiReview.gateway` 为新响应字段；见上传 OpenAPI。
- 内部 `POST /v1/reviews`、`GET /v1/status` 使用每企业独立 Bearer 服务密钥和 `X-IDMS-Tenant`；不是浏览器/企业用户直接调用的批准接口。
- 上传页显示真实审核模式；批次详情显示请求、模型、提示、策略、摘要、回执、范围和用量。处理中自动刷新，最终批准仍使用原有冻结版本和独立用户规则。
- `.local/ai/` 及 QA 凭据不得进入 ZIP、日志或聊天；原企业上传数据不作为演示打包素材。

## 验证

```powershell
npm test
npm run build
npm run ai:verify
```

`ai:verify` 使用生成的独立 QA 数据库、真实 OIDC 用户和合成输入，区分真实本地推理测试与合成恶意模型响应测试；不更改 acme 的六个既有上传批次。不仅检查连接，也验证幂等、事务失败、丢响应、重启、权限、人工终审和桌面/手机页面。成功证据输出为 `outputs/ai-verification.json`。
