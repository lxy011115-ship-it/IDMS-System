# 来源与点表审批

来源审批管理的是“接收时使用哪份配置”。它不会逐个批准测量值，也不证明报文所写 eventTime 时现场采用了相同配置。当前仍是开发验证平台：现场通道、证书验收和任意测点采集需要另行实施。

1. 在“设备采集”中确认当前企业的 edgeId、设备和公开点表。设备台账、测点定义须先导入并由其他授权人员批准；缺少依据或不在当前账号范围内时，治理查询返回 404。
2. 在“来源与点表审批”填写 edgeId，核对当前审批状态、运行映射及接收审计。也可在“企业模板”新建来源点表审批草稿，填写 edgeId 后点击“读取此源与当前批准定义”。
3. 从服务器返回的当前批准定义中选择测点，填写只读节点标识、映射版本、带时区生效时间和依据。无需手工抄写批次摘要。暂停条目不包含点表；恢复时须再次核对引用。
4. 保存、提交冻结，再由未参与该版本的授权终审员批准。每个 edge 只能属于一个编码族，版本间不能改绑 edge 或设备；同一设备可以有多个独立 edge。首次用 INITIAL，未来调整用 PROSPECTIVE，改变已生效内容须明确选择 RETROSPECTIVE_CORRECTION 并说明依据。

有任何发布历史的来源，每次接收都会先核对当前审批与定义，再处理旧回执。暂停、映射不符、设备身份不符或定义更正后，旧成功报文也会收到拒收确认，并追加重放被拒审计；原测点与原成功回执保持原样。之前拒收的同一报文不会因后来批准而被改写成成功。恢复须新建版本、引用当前定义并独立批准。

没有发布历史的既有开发模拟源保留兼容接收，明确标记为“未人工审批”；它不属于已批准现场源。审批 FIELD 配置也不会开启现场通道。现有启动通道只支持原三类内置测点；声明更多测点不等于已完成其采集适配。若运行实例的公开配置观察已过期，页面会另行提示；配置审批通过仍不能绕过接收事务的配置栅栏。

“接收审计开始/结束/资料截止”筛选父审计的业务时间，采用前含后不含窗口，最长 31 天。当前配置状态按本次评估时刻核对，历史每条记录保留各自的接收依据。分页不截断整窗计数；超过 25,000 条、证据不一致、查询取消或预算不足时，不返回部分成功。大点表或大元数据也可能先触发预算上限，应缩小窗口或调整经过验证的容量配置。

下载会包含整窗公开审计、来源配置、审批版本与定义引用、结果和摘要，不包含密钥、状态 URL 或被拒报文中的其他设备正文。引用旧兼容测点的后续回执会明确保留“原测点未审批”，不会追认原测点。

离线执行：

```powershell
node scripts/verify-source-evidence.mjs <idms-source-governance.json>
```

输入文件上限 256 MiB。校验器重算公开依据、审计见证和结果的内部一致性；服务器另在同一已验证只读快照中核对原始回执、报文摘要与测点。公开包不重新认证历史 HMAC、外部签发身份、可信授时或物理提交时刻。它是配置取证包，不是新的分析报告终审类型；旧覆盖报告、质量规则和运营报告的冻结计算保持原版本。

接口为 GET `/api/v1/telemetry/source-governance` 和其 `/export`。查询只接受 edgeId、from、to、knownAt、page、pageSize；时间为明确 UTC 毫秒格式，pageSize 最大 200。公开输入为 `idms-source-evidence-input-v1`，包为 `idms-source-evidence-v1`，计算规则为 `source-evidence-1.0.0`，来源绑定为 `approved-source-binding-1.0.0`。未来规则变化须保留本轮固定向量及 v1 依赖的重算能力。

策略最多 64 个生效条目，每条 128 个唯一测点/节点，全版本合计最多 512 个绑定。策略包文件上限 8 MiB；模板新建、编辑和导入的请求体上限 8 MiB，较大请求仍受解析预算约束，其他业务 JSON 请求保持 1 MiB。
