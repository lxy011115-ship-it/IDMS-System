# IDMS 手动运行与备份巡检

更新：2026-10-31。用户已批准方案A；本工具在已有平台旁独立运行，主站无需重启。它帮助管理员区分进程存活、依赖状态、最小数据库绑定和备份证据，不能替代企业签收或生产放行。

## 运行一次检查

在项目根目录使用现有 Node.js 24.20.0 和已安装的锁定依赖：

```sh
npm run platform:inspect
npm run platform:inspect -- --verify-backups
node scripts/inspect-platform.mjs --json
```

Windows也可双击根目录“检查IDMS本地运行.cmd”。窗口显示结果后等待按键。命令不会安装依赖、启动服务、初始化账号或自动重启；依赖未运行时会如实报错。

每次报告默认写入新的 `.local/inspection-reports/<随机标识>/`，含 `report.txt` 和 `report.json`。报告目录和文件使用现有私密文件权限工具保护，不纳入源码。支持显式的新目录：

```sh
node scripts/inspect-platform.mjs --profile .local/runtime-inspection.json --verify-backups --output .local/inspection-reports/manual-check-001
```

已存在目录会被拒绝，不覆盖历史报告。`--json`使标准输出只有JSON；需要脚本解析时直接调用Node命令，避免npm附加标题。原始异常、口令、令牌、连接串、业务正文和完整私密路径不会写入报告。仍应把报告作为内部运行材料保存。

| 退出码 | 含义 |
| --- | --- |
| 0 | 所有必需项在各自证据范围内PASS |
| 1 | 至少一必需项FAIL |
| 2 | 必需项没有FAIL，但存在UNKNOWN或NOT_CONFIGURED |
| 3 | 参数、配置、输入边界或报告保存未完成 |

可选项异常仍完整显示，并计入 `attentionItems`。退出0不表示全部13项通过，更不表示生产验收通过。`productionAcceptance`和`enterpriseUserAcceptance`始终为false。

## 配置方式

默认先读取 `.local/runtime-inspection.json`，不存在时使用公开的 `infra/runtime-inspection.example.json`。所有相对路径均以项目根目录解析，不受当前终端目录影响。公开示例只含地址、私密配置文件路径和检查预算，没有账号口令。

需要调整时复制示例到 `.local/runtime-inspection.json`，按已核实的本机拓扑编辑，不覆盖已有私密业务配置。巡检文件只引用现有凭据文件，不填写新密码或服务令牌。

| 字段 | 用途与限制 |
| --- | --- |
| `required` | 必需组件，必须含core；拒绝重复及未知名称。示例必需10项为core、business、sessions、identity、workflow、predictor、ai、model、telemetry、mqtt |
| `budgetMs` | 总观察预算，默认30000，最大120000毫秒 |
| `concurrency` | 同时最多2项，允许1或2 |
| `httpMs` / `tcpMs` / `databaseMs` | 默认3000 / 2000 / 3000毫秒，均不能超过各自默认上限 |
| `core` / `predictor` / `model` | 已核实的回环地址、存储模式和模型版本 |
| `business.config` | 现有BUSINESS_RUNTIME受限应用身份配置；不能使用部署管理员替代 |
| `sessions.config` | 显式AUTH_SESSION_RUNTIME配置；null时按企业部署绑定定位现有文件 |
| `identity` | 现有身份origin/realm配置或显式issuer；同时指定时必须匹配 |
| `workflow` / `ai` | 既有客户端文件及明确的本机服务地址，企业集合须匹配业务配置 |
| `telemetry` | 现有采集文件和允许的状态接口origin；当前适配明确标记SIMULATOR的来源 |
| `resources.tokenFile` | 可选的既有维护令牌文件引用；旧配置省略时资源项未配置，不猜测文件 |
| `disks[].minFreeBytes` | 经运行负责人确定的最低可用字节数；null表示尚未设阈值 |
| `backups.directories` | 明确的既有备份目录。优先选择本次需要核对的完整备份批次目录 |
| `backups.keyFile` | 现有档案密钥文件；仅显式认证时读取 |
| `backups.maxAgeHours` | 经负责人确定的最大备份年龄；null表示尚未设策略 |

端点只接受字面回环地址127.0.0.1或[::1]，拒绝URL内凭据、查询串、片段和重定向。私密输入拒绝符号链接、硬链接和超出预算的文件；配置支持UTF-8及UTF-8 BOM。云端需先核实实际拓扑与凭据，不能复制本机企业连接文件到服务器。

## 读懂证据

| 项目 | 本轮实际检查 | 仍未证明 |
| --- | --- | --- |
| 主站 | 既有健康GET中的版本、OIDC及数据库/会话模式 | HTTP UP不证明数据库或其他依赖就绪 |
| 企业库 | 当前库/角色权限与企业最小绑定，只读事务 | 全量业务、审计链或所有表完整性 |
| 会话库 | 最小结构、迁移校验和与部署摘要 | 当前用户登录、密钥见证及真实会话签收 |
| 身份 | OIDC发现文档发行者匹配 | 真实账号登录、撤权或所有回调流程 |
| 工作流/预测/AI/模型 | 现有GET状态契约、版本和模型摘要 | 新流程执行、现场准确率或模型生成质量 |
| 采集 | 状态身份、模拟只读模式、连接、样本、缓存计数 | 现场设备接入或样本时效SLA |
| MQTT | 端口及已有边缘报告的MQTT会话 | 端口可达不证明消息已入库、已确认或设备在线 |
| 磁盘 | 目标卷可用空间及显式阈值 | 无阈值时不能判容量正常 |
| 资源 | 可选维护令牌引用读取被访问主站的实时计量；旧配置保持未配置 | 应用预算/进程RSS不代表操作系统生产容量，见[就绪与资源说明](runtime-readiness-guide.md) |
| 备份 | 有界候选元数据；显式选择时认证清单及dump | 已实际恢复、异地保留、调度或跨服务灾备 |

采集状态即使MQTT/OPC均连接，只要报告 `SPOOL_CAPACITY_REACHED`、`capacityBlocked`，或待确认加拒绝记录达到明确容量，也会返回 `TELEMETRY_BUFFER_FULL`。报告保留数量和容量，不输出原始样本或任意错误正文。应核对主站接收及确认链路并保留未确认资料；不能通过删除缓存把状态变绿。没有有效样本或存在其他未确认错误时为UNKNOWN。

来源Git提交、源码清单摘要及巡检配置摘要用于定位报告。它们是磁盘源码元数据，`provesRunningCommit:false`，不能证明网站进程正在运行该提交。

## 备份认证的边界

默认只查文件，不读取密钥或解密，结果为 `ARCHIVES_NOT_AUTHENTICATED`。使用 `--verify-backups`才逐份认证格式2业务档案、企业、源数据库、清单及dump摘要；解密后取得的dump缓冲清零，不落临时明文，不调用恢复或创建数据库。共享档案读取器同时在认证/清单失败路径清理可变解密缓冲；这不是对JavaScript运行时内存作安全擦除保证。

每企业最多32个候选，目录深度最多2层、最多64个目录，条目预算为企业数×32+128；单档案沿用128MiB压缩dump和256KiB清单预算。范围超限返回UNKNOWN，不能跳过新坏档案或回退到旧档案冒充通过。目录名必须按企业前缀命名档案，未绑定企业或来源不符明确失败。

扫描整个历史总目录超限时，应选择经核实的完整批次目录，不自动删除旧备份或扩大预算。所有候选认证成功且每企业都有档案后，仍需明确的时效策略才能给出PASS；没有 `maxAgeHours` 则为 `BACKUP_AGE_POLICY_UNSET`。真正恢复仍按[备份恢复说明](backup-recovery-guide.md)在隔离目标中单独验收。

## 超时与取消

HTTP每响应上限64KiB；数据库使用现有应用身份、只读事务、最小SELECT和回滚。到达观察预算或按Ctrl+C后，停止调度新项，取消本次拥有的请求或数据库查询，并等待原任务、回滚、连接及池实际收尾。报告区分观察超时和完成时间；30秒不是强制终止承诺，也不会因超时另启一套检查。

未启动项及迟到成功均不能变成PASS。工具不主动修改服务配置、授权、业务数据或备份，不发布MQTT消息，不触发AI生成和对外告警。
