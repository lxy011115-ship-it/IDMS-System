# 本地启动与演示候选包

更新：2026-10-30。当前仍为本地开发/企业试点准备，正式生产门禁保留。

## 已有本地平台

使用根目录“启动IDMS本地网站.cmd”或当前`start-platform-v4.mjs`。普通启动只读取已有身份配置、核对发行者和必要时启动既有身份进程，不调用完整账号初始化。身份库未初始化、配置缺失或端口被其他服务占用时会明确停止，不通过恢复默认授权来使登录成功。

`npm run auth:setup`是显式初始化命令，仍有创建realm、客户端和角色定义等管理操作，应在独立的初始化流程使用，不能作为日常重启或离职撤权后的“修复”步骤。已有账号的停用状态、角色及范围由企业管理员维护，重复初始化不自动覆盖。仅新建账号获得初始角色和临时密码；中断的新建流程如果缺少角色，需管理员核对，脚本不擅自补回。

普通进程不会继承bootstrap管理员、导入或Java覆盖参数；不输出数据库密码或令牌。本机仍使用回环开发模式，不代表完成生产身份服务验收。登录会话失效时从网站进入正常企业登录，不能改用伪造角色的请求头。

## 构建演示候选包

在项目目录执行：

```powershell
npm run demo:package -- --plan
npm run demo:package
node scripts/package-check.mjs outputs/实际生成的候选包.zip
```

`--plan`仅给出文件数量、体积和排除统计，不执行凭证扫描，也不创建ZIP。实际打包才创建独立快照，检查已配置私密凭证、私钥材料及可疑凭证字面量，再写压缩包并逐个校验文件长度和SHA-256。只在全部一致后生成带唯一标识的新候选文件，不覆盖旧演示包。

打包使用明确的源目录、根文件和锁定的运行依赖。排除规则在实际文件枚举中执行，不能只依赖Git/Docker ignore。禁止符号链接、重复/越界路径；排除本机配置、环境文件（保留公开`.env.example`）、数据库/备份、日志、工作目录、历史输出、构建目录以及依赖中的测试/工具文件。保留运行依赖中的`dist`文件和许可证。代码、依赖及模板均以包内清单为准。

CSV/XLSX教学样本从源码模板重新生成，不直接复制可能已被用户修改的旧`outputs/demo-data`。历史截图和真实账号配置不属于本包。源码文档里指向本机历史交付材料的链接，不等于这些材料已经公开随包发布。

已配置凭证比对和字面量检查有明确覆盖范围，不能代替企业完整安全审计。包内清单校验是文件一致性核验，不是外部签名。该候选包也不是Git提交、完整平台备份或正式生产发布。

## 在独立副本中运行文件演示

安装Node.js 24，解压到独立目录，运行“启动演示.cmd”，或：

```powershell
node scripts/demo-runtime.mjs --port 4030
```

默认端口4010已被当前本地系统占用时使用另一个明确端口。演示只监听127.0.0.1，使用独立文件命名空间和模拟身份，启动时清除继承的企业连接配置及令牌，不读取现有企业数据库或连接现场设备。它不会停止占用端口的现有服务。`NODE_ENV=production`门禁继续生效，不自动改为开发模式。

运行依赖随候选包纳入，开发工具不纳入；如需运行开发检查，在独立副本按锁文件安装完整开发依赖。备件采购需要PostgreSQL，不属于文件演示可完整运行的范围。完整本地OIDC/数据库/工作流/现场平台需要单独的私密配置和原生运行时，不能把文件演示作为其替代交付。
