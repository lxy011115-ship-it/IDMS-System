# 方案A：Flowable实施批次

沿用已批准架构，非重新定义完整目标。现有Node核心、上传、预测和采集保留。

1. 安装便携Maven，使用Java21、Spring Boot3及Flowable7.2构建独立服务；固定版本、独立每企业流程库、仅回环端口、私密服务身份。
2. BPMN维修流程：领取→开始→提交证据→独立终审；退回回到维修，批准结束。流程实例固定部署版本。Java层重复校验身份类型、角色、执行者不可自审、版本和证据摘要；不开放任意表达式/部署/变量修改接口。
3. 核心使用每租户数据库持久化命令outbox，与待处理标记/审计同事务。网络调用不在数据库事务内；引擎命令与幂等回执同事务，按命令ID/摘要重试。只有引擎确认后本地业务状态推进；终审未确认绝不关单。超时结果未知重试同命令，不能新建重复流程；重启恢复。
4. 新工单接Flowable，旧工单继续旧状态机并明确标识，不静默补写历史。流程引擎不可用时保留待处理并阻止后续推进，人工不能跳过流程。自动重试耗尽进入人工处理，重试入口有权限与审计。
5. 页面显示实际引擎状态、流程实例、任务、同步/重试状态，继续真实OIDC和职责分离。
6. 唯一QA数据库/账号/端口验证：真实Flowable表及历史、领取/开始/退回/再提交/独立关单、跨企业/自审拒绝、重复命令、超时/重启恢复、outbox提交故障、引擎提交后本地失败恢复、原回归和桌面手机；再接入4010，核对原业务不变。

未覆盖本批：流程设计器、全部业务流程迁移、模板审批发布、生产SLA/升级策略、生产安全/灾备。未验证能力不能标完成。
