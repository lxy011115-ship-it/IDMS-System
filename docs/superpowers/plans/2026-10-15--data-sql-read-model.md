# 方案 A：设备数据领域表与SQL查询

承接已批准方案的规范化业务表、租户数据库事务及分页查询要求。优先多类型设备数据管理，不改变人工终审和原业务记录，不取消全平台商用验收。

## 实现边界

新增已批准记录来源表、设备表、测点定义表、测点记录表。来源保留原始规范化行、原批次/物理行号、来源系统/记录ID和冻结摘要；设备/测点/时间/质量采用实际类型、外键、唯一约束与索引。不得把种子展示数据作为已上传事实。

启动迁移在企业数据库事务内锁住runtime_state，从原已批准记录回填，核对已存在的投影；重复启动不重复迁移，不允许静默修复篡改/缺失历史。新批准在原审批/审计/幂等事务内追加来源及领域表；SQL失败整体回滚。无更正功能时投影禁止UPDATE/DELETE/TRUNCATE，不能利用投影更新覆盖原事实。

PostgreSQL数据中心使用参数化SQL筛选、稳定排序和分页；多次查询在同一只读重复读事务取得一致视图。权限与租户从真实身份及独立连接池取得，额外带tenant_id谓词；不接受外部连接信息。文件Demo继续使用同契约内存实现。跨模式测试比较接口结果而非只数行。

这是迁移第一阶段：原快照仍负责业务写入/审批校验及回放，因此未完成全业务规范化、多实例或大规模写性能。TimescaleDB、迁移/应用账号分离、数据更正、工厂/设备权限及生产容量/性能仍待实施；禁止宣传为已完成。
