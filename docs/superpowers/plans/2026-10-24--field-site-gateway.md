# 统一站点现场网关实施与核验

目标：将当前现场网关接到真实身份、物理冷恢复准入和同一个 SITE 监听器，保留完整系统目标。

1. 已有网关和 SITE 适配层严格验证 enabled、站点绑定和关闭请求，关闭现场功能不产生额外现场连接。使用现有边界测试复核。
2. 原生场景沿用完整 R4 和 Keycloak 创建、维护封闭、物理加密备份恢复、凭据轮换与 ADMITTED。父版本 957 文件逐一固定；新执行源在创建资源之前固定并在清理后复核。
3. 旧治理队列排空后，两个实际 OIDC 用户经封装 SQL 任务和 V6 执行器独立发布来源与现场通道策略，保留实际六条命令记录。实际批准的点定义决定 OPC UA 节点、单位与量程。来源沿既有编码族升级，完整保留旧条目并使用明确未来生效的 PROSPECTIVE 版本；到期前不进行现场采集。保存六项提交完成收据及新旧策略的当前根证明。
4. 停止本次场景拥有的旧站点句柄，在同端口启用新 SITE 适配层，验证原四模块会话和机器接口。接入实际只读 OPC UA、mTLS MQTT、当前 SQL 根、签名 ACK 和 SQLite。
5. 验证实际身份撤回拒绝历史重放、丢 ACK 保留并补传同收据、持有读取时停止不新增序号、持有实际 owner SQL 事务时同请求关闭等待回滚，先现场排空再释放 host 与 SITE。保存当前根成员证明和所有真实进程退役证据，独立离线检查。
6. 通过后再完善正式 manifest、平台 field 槽位和统一控制器中的实际 broker/edge 生命周期，再发布隔离分支并进行 Linux 核验；本地通过不能代替这些步骤。

本次 QA 的全局身份和冷恢复使用真实运行环境。现场专用 ACTIVE control 和 activation candidate 为声明过的 QA 材料，不能代替正式现场恢复批准。原始 FIELD 历史迁移、授权查询页面与预测消费、完整验收、服务器准备及同版本图文视频继续保留。
