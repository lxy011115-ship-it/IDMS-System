# 当前现场宿主接入实施顺序

延续原方案A、平台依赖与现场当前映射计划；本顺序不替代完整系统验收。

1. 实现明确版本的宿主配置与加载器，实际调用现有IdentityAuthorityGuardV1/RuntimeColdGuardV1；固定准入/口令/库角色与目录/系统标识/SQL围栏。禁止任意替代guard和隐式再基线，拥有的连接必须正常排空。
2. 在新自有实际Keycloak、维护封闭、物理冷备恢复及ADMITTED环境测试当前map事务。实际外部身份撤回发生在真实SQL delta之后，必须回滚；覆盖维护/准入/口令/围栏变更与持有SQL时关闭。独立校验成员证明、退役连接及三个PG目录干净离线。不能用声明ACTIVE文件或假身份HTTP替代。
3. 把该宿主提供的绑定接入FieldMapPlatform和当前接收器，机器HTTP挂统一SITE；补严格enabled/manifest field槽位和controller broker/edge依赖。版本化扩展保留已验旧基线，关闭以同一请求和实际持有句柄重试，未排空不可退役PG。
4. 在真实组合平台再验证签发/原生只读/MQTT/原子接收/签名ACK、失权前重放拒绝及在途关闭。处理旧待发布治理任务和现场SQL历史迁移，不用空marker绕过历史。
5. 当前查询接授权HTTP、站点设备页面及预测器；完成原D资料/模型恢复、完整故障/容量/OT/HA/DR/安全/商业/UAT。双平台与GitHub管理后准备云端候选；未备案不激活公网。最终交付同版本中文DOCX/PDF、真实截图、旁白字幕实操MP4。

本轮正在第1–2项。其余项目保持待办，不能把当前宿主内核成功汇报为统一平台已接入或系统部署完成。
