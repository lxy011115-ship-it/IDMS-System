# 现场边缘生命周期接入（延续平台依赖计划第 5 步）

沿用已批准的 field-edge-runner、field-mqtt-binding 规格和平台依赖控制器计划。最终范围包括真实 broker、签发/接收服务、边缘队列和统一控制器接线；下列步骤是实施顺序，不能用前一步成功替代完整接入验收。

1. 新增边缘循环 V2，保留原入口和失败证据。导出自有实例的当前状态；只有当前租约有效、实际 MQTT 已连通且本流收到签名 STORED 业务确认才允许 ready。换流撤回先前确认。停机等待 HTTP、原生读、MQTT 发布与回调，关闭 SQLite、清密钥，确认资源排空后才释放身份锁；清理错误不能报告正常停机。
2. 实际子进程适配层先返回 ChildProcess 句柄，启动、探测、停机用同一私有 IPC 的 owner/request 相关联。复用现有材料加载器，边缘只能得到其自身材料及平台公钥；原生输入和子进程退出、stdout/stderr/IPC 全终态均须核对。启动取消、重复停止和无关边缘隔离是必要场景。
3. 把签发/接收服务绑定到登记的 PG、当前身份权威和恢复准入。按启用配置登记 broker、issuer/intake、edge，并定义逆序排空依赖；不隐式借用旧 server/index.ts 或旧 45432 实例。
4. Windows/Linux 实跑当前准入、真实只读 OPC UA、mTLS MQTT、事务接收与签名业务确认；覆盖持有读取、提交中停机、丢 ACK 补传、重连、崩溃恢复、旧流保留和未排空阻止 PG 停止。只用公开批准模板和隔离运行时，不能接原库。
5. 将代码、验证摘要和部署候选纳入 GitHub；保持未备案仅准备的限制。完整系统验收后交付同版本中文 DOCX/PDF、真实截图与实际旁白字幕 MP4。

## 本阶段证明边界

直接在进程内调用 V2 并验证真实 HTTP 取消和操作系统身份锁，只证明该局部生命周期。没有运行原生 OPC UA、MQTT 事务接收和业务 ACK 的场景，不得报告数据链路就绪、全系统已接入或部署完成。单元测试中的故障注入只验证异常处理，不代替真实连接验证。
