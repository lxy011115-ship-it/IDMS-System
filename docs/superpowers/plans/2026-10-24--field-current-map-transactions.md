# 现场当前状态映射事务接线

延续已批准的平台依赖计划第5步和现场当前状态映射规格。完整结果仍为当前数据集上的真实签发、MQTT接收、只读见证、持久回执、身份/恢复权威及统一控制器排空；各阶段检查不能替代最终验收。

1. 在维护期从完整且通过原规则核验的当前企业负载编译现场注册历史与租约索引，写入明确版本标记。运行期不能把“索引不存在”解释为“没有历史”；缺少版本标记就拒绝服务。V6治理候选同时发布业务、现场准入、历史索引和控制锚点。相较运行时扫描全历史，该方式保留有界读取；继续旧public表无法接入当前站点，因此不采用。
2. 实现当前根上的注册观察、租约审计和请求重放索引，审计仍使用原格式/时钟/链规则。当前根、注册与批准先于重放查找；旧请求不能续期；当前核对只读且要求实际持久签发证据。准备、审计、索引由一次CAS根事务提交。
3. 新事务适配器核对当前库/角色OID、目录目录校验与SQL写入围栏，并在SQL写入前后、COMMIT前检查调用方当前权威和取消信号。未知提交只能使用原请求摘要解析原回执，不能重新生成结果或提前签名。运行宿主提供已登记PG、实际身份/恢复门禁；QA注入不能代替宿主接线。
4. 在同一事务机制中实现测点/回执、事件ID/流序列/读ID冲突、旧回执和测点证据再核验；当前准入先于重放，签名ACK只在提交确认后产生。保留原签名、只读OPC UA见证和补传规则。
5. 实际隔离PG验证注册幂等、签发/只读核对/原始过期、当前批准和注册变化、错误请求重放、CAS竞争、取消/权威失效回滚、未知提交解析、围栏关闭和正常退役。再接真实边缘/MQTT及统一平台逆序关闭，双平台检查后纳入GitHub。原core失败、全部原TODO、未备案仅准备与最终图文视频交付均保留。
