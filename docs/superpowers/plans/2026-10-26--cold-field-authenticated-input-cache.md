# FIELD 已认证输入的解析缓存

沿用已批准的冷恢复登记与FIELD传输规格，修复同一个30秒窗口内重复重建相同历史图的耗时。Native6与Native7真实check36失败均保留；Native7传输检查在捕获后26.216秒完成，最终revalidate没有通过。由于旧错误被脱敏，窗口耗尽仍是依据时间线的推断，不能伪称取得内部原因码。

采用新的私有输入见证与编译器V4，而不延长期限或减少当前权限检查。原V3的完整配置、证书、历史、签发、缓存、ACK和来源图认证全部保留为首次编译。见证将每份实际私密文件的原缓冲内容绑定到独立随机HMAC，并保存实际文件身份、父目录链；把原SOURCE选择的完整映射文件按原公开SHA绑定。原空WAL也必须按零长度文件和原身份复核。显式枚举的spool和DLL目录保存原枚举结果，防止在解析后加入未认证条目。

每次复核仍读取全部原始字节、验证文件与父目录身份、目录条目、零WAL及全部原SOURCE映射文件；再读原SOURCE前后锚。只有输入完全一致时复用私有解析结果。原始私密摘要不公开，普通JSON不能重建原见证能力。关闭、漂移、重入或失败后不能复用；关闭等待已开始读取结束。临时检查目录不作为材料目录枚举，已有禁止spool与临时目录别名规则保留。

当前材料V4在原HELD/原MAC/原30000ms期限内使用编译器V4，保留每次原账户SCRAM、当前身份和原SQL peer检查以及最终revalidate。每个操作前后都复核上述输入，不缓存权限或peer证明。保留原私有配置内容直到当前材料关闭，再清理。只增加固定安全的失败阶段/原因分类和耗时，不能把原始异常、路径或凭据带到公开结果。

先在已接受Native4真实来源的隔离材料副本上验证缓存初次结果与原编译器一致，再测同长字节漂移、相同内容文件替换、新增/删除目录条目、零WAL变化、来源文件原字节和身份、关闭与失败后复用拒绝、并发读取及清理排空。原材料和SOURCE映射文件不得修改；来源文件变异测试使用独立复制文件验证见证原语。

修复均为新版本；原失败案例、输入和已执行脚本不变。后续使用新Native8真实运行全部43项，只有原normal0/check43/host0后才运行其固定独立检查和本次真实来源76项案例。旧Native7的独立wrapper、CI4和未来Windows记录入口不再作为可执行成功链。最终材料、正式审批、启用和整体验收仍未完成。
