# MQTT broker 生命周期实施顺序

1. 固定运行配置和 mTLS/ACL 校验，封存实际程序与材料；新增源码保持当前已发布 785 文件不变。
2. 建立 Windows 固定内部控制程序，仅接受本创建者的私密绑定，校验实际进程创建时间/父进程/命令行及监听，再使用原生 shutdown 事件并核实际句柄退出；先做真实隔离通道验证。
3. 实现返回实际句柄的启动、绑定、检查和正常停止 API；Linux 使用原创建者持有的 ChildProcess 和自有 socket 绑定。记录启动意图、实际创建、就绪、单次停止和实际退出证据，重复停止复用同一请求。
4. 实测认证 MQTT5/QoS1、独立探测账户权限、错误句柄/错误配置、同请求重试、端口冲突、无关 broker 保留、取消及独立清理。验证终态之前不改封存输入。
5. 当前 f499 全 CI 终态后发布经过扫描的 broker 文件和实际 Linux 验证工作流，取得双平台证明；继续边缘/平台传输正常退役和控制器接线，再完成启用的 AI/模型及其余全部既定范围。

当前只开始第 1、2 步。Windows 通道、正式 broker API、原生/独立验证与平台整合均尚未取得新证据。现有旧 broker 启动器和 QA fixture 不作为正常停止证明。当前 13 CI 不取消、不重跑、不推送打断。
