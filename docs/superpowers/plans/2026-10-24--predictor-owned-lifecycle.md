# 规则预测依赖接线

承接平台依赖控制器实施计划第5步的固定类型、实际创建句柄和正常排空方案，先完成规则预测服务这一种依赖。原 broker、边缘、AI/模型接线与私有数据恢复目标继续保留。

1. 固定新预测服务入口，复用 `createPredictorServiceV4` 和原模型，不接受任意程序、PID、环境或命令行。运行配置只允许原 `PREDICTOR_SERVICE` 的回环地址、端口和服务令牌。
2. 创建前保存私密意图、运行配置及导入闭包摘要、Node程序摘要和随机挑战；实际 fork 后立即保留句柄。子进程先验证输入并报告 CREATED，父端再选择 START 或已请求的 STOP，允许创建后、监听前取消。
3. READY、停止接受、HTTP活动及关闭消息绑定实际父子PID、所有者、挑战摘要、配置和入口封套摘要。停止只接受本适配层 WeakMap 留存的实际句柄，同请求复用一次操作，预检失败不发送意图；恢复原字节后同编号可重试。
4. 正常关闭先撤销新请求，再等待实际 HTTP server.close 回调和所有已接受响应结束，最后等待根进程退出、stdout/stderr关闭及IPC断开，写独立实际终态证明。不以超时、端口消失或通用kill替代关闭。
5. 实际验证合法预测和鉴权、错误控制消息、真实半包请求排空、配置漂移预检与原请求重试、监听前取消及被占端口失败。独立核原始句柄退出文件、关联证明、端口撤销和原695受管保持。通过后再接入平台控制器，并补其他依赖与全系统验证。

此处是现有固定依赖管理方案的实施拆分。单独预测服务验证不能代表平台已经启用全部可选依赖，也不能替代原私有资料整站恢复或最终图文视频。
