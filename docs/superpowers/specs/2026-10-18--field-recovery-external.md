# 恢复计划的外部现态与独立审批

沿用已确认完整备份设计的“恢复批准”和维护设计，不重开普通业务写入口。终审必须把恢复目标、原完整事实/根、精确策略引用、新激活身份，与作者和不同审批人的当前OIDC身份及外部工作流现态绑定。旧JWT、旧备份允许和离线自报JSON都不能代替现态。完整实现依次为外态适配器、恢复计划/事务审计、维护审批接口、重新注册与激活；本阶段先交付前置外态适配器及实际服务验证，后续环节继续完整范围。

选择独立读取器和专用工作流只读端点：相对复用业务写凭据，它限制观察进程的能力；相对仅查询工作流status/cases，它还覆盖未知/额外流程与完整命令历史。现有业务命令、auth/access/SQL契约保持。运行中的原核心和工作流进程不切换；新服务在独立QA数据库与端口实测，构建到新目录且保留旧jar。

OIDC适配器先复用冻结JWT校验，再用专用client_credentials读取账号查询当前用户enabled/requiredActions/企业属性、实际有效realm角色、realm/client notBefore与enabled、实际活跃sid及客户端绑定。权限取旧令牌和当前角色的交集；角色/企业/范围漂移拒绝，系统运维角色不能叠加成业务终审。作者需当前template:submit；审批需当前template:publish且不同主体，当前仅允许完整企业范围的独立恢复操作。Keycloak读取账号不接收个人admin密码，实际证明缺管理写权限。每次重做，不能缓存成功快照作为以后批准。

本机真实26.8.1 sid不是UUID；用户及会话标识按有界opaque字符串校验，签名后与实际API记录精确匹配，不能靠格式假定身份。当前引擎变量按编译v1只读原始列解析两个布尔和一个短字符串，拒绝附件/未知类型，不反序列化任意变量。新构建接受原无恢复配置，并实测原writer命令；读取端点没有回退。

工作流新增独立recoveryReadToken和稳定recoveryAuthorityId，缺任一配置不提供恢复观察；普通业务serviceToken不能访问该端点，读取凭据不能调用原写路由。受控GET在实际READ ONLY REPEATABLE READ事务内采集全部case、引擎历史/活动流程、任务、提交证据、提交人和全部命令记录的摘要；未知/孤立流程或命令拒绝。限制512case/16384历史任务/8192命令/16MiB命令扫描/3MiB响应，超限拒绝，不能当作已完成大库容量验收。固定v1 BPMN内容摘要和当前最新定义、目标外部authority均须匹配受控配置。

恢复工单必须SYNCED且逐个匹配当前流程实例/定义/版本/状态/受派人/证据/待办；全部外部case与恢复出的Flowable工单精确对应，额外或缺失不能自动合并。前后两次完整OIDC与工作流读取须一致且总窗口不超过30秒；输出短期、绑定tenant/actor/session及摘要的观察结果，无令牌/密钥。它是后续计划审批输入，尚非跨服务原子提交或批准完成；最终提交前须重新现查并绑定精确审计/根。

验证使用真实Keycloak专用客户端/用户/读取服务账号和独立Flowable/PG：实际PKCE登录；有效旧JWT下删除角色、禁用用户、改企业/范围或撤销sid均拒绝；只读账号不能管理写。真实流程创建/推进后精确匹配，当前后变化、未知流程、凭据/authority/定义错、不可用及容量异常拒绝。外态采集不发送业务命令、不改变目标或工作流数据；QA变更只能在自有资源执行，并确认实际进程结束后清理。保持66契约、十轮双份快照、旧jar与原运行。

依据本机26.8.1实测与 [Keycloak官方Admin REST API](https://www.keycloak.org/docs-api/26.8.1/rest-api/index.html) 的用户、角色映射与会话读取接口；[OIDC说明](https://www.keycloak.org/securing-apps/oidc-layers)。
