# 统一站点 R4：取消建单对账网页

延续已验证的领域与持久任务协议，在统一站点提供真实可操作页面。保留原取消记录及旧接管拒绝；新部署显式安装，不改当前运行环境。R4 沿用 R3 唯一的审计会话存储、登录验证器与清扫定时器，不另建浏览器身份系统。

选择独立对账工作区并在原取消任务详情提供直达入口。相比只增加一张后台表或依赖用户保存 UUID，新工作区需要服务器端查找已有 case、范围内待复核列表和本人操作列表；相比改写既有 SDK 和站点，本版本以显式新入口复用原协议，保持已验证组件。

只读目录通过 QI 的有界元数据查询获取候选，再用当前 READER 的原取消、设备范围与领域证明过滤。不给浏览器未授权记录、总数、加密会话引用或业务请求正文。分页标记绑定当前身份/会话、部署、目录、配置、筛选和期限。列表状态按当前事实核验，刷新后开始新的记录范围。原操作人按原命令查找时，必须能找回已有对账，不能再次打开新 case。

网页区分对账状态、本人提交和外部释放状态；显示 BLOCKED/HELD/ADVANCED、业务证据是否一致、双人复核、新登录确认要求、待释放及“释放已开始不可撤回”。NEEDS_ATTENTION 保留事实并提示人工处理，不显示为已安全结束。新状态不覆盖原任务 CANCELLED。

所有写动作明确点击；轮询只读。浏览器在发请求前保存白名单编号、摘要和版本；不保存意见正文、会话、角色或结果。未知动作恢复不依赖内存中的原复核意见。需要额外的编号关闭入口，由当前权限验证固定元数据后关闭原编号；已受理时仍返回原作业，不能假称撤销。

重新授权的未知受理也要安全关闭：在新 schema 扩展中追加授权控制围栏，并包装原 authorize 函数，确保旧入口也不能绕过已经关闭的同一授权编号。原授权回执仍不可变，同一控制允许查询已提交事实，不以新 SID 替换旧授权。授权回复丢失、刷新和身份变化时保留原编号，查询或关闭后再明确发起新授权。

严格运行准入验证 HTTP 只有 QI/READER，WORKER 才持 APP 和外部 token；核同 tenant/db/role/catalog/deployment、原预测/对账 marker、公共来源与共享认证材料。服务启动不自动执行 DDL 或激活领域。单租户执行器加载同一审计会话绑定，没有自己的 HTTP 监听。

页面继承现有深蓝工作台，桌面列表/详情双栏、手机顺序阅读，所有动态文字用 textContent，意见只在当前页面暂存，版本或身份变化后清空。保留有意义的焦点、状态播报和长编号换行。测试必须覆盖实际完整站点 CLI、真实 PKCE 浏览器登录、两人闭环、未知动作及授权关闭、迟到响应/身份变化、释放前后语义、移动视口、连续控制台及网络证据；不能借用旧 r3 的不完整异常证据。
