# v4旧库迁移锚与持久停写

完整目标保持所有领域的有界增量写、原审计/文件/投影/回执/后台任务语义。当前先实现其必要的迁移事务边界，不把通用Merkle映射直接接到HTTP或MQTT。前一14源基础包不可修改，新模块复用接口。

只在新自有QA源库和新目标map库操作。源基于现行五迁移，使用真实只读acme旧payload（含六原件）和另一测试租户；原运行库只读，不取得原维护门、不撤原权限。目标基础schema仍只在新库安装。

源BusinessMaintenanceGate排空旧写和后台lease、锁根与全部基表；readEntities、validateBusinessDatabase和独立databaseFacts验证旧canonical根、完整审计、文件SHA和投影。顺序扫描全部31/33基表，保留PostgreSQL原始jsonb文本，不经JS数字解析损失bigint/时间/bytea。每表排序/列/行数与摘要按现有backup事实协议独立核对；序列非MVCC值保持门内前后相同。

目标按表/ordinal保存行描述，超大JSON原文以256KiB二进制分块入不可变blob，行描述绑定完整文本字节/SHA和分块摘要。目标能逐行重组原文并独立重算每表事实。另将旧TenantPayload逐业务集合/顺序项保存，用于完整重构并以旧canonical及旧验证器独立检查；不是保留单个整租户大blob作为未来写入快路。包含文件、SQL投影、registry、两outbox、迁移表、全部审计及sequence锚，不能只迁遥测三表。

持久停写在源门的同一事务撤销原APP所有基表/列DML与序列USAGE/UPDATE，并核对无角色继承/写函数旁路，然后COMMIT。源数据不改；即使协调器退出，已有或新连APP也不能继续旧DML。真实验证包括在门前已开始等待的旧根锁事务：即使最初SELECT已获准，后续UPDATE必须权限拒绝并回滚。数据库owner/迁移管理员不是运行写者，不能声称防协调超级用户。

目标seal只在全量重构/根核对与源持久停写确认后写入不可变receipt命名空间。绑定操作ID、源cluster/DB/role OID、旧root/digest、全部表/文件/序列事实和目标seal前可信根。部分导入没有seal，不能激活业务。COMMIT未知时按既有同命令回执解析，不换操作ID。协调器在停写后退出的恢复必须重验同一目标根和源事实/权限，才允许同一操作seal；不创建替代库、不自动恢复旧APP写权。

这不是已完成版本4业务格式切换或备份恢复：未来还需将原业务集合/SQL事实映射到领域索引、来源治理依赖闭包、原子点/回执/审计与全部HTTP/审批/工作流/AI回归，再规划原部署。保留旧节点不删除，原完整商用目标ACTIVE。
