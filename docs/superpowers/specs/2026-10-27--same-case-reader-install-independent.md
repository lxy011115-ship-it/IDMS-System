# 新安装案例的完整独立验收

新增owned-case读取器、范围清单、完整检查器及portable CLI。范围从已接受原17的64个检查名称及真实报告摘要建立固定锚点；仅增加两种模式各一条安装检查。新66检查删除这两条后必须逐项恢复原64，再保留旧62/60/58/54范围的全部既有比较。field-current原27检查同样保留，新增两安装检查后为29。入口/版本/原拥有链/报告/1510源码数均固定，未来若生产版本变化须新清单和新读取器。

完整检查器继续原来源全数据、7库/29角色、数据库权限、程序与owner权限、两完整根、原workflow和peer证据、真实空流和三轮轮换、原Source与HELD期限、原用户确认和身份的全部旧验证。安装不能替代或省略这些内容，不能重放SQL、OIDC或现场传输。

接入既有安装独立helper，从原控制库和上下文原件独立验证唯一attempt、observation、提交授权的严格schema与HMAC链、原确认/30秒期限、全部原始签名身份记录、原/新SQL后台帧、完整全局catalog/password快照、两读者的唯一密码变化、单独保存的安装后原始SQL见证及重复/重开历史。QA安装后见证必须如实标注为独立于生产观察的另一次检查，不能声称是同一SQL事务。

新增独立原件worker检查：每份已签名preflight map只能匹配一个原私有输入文件，核对其nonce、完整facts和实际原件路径；核对对应真实终态文件、原stdout一条JSON、输入摘要及完整独立结果，绑定预检中记录的PID、起止时间、双流和正常退出。固定worker入口与owner源码必须在原生产源码集合中，Node摘要必须匹配原拥有任务。随后仍从原件直接运行原慢算法重建，所有原文件字节/身份前后不变。

两个模式均需完整独立安装接受，预计各额外12份原始身份记录，加上原有每模式6份确认身份记录。准确数量由原始记录严格重建后核对，不能仅统计flags。最终摘要分别报告原确认和安装新增身份、两份map原件、唯一安装操作及全部保留范围。
