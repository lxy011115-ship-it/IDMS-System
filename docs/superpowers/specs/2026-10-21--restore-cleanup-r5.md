# 隔离恢复失败清理 R5

沿用已授权的持久化恢复方案及其“未知连接拒绝、保留目标、不终止连接”要求，修复 R4 已记录的 admin.end 跳过缺陷。采用独立 R5 文件，当前运行 owner、R4、旧证据和源业务库不变。

仅把 end 移入 finally 能关闭连接，但会让关闭异常覆盖此前错误；忽略清理异常则丢失未清理事实。选择顺序执行的生命周期包装：业务、资源清理、连接关闭、成功清理后的凭据删除。无论业务或清理失败均尝试一次 end；一个错误按原值抛出，多个错误按发生顺序 AggregateError。清理或 end 失败时不运行凭据删除。连接建立也置于生命周期内。

捕获函数使用原备份/恢复和 R4 实际连接观察器。未知主体或等待超时保留目标与凭据；不 FORCE、不终止 backend。成功路径继续完整隔离还原事实、业务、非 MVCC 序列校验，并保持源维护门。重对账函数同样保证外层管理及内层只读连接关闭，不削弱档案认证、目标 OID/角色、事实核验。

在新随机命名的一租户 QA 源库上运行真实维护门、pg_dump/pg_restore。真实未知管理连接在恢复后接入目标，使清理观察器拒绝；确认新函数自身的管理连接已不存在、未知连接仍可 SELECT、目标和凭据保留。随后关闭本轮自有未知连接，经完整档案/事实与 OID 校验的 R5 reconcile 回收；另测成功捕获、业务与清理双失败、连接错误的生命周期。原运行系统只读 STATUS，旧历史 inputs 逐字节保值。

这不是原站点切换、DDL 并发隔离、跨服务灾备或整体商业验收。底层旧 backup-support 的其他失败路径不由此修订自动改变。
