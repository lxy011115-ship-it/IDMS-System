# 核心故障退役验证

延续平台依赖控制器既有故障矩阵：在现有正常启动、SQL 排空阻止、三阶段启动取消之外，实测工作流配置漂移、应用清单漂移后恢复、依赖 JVM 意外退出。保留原 V3 控制器和 V1 应用适配层；新行为使用 V4 控制器与 V2 应用适配层，先经隔离资料验证。

应用停止预检被拒绝且实际进程仍运行时，应立即返回 BLOCKED，保留原请求和句柄。恢复原始配置字节后允许同请求重试；不得等待一个未收到停止请求的进程来代表操作完成。

应用管理器可能在配置漂移期间自行结束。重新核验退役只能接受当前适配层 WeakMap 保存的实际创建句柄，要求已观察原 fork 的终态、原配置与源码摘要恢复、原登记所有者/清单/哈希链和每个成员终态成立。保留首次未确认结果文件，另存重新核验结果；不从 PID 或旧日志重建所有权。故障后全部资源退役的最终状态仍为 FAILED，不能称正常服务关闭。

新隔离原生案例将原 34 项运行在 V4/V2 路径，再增加上述三项实际故障检查。独立检查核每个新增 PG、JVM、应用组及成员退出、服务入口撤销、PG 客户端排空和原输入保持。原数据、原 Windows owner、云运行和公网不切换。完整故障矩阵、所有可选依赖和原完整系统目标继续保留。
