# 旧模拟链路的业务确认背压

沿用完整方案A容量开发授权和既有“确认后清队列”设计。2026-10-18对当前Sandbox模拟源只读观察45.02秒：3540次合法遥测投递、169个事件，其中3371次重复投递；实际STORED测点和边缘确认各只增加1，待传10000条。观察说明重发放大存在，不单凭这组计数断言它是全部数据库瓶颈，也不承诺修复后吞吐。

选择独立、显式启用的 `services/edge/flow-index.ts`，复用未改动的旧 `EdgeSpool` 和 telemetry-v1 协议。默认入口、原SQLite、旧签名/确认/映射/审计规则、66项冻结契约和已部署主核心都保持。扩大队列只延后满载；改核心缓存旧ACK会绕开当前治理复核；新入口以最小风险在生产者端限制重复请求。

发送窗口默认1、严格限1至8。一个槽位从发送直到经过原spool完整验证的业务STORED或REJECTED才释放；PUBACK不释放。超时默认60秒，重试指数退避至300秒；每条最多一个未完成的MQTT发布回调，断网/未完成PUBACK不再叠加新publish。重试原字节/原事件ID；无删除、重签、重编号、重标来源或跨源拷贝。重启尊重SQLite最后尝试时刻，至多延后一个基础超时；运行中期限使用单调时钟。仅PENDING最老窗口参与，不让较新事件无限越过未确认头部。

业务ACK到达先由原spool核验签名、企业、来源、摘要和状态并执行同步事务，再释放槽位。旧已发送事件的有效迟到ACK仍可核验清理。错误ACK不推进。REJECTED保留并占容量。ACK先于PUBACK时仍等待旧publish回调结束才发下一条，防止隐藏传输队列扩张。不会用缓存替代服务端当前策略核验。

入口只允许本机只读SIMULATOR、None OPC安全模式和本机MQTT；现场仍使用独立现场入口。相同受认证status监听先于spool/MQTT/OPC初始化，标准同配置启动竞争直接拒绝。采样前为一整组点预检容量，空间不足跳过本轮并增加gap，不产生部分组。容量当前状态与累计缺口分开呈现；恢复后当前容量错误可解除，历史gap不清零。状态不暴露负载、凭据或事件ID。

本轮交付可审阅源码、确定性SQLite/迟延ACK/断网/重启测试和独立真实本机MQTT+OPC UA组合，并补充实际未改TelemetryService/PG事务、1000条合成历史审计和提交后丢ACK验证。真实万条积压排空仍需受控部署和长期观察；本轮不停止原edge13072，不动原队列/采样配置，不冒称原积压已解决。Windows进程通过私有IPC STOP或信号停止，等待采样与网络关闭后关闭SQLite。整组容量预检不等于磁盘故障/崩溃时的跨事件原子事务；累计gap仅本进程内保持。
