# 当前部署诊断审查的独立意图与存储合同

本合同实现下一计划的第一层数据与持久边界，尚不是新的原 HELD 会话、当前身份审查、程序启动批准、MQTT 权限证明或正式准入。新协调器与实际来源/持有者整合仍须继续实现。

固定用途为 `CURRENT_DEPLOYMENT_DIAGNOSTIC_REVIEW_V1`。可信构造上下文固定原 SOURCE、完整事实清单、原只读意图/结果、目标目录、端点、部署摘要及程序清单摘要；请求只能选择稳定 review/operation ID 并提交预期摘要，不得提供 actor、approved、配置路径、SQL 或授权回调。新 review ID 与原只读恢复 ID 分离。

新私密合同包含新只读读者凭据和独立 journal key。意图精确绑定来源、完整清单、原意图/结果、部署/程序摘要、读者凭据摘要、目标及30分钟的数据意图期限，所有启动、MQTT 探测、业务写入及正式启用标志保持 false。意图期限与原30秒材料/当前身份观察窗口不同；它不延长或替代这些窗口。历史认证和当前有效期检查分别提供，历史记录过期后仍可认证但不能被称为当前授权。

同一控制库新增独立意图表及 details 下的签名 sibling anchor。INTENT、JOURNAL_ROW、ANCHOR 使用不同签名域，新用途密钥不复用原只读 SQL witness 签名。原 SOURCE/意图/结果、原用途计划与批准不得修改。模块只在已打开的真实 SQLite 事务中写入，不自行 COMMIT；原协调器负责把表记录和 anchor 原子保存到原控制行。

创建私密合同会返回仅能初始化其对应存储的原进程不透明凭证。该凭证不是运行时审查或程序权限。首次实际写入前消费它；重试同一凭证只能认证已经存在的同一记录。读取从不返回“没有表和 anchor 所以是首次使用”的结论，缺失即拒绝。复制、序列化、关闭的凭证或旧会话对象不能初始化。初始化回滚/结果未知后可读取认证实际已提交结果；未记录时不能通过已消费凭证悄悄重建。新的可信协调器还须在固定私密上下文文件/操作 ID 上保证初始化唯一性及重开流程，不能在既有上下文丢失时重新调用工厂把它伪装成首次操作。

组件验证使用已接受 Native13 SOURCE 及旧 review 的私密只读快照作为结构数据，并在自己的 SQLite 控制库副本中测试。它不重放 SQL/OIDC/网络服务，不认证新操作人员，不生成真正新 HELD，不开启任何角色或业务入口。只有未来的新协调器在原控制/authority 锁、全部当前事实、真实身份、原拥有会话、程序授权和短窗口内接入后，才能继续诊断动作及正式批准流程。
