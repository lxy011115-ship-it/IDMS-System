# 独立权限核验的公开符号参考

当前完整Windows独立核验从四个已接受真实SQL组件的原回执、首观察和SOURCE取得权限模板；它们引用本机私密work目录，不能直接作为Linux输入，也不能上传整份历史fixture。新资料仅表达预期权限，保留历史实际组件来源摘要，不表示当前部署已经核验或获得运行许可。

导出前仍由原独立加载器核验原任务实际root/host正常退出、原结果SHA及全部原源码。随后只投影五类map/auth/workflow/fence/retired的对象名称、类型、每一权限键的正负授权集合、函数签名和解析目标、列ACL空缺计数、固定策略摘要、标准PG16大对象函数OID/名称。原角色OID转成owner/app/worker/reader等有限符号，保留实际别名相等关系；不输出私密SOURCE、description、角色OID、账户、路径、令牌、SQL行数据或函数正文。

强类型合同拒绝额外属性、非法符号、对象/目标重复及别名环。全部投影向量必须能按原符号绑定反向还原每个原授权值，包含未授权的空集合；有效形状但权限位改变也须被原观察比对及固定字节SHA拒绝。公开资料使用精确规范UTF8 JSON，拒BOM/重排格式，按固定摘要加载。它不生成或替代新Linux SOURCE/原HELD/真实SQL/OIDC/进程退出证据。

六项本地组件检查使用只读历史组件数据验证投影无损和排除私密材料，不重跑旧SQL/服务。未来新的独立消费者必须把符号映射到当前完整SOURCE实际职责，继续核全部当前SQL对象/OID、全部正负权限、授权选项/default、公有schema/退休ACL、owner切换及原窗口和peer证明。不能伪造旧SOURCE对象来喂旧加载器，也不能因符号参考加载成功就称Linux通过。
