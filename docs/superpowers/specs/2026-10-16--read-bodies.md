# 只读工作区正文按需加载

继续完整方案A的活动工作区/GET缓存正文驻留问题。选择独立BatchBody/ImportView/StoreView/ReadWorkspace，不给完整Batch填空原文件或使用假getter；写Workspace保持完整Batch、审计和回执。仅减缓存TTL仍会复制正文，异步getter混入持久化模型会造成误用，故采用显式只读类型和正文提供器。

PG普通GET在原RR+SHARE内验证所有依赖关系MVCC指纹，未建立/变化时仍完整canonical/fileSHA/审计/冻结类型映射更正/投影验证。已完整证明的同一快照才可读取轻量SQL工作区；SQL仅取业务、批次元数据、输入和事实，不取文件、审计、导入请求、命令回执和冗余镜像正文。缓存只持冻结轻量数据，提供器绑定当次SQLclient与生命周期，不能逃逸后继续查询。历史摘要/schema不改，不能只凭revision。

原文件接口先按现有混合批次/有效台账范围授权，使用同一client/RR快照读取文件长度和SHA，预留响应及原始内存额度后才取该单文件bytea，复核绑定和SHA，直接附件返回，不Base64回填缓存。审计接口按需逐行读取SQL审计，绑定列/事件、全企业链验证后才过滤可见项，SERVER_FULL_TENANT_CHAIN语义保持。错误、断连和预算失败不返回部分结果；提供器失效或跨批次/企业参数失败关闭。

读路由与写路由拆分；GET函数接受StoreView/ImportView，Full仍是兼容子类型；写操作只接受完整Workspace。文件Demo通过适配原有完整内存快照的提供器保持行为。当前输入/事实仍可能全量驻留，冷校验和写操作仍完整加载文件/审计，审计HTTP仍返回完整历史，真正分段/组件完整性和CPU继续，不将本批称为常量内存/生产容量完成。

验证：只读形状无正文/回执/隐式引用、冻结与完整写模型区分、SQL流顺序与错误排空、提供器生命周期/错误批次、响应额度前置；原生双企业大数据与真实OIDC读写/独立审批、warm缓存清除后轻SQL不读正文、单文件及审计按需、并发提交仍同一快照、文件/审计/输入/映射/投影污染不能用旧缓存绕过、权限/职责/CSV/更正/类型/worker/会话/采集回归。原平台备份恢复、同SID/CSRF、停机全payload/逐表/历史迁移、受控升级和后备份恢复；新专用基线拒绝覆盖。完整目标active，沿用继续开发授权。
