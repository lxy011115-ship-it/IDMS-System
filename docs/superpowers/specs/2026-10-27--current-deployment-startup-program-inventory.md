# 新用途诊断启动的完整程序文件清单

沿用方案A的明确启动批准要求。当前元数据清单只有工作流读者JAR、Java、peer代理JAR及其五个类，共八项，明确未批准启动。现有真实生命周期工具还使用七项JDK原生程序/运行库、四个生命周期类及生命周期代理；未来审批必须覆盖这些实际输入。旧意图、八项清单和正在执行的Native19不修改。

新增只读收集器，从原WeakMap登记的生命周期工具及同一工具派生的原peer工具取输入，重核原工具文件和固定读者JAR。要求原八项清单的规范字段、摘要、顺序无关的精确八路径及每项真实字节匹配。生成十九个不重复的程序文件描述、各用途分组及规范正文摘要；两个工具必须属于同一原生命周期句柄。调用方不能塞入额外程序、参数、环境或批准字段。

收集器只描述当前程序文件。它不认证SOURCE、当前用户、账号安装或计划，不创建程序，不提供执行能力，也不包含运行配置/参数的批准。未来可信协调器还须从原context和已安装记录取得固定输入，持久化包括只读配置、固定参数、环境策略、监听端点及整个文件清单的新启动计划，并让当前用户明确确认这个新计划；旧诊断请求或八项清单不能代替批准。

组件验证创建真实原生命周期与peer工具，使用已接受案例的原工作流读者JAR只读字节，独立枚举实际工具记录和文件构造十九项预期集合。覆盖假/复制/跨原工具句柄、原清单缺项/额外项/重复/摘要漂移、自报批准和调用方参数注入。测试不启动读者JVM、guard、broker，不连接SQL/OIDC，不替代Native19安装阳性或下一新用途会话的完整验证。
