# 目标企业状态读取与摘要内存

继续完整商用方案A容量工作。前一批隔离企业工作区，仍未改善大企业自身约3.3秒写入，观察堆峰约1.38GB。原因包括runtime_state将所有表/文件聚合为单份JSON、Node整份字符串化/比较/规范化及未变化批次仍splitBatch。

比较：只减少重读会削弱保存后SQL精确重建校验；改新摘要/存储布局需要迁移并增加历史兼容面；选择在现有v4/实体3/payload2契约下，以一个SQL statement快照逐行读取领域表，保留全部行/文件/审计校验，分块计算完全相同的canonical SHA256，直接有界比较与JSON线格式规范化。旧runtime_state视图及迁移checksum保持。

新增独立canonical工具：摘要保留旧对象键排序、字符串JSON转义/Unicode/代理对、数字、数组顺序及原undefined语义，分块输出并有界缓冲；比较不构造巨型字符串，保持同样规范化相等语义；wire clone保持JSON.stringify/parse的JSON值/undefined/数组空位/非有限数字/toJSON与原型键行为，避免巨型中间字符串。以固定/随机/大字符串和实际历史摘要对照验证，不将新版摘要当作历史重置。

新增单statement UNION ALL关系读取器，通过pg.Query逐行事件消费。节点按kind/tenant/id/ordinal组装，次序由显式ordinal排序，不依赖UNION返回顺序。所有关系含租户列，外企业行拒绝；状态唯一/schema3、文件与输入绑定、审计SQL列绑定、工单镜像完整检查。rows和validRows重新建立独立JSON对象，避免改变旧视图的可变别名语义。原文件Base64作为独立文本列而不是整体JSON的一部分。标准query_timeout/statement_timeout与错误处理保留，行事件错误先记录并完整排空，再拒绝，不能抛成未捕获进程异常。

单statement快照适用于既有锁后READ COMMITTED、只读RR及迁移/QA单独调用，不改变跨核心锁后最新状态契约。pg的结果rows在每条事件清空，只保留至多一条额外行，回调/超时与错误传播仍使用标准Query。实际驱动版本进行有界行数组及故障/恢复验证。

持久化仍锁后读取、目标企业克隆、完整校验、差异写入和保存后SQL精确重建；比较/摘要改用等价工具，未变化批次先比较再split。完整来源、权限/职责/幂等、版本、v4领取栅栏和共享OIDC保留。

验证包括旧视图逐字段/原摘要对照、未知/外企业/孤儿/文件和审计损坏、RR跨查询并发快照、Node驱动错误/超时后可用、同revision篡改、原读容量/企业隔离/真实Flowable/AI/采集/更正/身份回归。冻结本轮改动前状态仓储作同fixture基准，测20k记录/大原文件的冷读取、目标写入、SQL行字节和进程内存，记录无改善项。原平台先备份恢复、停拥有core、保值与同SID受控升级。
