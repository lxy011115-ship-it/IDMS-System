# 恢复审核的完整业务与工作流一致性

延续已经授权的完整方案 A、独立人审和当前恢复准备待办。本项是正式审核的前置集成，不能授予审核批准或现场启用。

## 方案与边界

采用原完整根事务中重建的业务数据，加原持有连接的真实 Flowable 快照。普通 HTTP 在持有期间返回 503，不改成写者连接读取。只比较计数会遗漏错配；从目标重新生成基线会丢失原来源约束，因此均不采用。

在新的目标采集版本中，从已经逐项比对原源事实的 payload 提取所有工单与全部已发布模板描述。输入带租户、原 fullFacts 与原 map facts 的摘要，以及完整 payload 摘要。工单最多 512，发布策略最多 512，输入编码最多 16 MiB；超限明确失败，不截断。

将原有工作流快照校验抽为纯函数，保持定义摘要、全部流程、工单版本、最后命令、任务、历史、维修证据和活动流程库存校验。完整 map 租户集合、工作流读者集合和实际捕获集合必须完全相同，重复或遗漏拒绝。消费私密快照前后验证文件身份、大小和摘要。

新恢复准备器只在原 WeakMap 会话、原 READY 意图、原维护锁和当前独立身份权威均有效时执行该集成。原 source/fullFacts、第一次准备结果与旧源码快照保持不变。检查通过只返回审核输入一致性结果，当前人审、批准和启用仍分别等待实现。

## 验证

纯测试覆盖孤立流程、缺工单、重复、跨租户、定义和任务漂移、最后命令和维修证据漂移、完整策略摘要及输入上限。新的原生案例通过真实业务预测/维修入口与真实 OIDC 创建一致工单和引擎流程，随后执行完整整库恢复与持有连接检查。保留此前全部恢复、COMMIT 丢回复、外来连接、来源漂移和正常关闭检查。独立复核从原证据重建 payload，核对采集输入，不能只相信汇总标志。

后续仍须完成当前作者/全部贡献者/独立审核人授权、持久计划/批准、正式激活、整站迁移、现场验收、服务器候选及最终图文视频交付。
