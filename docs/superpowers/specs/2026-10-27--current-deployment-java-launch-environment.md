# 诊断Java启动计划的固定环境与私有目录

现有生命周期辅助器继承父进程环境，再删七类Java/Spring选项。后续新的明确启动计划需要从空环境构造固定列表，防止继承API密钥、代理、动态库注入或其他未批准选项。旧启动器、旧案例及当前Native19不修改。

新增纯值构造器只接受受信javaHome和planDirectory，派生固定reader-runtime.private.json、home、tmp路径。固定语言/时区、JAVA_HOME、只读配置路径和最小PATH；Windows仅另取启动进程的SystemRoot/WINDIR，要求规范绝对路径且一致，不复制其他父环境变量。固定Java属性限定user.home、java.io.tmpdir、UTF-8、UTC、无系统代理和无图形界面。计划协调器将创建并认证这些私有目录/配置文件，绑定真实原工具与运行目录，签名持久化固定属性与环境，取得新当前用户批准后才能执行。

构造器不做文件认证、SOURCE或当前用户验证，也不授予执行能力；SystemRoot仍属操作系统信任基。它尚未接入新读者启动，不能把纯值检查当作原V8启动器已更改。

在独立测试子进程设置明确的假注入选项和假密钥，验证它们不出现在固定环境。编译小型公开Java测试类，再用构造的环境与固定属性启动一次原Java子进程，检查环境键集合、私有home/tmp/读者配置路径、编码/时区/代理属性及注入属性缺失；保存原退出和双输出流关闭。输出仅固定布尔结果与键名，不输出父环境的值。无读者JVM、guard、broker、SQL、OIDC或业务启动。
