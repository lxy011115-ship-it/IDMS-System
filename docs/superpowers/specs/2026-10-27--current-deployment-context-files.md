# 当前部署诊断审查私密上下文的固定文件与重开

接续独立意图合同。可信协调器在自身控制锁内提供固定工作目录、完整可信 context 及仅含稳定操作 ID 和预期摘要的请求。每个操作在 `current-deployment-context-<operationId>/context.private.json` 保存一次新合同。只有排他新建操作目录的原调用者保留一次性存储初始化凭证；既有目录是永久占位，即使文件或 SQL 记录缺失也不能重新初始化、刷新期限或更换密钥。并发失败/中途写入可重新读取原记录，不能拿失败当首次创建。

工作目录必须已存在，不能放在 SOURCE/目标数据库、原控制库目录或旧只读 review 目录内。拒绝符号链接及非规范路径。文件读取使用真实打开句柄核对路径与句柄身份、完整字节及 EOF，两侧核对目录链，拒绝多硬链接、超限文件、非规范 UTF-8 JSON。原不透明文件持有者绑定 SHA、设备/文件身份、大小、修改与变更时间及目录链身份；变化后失效，不能重设基线。新文件按现有私密文件工具限制访问；本组件不声称能抵御同一 OS 账户或管理员接管，现有文件 ACL 的独立运行时审查仍属后续协调器/部署安全工作。

在真实 SQLite 的调用者事务内，保存原独立意图记录及两个独立签名 anchor。新增文件 anchor 绑定完整文件身份与字节；跨进程重开也必须认证已经提交的原文件 anchor，不能用相同字节的新文件替代。MODULE 不 COMMIT，不拥有 SQL 事务，调用者必须将 details 两个 sibling 与 SQL 表一起提交；失败时回滚并丢弃事务内 details。认证成功表示当前事务中记录相符，不是提交完成或结果未知处理证明。私密凭据导出需先认证存储及文件并检查原期限。后续实际协调器还须在持有锁、当前身份/完整事实及新原拥有会话下再次验证，数据组件不产生任何运行时权限。

close 等待其原异步操作结束，关闭初始化凭证并清理内部密钥副本，保留原文件及占位。只拥有文件数据，不停止或接管程序/数据库。重复 close 返回同一个 Promise；复制、序列化、旧 HELD 或关闭持有者拒绝。

验证使用已接受来源及旧 review 的历史结构数据，在全新自有目录和真实 SQLite 副本上进行，覆盖排他创建、原数据保持、重开、回滚、缺失/替换/篡改、过期、并发及独立 Node 子进程。测试结束清除自有测试目录，原已接受案例及用户运行服务保持。这里不测试新 PG/OIDC/HELD、程序启动、MQTT 或正式准入；这些仍按完整计划继续。
