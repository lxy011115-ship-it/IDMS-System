# 旧预测根与作业迁移

沿用已授权的预测、统一站点及整站受控切换目标。旧 SDK 已激活根缺读取版本、来源摘要、基线、设备作业索引、快照关联和 SQL 宿主绑定，不能靠重跑 activate 或直接放宽校验接入。

依赖顺序为：A. 原生旧根的完整证据核验、分批索引与读取版本迁移；B. 无宿主旧作业在原身份重新授权下接管到产品 SQL 队列，保留原命令、计划及外部流程信封；C. 原业务 workflow outbox 与整站切换。本阶段实现 A，不把 B/C 缺口算成完成，也不自动发送旧作业。

A 采用独立迁移 SDK 和私密 CLI，准备不可变计划后以 SMT CAS 将领域控制变为 UPDATING，增加 epoch；每批最多 60 项索引操作，与检查点原子提交。检查点包含前根、前检查点哈希和批次范围，使用原生 SQL 收据复核当前根确为上一次迁移提交；旁路写入、旧计划或不同配置拒绝继续。进程中断可凭原计划恢复，未知 COMMIT 回复按原 UUID 收据恢复。

准备阶段以原生队列全部位置枚举去重作业，核对命令键、计划/请求摘要、原身份/服务绑定、队列最新位置及完成或取消回执和原生审计。新设备顺序索引保留每个作业。快照关联必须来自原 predictive_result 指向的原始已完成分析，复用分析不能顶替原申请人。既有 episode 只补经实际建议实体与原生分析验证的 recommendationId；无原生责任证据的旧告警保持历史待对账，不补造证据。

最终一次 CAS 发布新读取标记、配置与来源摘要、原根基线、迁移系统审计和完成回执，并恢复原控制阶段、增加 epoch。整个迁移不改原业务、历史审计、作业或计划；没有 SQL 宿主的作业另写非授权的待对账记录，保留不确定外部建单边界，不构造当前会话或 SQL 成功。

QA 必须从保存且 SHA 固定的旧 SDK 源码实际生成旧根，不以删除新字段伪造旧版本；真实 PG、独立规则服务、原生完成/待办作业、旧告警和原件保值。校验读取前拒绝/迁移后成功、原生证据归属、暂停/恢复/陈旧计划/篡改与中断恢复、实际 COMMIT 回复丢失，以及新写者继续工作。原运行库和活动 owner 不执行迁移或 DDL，所有历史源与 QA 输入不覆盖。
