# 新用途用户确认的持久记录

日志不是运行时批准。它保存本次准确用途、原意图/来源/部署/程序清单、各企业明确确认和Gate2实际认证的三组私密原始身份记录，供重启后认证和之后独立重建；公开状态不含令牌，也不返回用户当前仍有效或可启动程序的结论。

所有接口只接受原context-files-v5模块真正创建的fileOwner及真实SQLite事务。初始化仅允许同一排他文件创建者、已经认证原元数据的拥有者，模块在首次创建尝试之前消耗一次机会。它创建固定schema及独立HMAC的EMPTY anchor。已尝试的拥有者只能读既有记录；重新打开的拥有者不能取得初始化权。已有意图缺失schema、行或anchor时拒绝，不根据缺失重建“未确认”或“已确认”状态。

写入必须消费Gate2模块真正的句柄，已经实际再次核验、绑定同一控制/来源/操作/意图和所有输入。拒绝V1能力、副本、公开证明、自定义验证函数和额外请求字段。每企业的三组记录须与确认actor及实际原令牌摘要一致。写入一次固定行和独立ROW/RECORDED_ANCHOR域分隔HMAC；再次提交同一原证明只能读回，不更新时间或材料，也不覆盖另一份确认。所有材料在原证明30秒有效期内记录。读取认证持久的历史，不把已记录推断为当前权限。

父协调器必须持有原control和identity两份事务/实际文件身份检查，负责保存details并COMMIT；本模块不提交、不关闭调用者事务，不写目标PG、不启动程序、不发MQTT。初次prepare先记录并保存真实私密上下文，初始化EMPTY日志后再保存details及提交。确认在同样原锁内执行Gate2验证/再次核验、写行和anchor，旧SOURCE和旧review精确保留。元数据提交结果不明后先读取原日志，不重新生成初始化权；这不是最终业务COMMIT未知恢复的验收。

原始用户令牌只保存在受控私密SQLite记录中，不进入公开状态、Git或CI摘要。原服务令牌、客户端密钥及其他管理响应字段不进入记录。证明的时间和密钥不刷新；过期数据可供后续独立离线审计，本控制模块的私密数据桥仍受原上下文有效期限制。

本阶段先验证SQLite实际提交、对象重开、子进程读取、同证明幂等、缺失/篡改/旧能力拒绝和一次性初始化，不替代下一完整SOURCE中原control/identity锁、实际Keycloak、新读者凭据/HELD、程序批准、MQTT ACL及最终多库准入验收。
