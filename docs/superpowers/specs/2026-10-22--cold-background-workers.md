# 恢复后治理、维修和预测后台入口

沿用 R4 写入门与整簇冷恢复的现有设计，补齐治理、维修（命令与工作流）和预测接管后台。当前受控入口只有 HTTP 和对账 worker；仅验证网站能读取不能证明其他后台可以恢复处理。

采用独立的新加载器和 CLI，复用现有业务 runtime、队列、加密引用、worker 和预测接管实现。直接复用旧 CLI 无法在 claim 前核恢复准入；复制业务 worker 会产生第二套语义，均不采用。原站点、旧 CLI、已固定执行源和 JAR 不改，不以旧 PID 作为所有权证明。

新显式私有配置声明 worker 类型、业务 runtime、外部身份权威和冷控制信任文件。启动前和每次取任务前核 ADMITTED、原维护 CLOSED 回执和当前身份权威；解析执行者授权时再核这些条件。SESSION 引用还拒绝镜像捕获的旧会话；BEARER 仍执行原 JWT/当前角色验证。业务与队列角色必须属于捕获的活动库及登记角色，并使用准入后凭据；不把控制登录传给业务进程。只使用 WORKER 配置，拒绝 HTTP/QI 角色配置。

加载时固定实际读取的私有 JSON 字节，后续读取任务前重新核对，阻止配置在运行中被替换。密钥、密码、会话与服务令牌不写公开日志。停止只唤醒等待并停止新 claim，等当前任务和心跳完成，再关闭 runtime；不终止后端或强杀进程。

验证须在新隔离集群的完整受控恢复后，启动实际 worker CLI，执行治理、维修及预测队列任务并核原生完成/回执，验证错误模式、陈旧凭据/信任/权威与配置漂移拒绝；再正常停止并核 SQL 连接清空。公开样例与私有原资料分开，不把这一阶段称作所有生产组件、所有秘密轮换、原 owner 移交、完整 GUI 或生产部署完成。
