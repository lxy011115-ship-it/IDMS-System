# 统一主站 r3：旧预测任务接管

延续已授权的统一主站和旧任务接管范围。本修订将已验证的接管页面、原人授权后台与独立接管 worker 组合进统一站点。保持已验收 r2 文件逐字不变，采用新的配置、运行加载器、HTTP 包装和 CLI；不切换原活动站点，不在原库追加 DDL。

可选实现为直接改 r2、新建 r3、另设接管站点。选择新建 r3：保留旧验收证据，避免另设入口割裂共享会话。r3 复用既有治理/维修宿主，以相同业务、认证、认证审计及认证运行文件绑定每个租户的预测 HTTP 成员。每个成员启动前必须通过接管扩展 QI 权限探测；HTTP 不携带 APP、规则、工作流服务材料。仅基站长期持有认证状态、provider 和过期清扫器，预测加载器的临时认证实例验证后关闭。

同源首页、导航和三个模块保持可用。预测静态入口改为接管 r2 页面；旧预测基础协议资源仍由同源明确路径提供。预测私密路由由当前服务端会话选择已注册租户，再校验 tenant/actor 头；原人、范围、CSRF、原生结果证明和不可变控制决定均沿用接管后台，不新增绕过。worker 使用已验证的接管适配器，保留原命令、计划、外部信封与独立重试规则。

验收使用新的隔离资源命名空间、fresh SQL r2 目标、两真实租户和独立 Flowable 引擎。验证三模块真实业务闭环、本人旧任务接管与未知接受恢复、跨租户/跨身份拒绝、HUMAN 独立重试、统一 PKCE 登录/退出、窄屏、浏览器错误及恢复元数据。启动负例覆盖缺失接管扩展与不合法权限，不能仅靠静态页面检查。精确清理自有资源，保留输入快照，不触碰原活动实例。

本阶段不完成被取消且外部创建不明任务的人工对账、workflow outbox 专门迁移、整站切换或完整商业待办；这些仍属于原目标。最终图文手册和实际演示视频按 docs/idms-user-delivery-plan.md 在原目标验收后交付。
