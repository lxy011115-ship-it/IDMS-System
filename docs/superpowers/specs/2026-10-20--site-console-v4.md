# v4 站点整合与认证审计投递

继续已授权完整方案A的整站接线待办。现有导入/模板/审计与维修均有独立认证HTTP和后台入口，但缺少统一站点和跨模块会话；认证生命周期outbox的实际整站投递仍待验证。

采用新站点宿主组合冻结的领域HTTP，不修改已发布控制台或历史算法。备选为浏览器跳转多个端口（不能形成同源会话）或把全部APP权限放入HTTP（破坏既有分权）。新宿主使用同一OIDC、共享会话和认证outbox；多企业静态注册在私密运行配置中，以服务端验证的session tenant选择，禁止请求头选择任意数据库。未注册/挂起企业拒绝登录，身份/范围继续由原领域边界核对。

每企业配置引用既有HTTP私密运行文件，启动时复用原QI/READER/SQL目录与认证隔离校验，同时校验所有成员的认证配置、认证部署/审计绑定和企业业务绑定一致。新宿主只接收HTTP配置，拒绝worker/Flowable/AI服务材料；认证投递和领域worker继续独立进程运行，不把业务APP/投递密钥并入HTTP。配置只显式从私密文件读取，日志不回显材料。

首页呈现当前企业与数据/审计、维修入口；两控制台增加统一导航，但静态资源通过新宿主生成，不覆盖冻结文件。私密API必须提供与当前session一致的tenant和actor；原API再作当前权限和范围核对。未识别API明确404，不通过任意代理或请求提供的路径加载运行材料。公共静态页面不包含企业配置或凭据。

验证必须覆盖两个企业同源读取/交叉请求拒绝、模块间共享真实身份与退出、挂起及未注册企业、新宿主独立CLI、模板和维修实际排队动作、独立认证投递进程把实际登录/退出事件写入相应企业审计链。浏览器实际PKCE、两控制台导航与审计可见性验证单列，不能用直接授权夹具替代。失败配置须非零退出且无READY/秘密；所有QA资源按准确OID、owner与零连接清理，原运行服务与已发布SHA保持。

本轮不把首页组合当完整商业验收。新建预测/工单、旧未解决workflow outbox迁移、原站点受控切换、队列密钥witness/轮换、完整恢复/容量/HA及ICP继续，不能因整合入口完成而缩小完整目标。
