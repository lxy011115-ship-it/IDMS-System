# 生产读者凭据安装协调器

Control3保留Control2全部原控制文件身份、SOURCE/旧review、权威文件与签名head/当前realm核验和用户确认流程。可信构造增加固定bootstrap账号、工具目录和物理恢复密钥文件；外部安装请求只带原ID/意图摘要和完整原用户确认，恢复/历史请求只带原ID/摘要。不能传入actor、approved、路径、SQL、账号、密钥或检查回调。

新prepare仅由实际首次context创建者初始化安装EMPTY日志与独立授权记录空锚，既有缺项不升级。安装先验证已持久确认，确认旧HELD/reader SQL已正常退休且当前无其他backend，再认证原物理档案、离线原PG、HBA/REVIEW目录和完整7库SQL/映射事实。随后重新实际认证原请求中的当前用户，按原确认期限准备真实SQL阶段，并由安装日志派生准确原新读者凭据。

目标PG事务持有完整共享目录锁期间，先保存确定安装尝试。每次元数据checkpoint都COMMIT控制库，释放权威事务，再按原control→authority顺序重新取得两锁，逐字核原SOURCE/旧review/全部控制详情与原head；任一变化拒绝并回滚未提交PG事务。这样独立SQLite读取者可确认原尝试已真实提交，同时不假定两个SQLite库有一次分布式原子提交。

PASSWORD阶段后实际重验当前用户，把对应尝试的完整用户记录追加到单独域签名的授权链并提交保存，再重获锁复验，才由原PG连接COMMIT。授权记录不覆盖、不刷新原期限。原PG连接确实关闭后，以新连接和原签名SQL基线分类全原/全新状态。全新值必须对应已经持久提交的该次授权记录，否则拒绝认作已安装。实际观察追加原安装日志并提交；完整历史读取不冒充当前权限。

APPLIED后重复请求只读历史，不再更新密码或刷新确认时间。PREPARED结果不明时只恢复观察，不发第二次。观察为原值且原期限仍有效时，下一明确安装请求可以在同一确定操作下追加新尝试。混合结果或目录/来源变化保持异常。所有目标SQL连接、Gate和文件/事务正常关闭；不启动新reader/HELD、MQTT或业务服务。SQL回复丢失分支仍需之后真实网络故障注入，当前接线/请求预检不作为其验收。
