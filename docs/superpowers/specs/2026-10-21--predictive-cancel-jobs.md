# 取消建单对账的持久作业与网页接入

本设计继续原方案 A，将已验证的领域对账接入统一主站。保持原取消记录、原计划、既有协议和运行环境；新部署显式安装新命名空间与配置后才启用。

沿用现有 QI、只读凭据、可信执行器与加密共享会话的分工。直接由网页调用领域 SDK 会暴露写入与服务凭据；扩展原预测队列会改变已冻结的 ANALYZE/REVIEW 和原作业接管语义。因此使用独立对账命名空间，保存固定 case/action、严格请求摘要、加密会话引用、当前授权代数、租约与完成回执。网页只有 QI、READER 及已有会话能力；可信执行器持 APP 和外部流程凭据。

所有动作保持原 caseId、operationId、预期 revision 和证据摘要。HTTP 返回已持久受理与业务完成的区别。未知受理按同一动作查询；关闭未知受理时先持久关闭该编号，若已经受理则返回原作业并要求恢复，不能用新编号掩盖可能已经执行的动作。独立复核的原会话引用与领域复核在同一数据库事务提交；确认和释放从该持久引用获取复核人当前授权，浏览器不能提交他人的角色或身份。

每个 case 仅一个执行租约，租约失效后旧执行器不能发布。领域操作通过 hooks 在同一事务核租约、有效期、部署、CAS、领域动作回执与审计，并完成对应队列作业。原 native job/plan/cancelreceipt 不在允许变更集合。当前权限无效时待重新授权，不靠历史 ctx 自动继续业务发布。

释放分为可重新复核和不可撤销的两个阶段。在外部释放开始之前，当前原操作人和独立复核会话均需有效、证据与版本仍一致。随后在同一 case 租约下持久记录固定发布摘要、case/review/confirmation 身份见证和释放意图。该点是“释放已开始”的授权点，之后禁止新观察、复核和确认插入；网络断开、租约到期或权限随后变化，不撤回已经开始的外部动作。恢复执行器仅能按原固定释放摘要完成外部释放及事实对账，不能重新发布业务工单。恢复的审计明确记 SYSTEM 与原授权意图，不冒用已经退出用户的当前授权。若授权点之前撤权，保持外部 hold，允许新的独立复核与新原人确认。

新的队列 SQL 只向 QI 授予受理、本人作业读、授权更新和编号关闭；不授予表访问、领取、领域读写或完成。执行器只能以当前租约发布，目录默认值、ACL、索引、规则、触发器、函数、角色及DDL代数都参与见证。所有新业务表禁止直接修改及TRUNCATE，私有事务上下文表不授予运行账号表权限，guard 失效导致服务拒绝继续。

网页展示原取消记录及独立对账状态、外部 BLOCKED/HELD/ADVANCED 事实、审核人和证据版本、重新登录要求、待释放/已开始/未知结果恢复及 NEEDS_ATTENTION。保留原操作元数据，提交前保存编号；不在浏览器保存凭据或业务敏感正文。接入统一站点的新显式版本，不修改正在运行的旧版本。

验证要求包含真实数据库/Keycloak/加密会话/Flowable、两个写者与两个租约、真实 SQL 提交丢回复、独立复核引用原子性、释放已开始和重新复核的两种竞争顺序、进程退出后同意图恢复、撤权前后边界、未知受理关闭与迟到受理、QI 权限与实际目录漂移。网页阶段使用真实浏览器验证，包括 CSRF、身份变更、跨租户范围、断线恢复和移动视口。整体验收、正式迁移、域名部署准备和最终图文视频交付仍按原总范围完成。
