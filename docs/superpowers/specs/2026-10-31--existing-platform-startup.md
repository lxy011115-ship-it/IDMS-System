# 普通启动与初始化分离及本机运行恢复设计

日期：2026-10-31。状态：用户已单独批准方案A，已实施并完成本机恢复，见[实施计划](../plans/2026-10-31--existing-platform-startup.md)及[运行指南](../../existing-platform-startup-guide.md)。整体生产就绪和云端切换仍未完成。

## 1. 需要关闭的缺口

主站就绪接口、维护详情和资源巡检已完成源码及隔离验证，但完整本机平台尚未启动切换。不能直接运行当前一键入口来取得“已运行”结果：`start-platform-v4.mjs`和`start-platform.mjs`仍调用PG bootstrap、数据库迁移、会话库setup、MQTT配置生成、workflow/AI setup和工作流构建。即使部分调用幂等，仍可能创建/授权、改schema或重写既有凭据配置。

进一步检查发现，工作流Java构造器直接执行两张扩展表的CREATE、启用Flowable自动schema更新，并每次尝试部署流程。因此只从Node启动器删去setup调用，仍不能保证普通启动不做初始化。

本轮只读清点取得17项现有配置/运行文件，PG、JDK、Keycloak、MQTT和模型原生程序均存在。两处旧运行路径实际为同一物理数据目录的别名；PG控制文件仍记上次运行态，但pg_ctl status返回未运行、登记PID已终止。未删除PID文件、修改配置或启动服务。原始目录、系统标识和配置摘要只保留于私密的`work/startup-design-20261031/readonly-inventory.json`，不放公开说明。

本批目标：用户仍能从一个明确入口恢复已有平台，普通启动只使用现有数据、密钥和运行产物；缺少或不匹配时定位具体阶段并停止，不通过补建/重授权获得绿灯。完成隔离验证后，再用当前既有配置恢复网站和登录入口，分别报告HTML可用、身份可用和全平台就绪。

## 2. 实施选项

| 方案 | 内容 | 取舍 |

以下只定义A。它不打开公网、不修改账号密码或权限、不启动外部告警、不引入自动重启或生产放行。

## 3. 入口与一次性运行绑定

根目录“启动IDMS本地网站.cmd”“启动IDMS.cmd”和`npm run platform:start`统一到同一个普通运行协调器；`scripts/start-platform.mjs`/v4兼容入口转交同一逻辑，不能保留当前入口悄悄执行旧setup。文件演示入口继续是独立文件演示，不被转换成企业平台。历史版本脚本保留为历史材料并明确不属于当前入口，不自动删除。

运行协调器只读取一个明确的私密运行描述。描述引用现有native root、PGDATA、PG工具、私密客户端配置、已有工作流JAR、节点/服务端口及已批准的就绪策略；记录PG系统标识与运行产物摘要，用于确认复用的是原部署。描述不复制密码/令牌或模型权重。

提供一次性显式“登记已有平台”操作：先输出只读预检提案，再向一个不存在的新`.local`描述文件写入经过验证的引用和绑定，不覆盖已有描述。登记只建立运行引用，不创建数据库、用户、权限、业务数据或密钥，不调用旧初始化器。

候选路径先规范化并核对真实文件身份。像当前两个别名实际同一目录时可合并；如果是两份不同PG数据，则明确拒绝自动选择，要求指定目标，不以路径优先级、mtime或旧PID猜测。不能自动迁移/复制PGDATA或模型，不为腾空间删除旧运行目录。

首次由实施过程按已取得的清点结果登记当前既有平台；日后用户双击普通入口无需每次手输长参数或重复生成配置。指向就绪策略是明确运行选择，不借此生成维护令牌；现有令牌缺失则预检失败。

## 4. 预检与分阶段启动

所有必需文件/程序的静态预检先完成，再启动首个进程：配置用途/格式、企业集合、地址/端口、凭据引用、会话库部署绑定/密钥文件、MQTT服务文件、模型清单、工作流JAR及来源记录。输入限制大小，拒绝未核对链接/越界，报告固定错误和处理建议，不复制原始配置或完整异常。

普通入口不创建配置、不改ACL、不生成令牌/密钥、不运行initdb、bootstrap、migrate、auth/session setup、mosquitto_passwd、setupWorkflow/setupAi、不下载模型，也不隐式构建JAR。

| 阶段 | 行为与验证 | 缺失/异常时 |
| --- | --- | --- |
| PG | 精确绑定既有数据；核对PID实际终态、端口与数据标识。必要时使用原有pg_ctl启动，随后以现有身份进行只读部署/能力检查 | 不新建库/角色，不改端口或schema，不删除锁文件，不resetwal |
| 身份 | 使用已有Keycloak配置和数据库，默认禁空库初始化并验证schema，不携带bootstrap管理员/realm import | 版本或schema不符停止，交明确初始化/迁移维护流程；不恢复默认账号角色 |
| MQTT | 直接使用现有broker配置、密码文件、ACL和既有身份；认证与绑定核对后启动/复用 | 不重写密码文件、ACL或生成新边缘身份 |
| 工作流 | 启动已核对的JAR，以运行模式检查既有schema及流程定义 | 不自动CREATE、ALTER或deploy；不符时停止并保留现有流程实例 |
| 模型/AI/预测 | 使用已安装固定模型、既有网关配置与既有预测程序；验证版本、摘要和GET状态 | 不拉取/替换模型，不重写网关配置或生成新令牌，不调用生成 |
| 主站/采集 | 使用原业务和共享会话配置启动最新Node主站；确认主站MQTT订阅后接入既有边缘缓存及模拟源 | 不删除/清空缓存、不换映射或凭据绕过错误；缺schema/登记则停止 |
| 网站与就绪 | 分别检查HTML、OIDC发行者、维护详情与`/api/v1/ready`，核对资产字节与启动记录 | HTML可访问不等于全部就绪，采集满载/未确认不得宣布正常 |

PG正常启动可能需要自身的WAL恢复、日志及状态写入；这与初始化或迁移不同。当前控制状态与活进程不一致时，只按实际PID/端口和厂商启动结果处理，不把控制文件文字或“等待超时”当作终态。不得对实际数据做破坏性故障演练。

## 5. 工作流与身份的运行/初始化边界

工作流默认运行模式去掉构造期DDL和部署调用，Flowable使用验证既有schema的模式。除Flowable版本，还核对`idms_workflow_cases`/commands结构及已部署流程的企业、key、版本和资源摘要；定义与已审核BPMN不符则失败，不能只查到一个latestVersion就通过。

显式workflow setup/迁移入口保留初始化能力，并明确区分它与普通运行；构建也为显式准备步骤。既有已运行流程不得被启动过程替换定义、删除实例或自动迁移。记录源码、JAR摘要、运行模式及GET状态，旧JAR未具备运行验证行为时不能当作新版本复用。

身份普通启动强制采用“验证、非初始化”语义；现有账号停用、realm/client范围、角色及密码不被修改。参数选择需对本机固定Keycloak 26.8.1验证，不能只因其他版本文档存在该参数就对真实库尝试。使用本次拥有的空库/不匹配库验证拒绝且不建表，再验证已有库正常运行。如果无法证实该固定版本的限制生效，停止实际切换，不回退到自动更新。

如果厂商要求显式重建运行产物或升级schema，应交维护步骤，不通过重复启动或改版本标记掩盖。登录仍走原OIDC，不尝试已失效的初始密码，不用伪造身份绕过真实岗位验收。

## 6. 进程所有权、超时与失败

每次运行记录run id、阶段、进程PID及出生/可执行文件绑定、来源/配置摘要、开始/观察到期/实际结束和是否复用。旧进程文件和端口可达都不足以证明所有权；复用服务需要对应契约及部署绑定证据，复用的进程不归本轮停止。

全局单协调器锁与实际进程身份一起核对，拒绝重复启动。登记PID已不存在时记录陈旧状态；PID被其他进程复用或占用服务身份不明时停止，不能杀掉它或删除保护文件来继续。

某阶段观察预算到达时先记录未确认，继续核对同一活进程/句柄；不另起同名服务。明确退出则记录终态与固定错误。没有自动重试、重启、强制终止或切换到空白配置。

部分服务启动成功而后续失败时给出PARTIAL_START及已启动/复用/待确认清单，不串联强杀所有依赖。保留可追踪进程让管理员处理，重复普通入口按现状复用/拒绝，不能变成隐藏的第二套平台。后续显式停止仅针对该run确认拥有的进程，按依赖顺序和厂商正常停止方式等待终态；无正常停止能力时记录未结束，不猜PID/进程树或强制杀停。关闭一个启动窗口不应悄悄结束复用的身份/数据库。

原生工具及Node/Java子进程隐藏启动窗口，日志保存在有限私密目录，不把环境、口令、完整命令行或原始子进程异常输出到分享报告。报告按逻辑服务给出阶段和处理建议，失败证据不被绿色汇总覆盖。

## 7. 业务运行与验证口径

“不初始化/迁移”不等于服务启动后完全不写数据：现有会话、日志、工作流/AI outbox和已缓存采集消息可能按原规则继续处理。实际运行恢复时不制造企业测试单；前后核对凭据文件、账号权限、schema与流程定义，背景业务版本/队列变化如实记录，不能笼统承诺全部数据库字节不变。

就绪检查显式接入上一批已批准策略；未知、缓存满及原有错误继续显示。先确认HTML和登录入口可以使用，再按实际依赖结果报告整体就绪；不通过清队列、重置schema或放宽角色让报告通过。

真实浏览器只读打开系统及登录入口，不修改密码/账号权限。没有现用登录时不猜密码，多岗位签收继续单独保留。

## 8. 验证与交付门槛

1. 隔离验证所有静态缺失/篡改/错误用途、两个别名与两个不同数据目录、活PID/死PID/复用PID、未知端口占用、重复协调器；静态失败时启动数为0。
2. 真正的普通入口与npm/兼容入口都不调用初始化、写凭据、GRANT、DDL、下载、构建或隐式重试；不仅以文件字符串扫描证明，还对隔离运行的配置/权限/schema及调用事件核对。
3. 本次拥有的小型PG/身份/工作流隔离实例覆盖缺schema/版本不符明确拒绝、已有schema正常、错误流程资源拒绝；保持数据和权限，原任务终态与资源清理均确认。不克隆实际大库、不恢复旧Native大规模QA。
4. Keycloak固定版本参数与不建表行为、Flowable实际JAR运行/初始化两种模式均验证；JAR通过显式构建，记录摘要及代码关联，不把旧包形似可执行当作新模式已生效。
5. 生命周期覆盖迟到、部分启动、已复用进程不被停、无强杀/自动重启、日志和诊断脱敏；没有活句柄终态证据时不宣布已停止。
6. 只在上述通过后，核对本机现有17项引用/部署绑定并恢复当前网站和身份。记录源提交/JAR、实际PID、关键schema/角色/配置摘要、9前端资产HTTP字节及就绪/队列结果；无企业人工测试写入，正常后台变化单列。
7. 适当回归、构建和公开源码扫描、维护分支及同提交Linux CI，按现有成功门禁清理本次发布副本；更新启动指南/交付索引/项目记忆。初始化后的生产安装、云端同版切换和真实企业UAT不由这些本机证据代替。

## 9. 范围与参考

本批为当前Windows本地完整平台恢复；配置/生命周期核心尽量可移植，但不声称已交付Linux原生平台安装器或系统服务。云端会话、生产监督/容量/网络、跨服务灾备/异地保留、对外告警和责任、备案/TLS及生产门禁均继续保留。

[Flowable官方配置说明](https://www.flowable.com/open-source/docs/bpmn/ch03-Configuration/)区分schema验证与自动更新；[Keycloak官方升级说明](https://www.keycloak.org/docs/26.4.7/upgrading/index.html)表明数据库升级是独立维护行为、不同版本的SPI选项曾改名；[厂商26.4数据库配置](https://docs.redhat.com/en/documentation/red_hat_build_of_keycloak/26.4/html/server_configuration_guide/db-)说明validate/initialize-empty语义。这些用于设计依据，不证明本机26.8.1参数已测试；实际固定版本验证列为第8节门禁。

设计自查：预检、普通运行与显式初始化边界明确；不把路径别名当两套部署、不把控制文件/超时当活进程/终态；工作流隐藏DDL/部署和身份自动升级也纳入边界；允许正常服务数据写入但不改初始化权限/密钥。实施验证补充：固定Keycloak仅禁空库仍会创建Liquibase记账表，故在启动Java前通过只读事务验证既有结构、版本及237项变更记录内容摘要，空库直接零进程拒绝；AI/边缘SQLite也采用只打开已有库的普通模式。真实本机网站、身份、维护详情及资产一致性已通过，采集满缓存如实使就绪503，未通过删缓存变绿。
