# 采集容量诊断

沿用完整方案A及容量/保留期授权。先建立实际增长证据，再实现兼顾查询、重放幂等、分析证据和审计链的归档保留机制；本项不替代完整保留期能力。

选择独立只读运维CLI，使用显式业务配置、边缘配置、tenant/edge绑定和可选核心进程身份。相较直接加大容量或按时间删除，此方式可核对当前成本而保留既有数据；相较仅采集边缘队列，它同时测量PG点/回执/审计、SQLite与进程。既有66文件契约及固定运行源不改。

每个PG采样在READ ONLY REPEATABLE READ事务中核对原应用账号、库/角色和三张表OID，读取点/回执/审计全表的count和pg_column_size行大小合计，同时读取实际heap/index/total关系字节及库大小。物理大小不具备MVCC一致性，与逻辑行事实分开标记。审计总量包括其他业务，不归因全部采集；PG事务耗时是诊断采样成本，不是接收事务延迟。

SQLite只读事务核对source绑定、序号、PENDING/REJECTED/ACK计数与守恒；分别测量DB/WAL/SHM实际文件大小与文件系统可用空间。ACK前后状态读取绑定tenant/edge并校验业务窗口，作为跨存储时间边界，不强称与PG原子快照。核心进程使用PID+创建时间限定，CPU增量与RSS/PrivatePageCount区分，不混为任务预算。

报告含实际单调时间窗口、净积压变化、点/回执/审计行增长与每新增点的行大小增长，以及实际分配增长。ETA只表示当前窗口净排空速度的线性情景；无净下降时为null，所有结果均不作SLA/生产容量/保留删除资格。状态重启或计数逆转、库/表/角色/source漂移必须拒绝，输出不包含凭据/报文/业务审计正文。

验证包括模型的零流量/积压增长/负物理增长/计数逆转与边界，真实PG/SQLite只读采样及禁止写入证明、配置/来源不匹配拒绝；本机持续窗口及原业务/角色/队列守恒后验。失败保留有限采样不出成功报告，报告采用独占非覆盖提交。程序仅SELECT/ROLLBACK，SQL与进程超时不触发业务重启。
