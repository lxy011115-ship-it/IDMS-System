# 完整映射检查的等价哈希实现

第二个新物理目标的实际分段测时显示，两份映射缓存中的节点和值SQL合计约0.4秒；全部分支及根校验约5.1秒，捕获遍历另约6秒，业务证明重建约6.5秒。当前批量路径语义及原件字节已一致，但整体比原版慢，暂不接入当前用户安装。

新增只用于读取验证的等价SHA-256实现：压缩树扩展每层仍计算同一个81字节消息（版本字节、两个有符号64位计数、两个32字节哈希），复用每次调用私有的两个方向缓冲区及已验证空子树哈希，避免逐层重复字符串转换、缓冲区创建和多次hash.update。输入格式、计数上限、节点内容地址、深度、左右前缀、叶值、证明节点覆盖及所有错误拒绝保持原语义。分支/根/证明算法仍全量计算，不移除缓存、遍历或独立消费中的任何检查。

新模块不改现有状态映射写路径和旧实现，不产生任何来源、用户或运行能力。先以原实现作为独立参照，覆盖所有深度、边界计数、完整树、存在/缺失/空树证明、错误前缀/值/多余或重复节点/计数越界；真实原进程及双流正常关闭后才能记录组件接受。

组件接受不代表完整路径加速。之后以新不可覆盖缓存/捕获版本接入，仍须新隔离物理目标比较完整七库和两份实际原件的字节、事实及耗时，保留原离线慢算法独立重建。改善得到实际证据后才进入新Control4、完整Native20及同案例独立检查，原30秒不延长。
