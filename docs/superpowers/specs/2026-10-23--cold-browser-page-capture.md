# 冷恢复浏览器存储的正常页面采集

完整方案 A 的浏览器验收仍要求真实 S256 登录、正向业务写入、独立审批、角色与设备范围、刷新、共享退出、三阶段存储和正常清理。本改动只补齐已有验收的采集通道，不能把组件测试或旧中断案例改写为全套通过。

在独立恢复目标的测试 HTTP 包装层，为维修页附加可见采集按钮和同源脚本。脚本只读实际 localStorage、sessionStorage、IndexedDB 名称、CacheStorage 名称及当前可见“我的作业”编号；不写入或清空这些存储。页面只显示数量和摘要。所有原运行代码、页面资源、JAR 与已发布 QA 源保持原字节。

采集请求必须匹配本轮 owner、nonce、准确回环 origin、阶段、时间和有界字段，按 active、switched、logout 顺序独占保存三份私有回执。服务端另外记录请求中真实会话 Cookie 的 SHA256。浏览器工具独立读取同源 Cookie 元数据，立即哈希值，再与页面回执组合为旧严格存储格式。不能过滤额外 Cookie 或用服务端会话代替 Cookie 读取。

继续调用原 verifyColdBrowserStorageSnapshotV1；所有字段白名单、凭据拒绝、外来命名空间拒绝、未知存储拒绝、Cookie 数量/HttpOnly/SameSite、当前账号可见编号、三阶段必须含真实业务恢复编号等要求不变。新校验还要求最终快照与原始页面回执逐字段相等，回执摘要和采集请求 Cookie 与真实服务器 ledger 一致。

实际 Edge 的 127.0.0.1 Cookie 基线为空，因此使用既有回环 origin，无须改变产品允许的 origin。此前另一浏览器的无关 Cookie 保持不动。页面采集失败、Cookie 能力缺失或不匹配均保留为未通过。

新增版本化测试包装层、hold、入口与独立清理入口。全部原有恢复和业务检查仍运行；COMPLETE 要求三份回执均被严格验证，原有清理证明要求不变。完整真实浏览器流程和清理终态出现前，不发布成功结论，不切换云端或原运行服务。
