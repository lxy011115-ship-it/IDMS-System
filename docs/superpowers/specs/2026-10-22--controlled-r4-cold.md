# 持久维护接入 R4 实际冷恢复

沿用完整 R4 拓扑与独立身份数据库，将持久多库 CLOSED 回执、真实角色/数据库清单、退休旧源与实际目录固定进 PGDATA 外的控制记录。禁止布尔准入参数、固定库数/角色数和恢复后重建既有目录指纹。

新受管工作流需 quiesce 自有 SQL/reader/admin 连接并保留库、配置及端口；恢复只创建新句柄，不能重连已 end 的 pg.Client。源码保持旧版本，新版本显式支持该生命周期。

控制器从全部实际加密会话读取 JWT exp，核 JWT/加密期限一致并计入当前验证器宽限；从实际登记队列表读取 lease_until。全部活动门 CLOSED、旧源永久撤权、角色 NOLOGIN/连接限额0、实际零连接、源正常关闭后才能捕获。身份权威及控制记录在业务镜像外。

恢复为新目录，源保持离线。先核加密镜像、OID/权限/结构与冻结状态，再核外部最新签名 ACTIVE 权威、实际 realm marker 和过期窗口。开放 SQL 门期间保持角色 NOLOGIN，最后在全局 SQL 事务恢复角色/数据库连接权限并轮换登录密码；以新私有配置启动新服务，旧配置不能重新连接。所有源目录指纹不变，不旋转业务加密密钥或凭据绑定的服务令牌来偷换原业务见证。

本层还需实际 cold capture/restore、旧 SQL 密码拒绝、旧 lease/SID 拒绝、外部当前撤权保留、新明确授权提交、控制阶段错误与签名/权限漂移拒绝。全组件生产登记、原owner可信接管、全部服务令牌轮换/故障矩阵/Linux部署和最终用户材料仍继续，不能把本层视为整站完成。
