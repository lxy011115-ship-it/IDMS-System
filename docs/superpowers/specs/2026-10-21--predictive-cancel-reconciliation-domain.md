# 已取消预测建单的领域对账

继续上一层已验证外部 BLOCKED/CREATED 协议，实现领域业务职责及恢复。完整系统、HTTP 持久作业和网页仍是既定目标；此规格不替代原范围。

## 业务过程

原操作人使用当前加密 OIDC 会话打开对账，固定原 CANCELLED 作业、计划、取消回执及审计。为该告警持有兼容既有 submit 检查的 intent，防止并发新复核。原历史及取消结果不改写。其他 intent 或业务已变化时仍能记录对账事实，但不覆盖其他决定。

外部服务核对原信封：未创建需持久 BLOCKED；已创建且仍为原初始状态需在原实体事务锁内持久 HELD。新增流程表 UPDATE/DELETE 守卫使领取、维修及审核在锁定期间回滚。已有后续维修状态返回 ADVANCED，不伪造初始状态或盲目关联。原服务及上一层源码保持，新增扩展协议/控制器仅显式安装及启用。

另一位当前有 predictive:approve 的用户复核固定证据、理由和外部状态，原操作人在该复核之后创建的新会话中明确确认。每次写前重验身份、范围、权限和期限；最后确认还重验独立审核人的原会话仍有效且角色/范围未变。原会话、过期复核、身份切换、摘要或版本不符均拒绝。返回或重新观察使旧批准失效。

BLOCKED 经双方确认后另记已解决，释放本对账自己的 intent，无业务工单。HELD 的 CREATED 只在原业务证据、批准输入和当前意图仍一致时原子追加原计划工单、告警/建议、维修关联、双人审计及对账释放待办；保留原 CANCELLED 和其回执。原工作流创建回执已确认，因此工单的初始同步状态正确；外部 hold 另记在对账待办中。业务提交后，以固定领域回执摘要释放同控制外部 hold，再记录对账完成。旧维修客户端即使在间隙排队，外部更新也会被 hold 阻止并回滚；释放后原维修命令可恢复。不得在释放完成时覆盖已经排队或完成的维修状态。

任一步断开或未知 COMMIT 都按原对账/动作编号恢复。发布业务之后权限撤销或服务不可用时保持外部 hold 和持久待办；重新独立批准与原人确认可续办，不能重复发布工单。外部已推进、当前业务已变或其他 intent 冲突时记 NEEDS_ATTENTION 并保留事实，不能谎称已安全关闭。此类记录需在后续网页清楚展示并进入人工处理。

## 实施与验证

新增会话授权封装，直接使用现有实时 session verifier 和加密会话存储，持久化不可反推会话原文的 hash 与创建时间，不接收浏览器传入角色或旧上下文代替当前授权。领域 SDK 持有可信写者，可通过 hooks 由后续作业桥接原子发布，HTTP 不能获得 APP 材料。

新增外部 reservation SQL、目录见证、独立 Java 控制器和品牌证明，绑定旧流程 origin、tenant、服务摘要、目标 JDBC/OID/角色及 authority。正常创建控制器与上一层 V1 文件不改；显式隔离构建包含新增类和资源，不覆盖旧 target jar。

隔离真实 PG/Flowable/Keycloak 和加密会话，验证 BLOCKED、HELD 双人闭环、新会话要求、撤权/范围改变、并发新 review、外部后续状态、旧客户端持锁领取回滚、释放后原命令恢复、丢成功回复/未知 COMMIT/进程重启、动作幂等及冲突、原历史逐字保持。领域关联后的真实维修闭环与完整审计链必须验证。最后精确清理自有资源、固定源码和证据并更新 Git；不称本 SDK 阶段已完成用户网页或整站上线。
