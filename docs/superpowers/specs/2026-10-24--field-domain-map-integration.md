# 现场接入当前状态映射

继续平台依赖计划第 5 步与现场生命周期接入计划。已证明的旧生产 Field 服务使用 public 业务表；统一站点使用当前 state_map 数据库，旧源库在恢复流程中退休。直接登记旧服务会使现场数据进入站点之外的数据集，因此不能作为完成接入。

沿用状态映射现有的维护编译、不可变文档、可信根成员证明和原子分支发布模式。现场准入仍调用原 fieldAdmissionDecision，不新增另一套审批规则；维护期从当前企业负载和所有已发布现场公开配置编译历史时间区间与逐点决定。运行期在同一当前根读取有界路径，并核对当前 governanceAnchorDigest；未知测点使用单独的拒绝决定，不能复用无测点条件的允许决定。原决定中 evaluatedAt 在读取时恢复为准确查询时间，其余批准摘要、定义和未来边界保持。

新治理规划器把现场准入索引与来源治理、业务实体、审计及新控制锚点放入同一候选分支。旧治理规划器及已接受证据保持。启用现场服务前必须使用新规划器完成索引准备并排空旧待发布任务；未匹配当前锚点的索引拒绝服务，不自动信任或重建。

后续现场注册、租约、事务回执和测点写入同一当前状态映射，沿用完整原租约/只读见证/业务确认协议，按原子根提交去重。运行宿主必须绑定当前身份权威、恢复准入、同一已登记 PG 与准确账户/目录/OID，加入严格启用配置及控制器逆序排空。尚未实现的宿主和关闭门禁不能由索引或单独的 SQL 成功代替。

验证包括原规则与编译读取在所有边界前/时/后的逐字段一致、准确查询时钟、未知测点、错企业/错配置、旧锚点、损坏节点/文档和有界读取。实际新 PG 中验证当前状态映射、治理分支原子发布、候选准备/发布前的隔离和更新后的准入。身份失效、现场补传和平台同请求关闭仍须在宿主接线后进行真实组合验证。
