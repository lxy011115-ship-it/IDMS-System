# 本地运行状态与备份巡检设计

日期：2026-10-30。状态：**待用户审阅，尚未实施**。对应[企业交付评估](../../prelaunch-enterprise-roadshow-review-2026-10-29.md)的存活/就绪区分、备份和运行保障缺口。此设计是下一批工作，不修改已完成的业务方案或整体验收范围。

## 1. 当前证据和目的

当前`server/index.ts`的`/api/v1/health`返回进程状态及配置能力，不执行实时数据库、身份或工作流探测。HTTP 200/UP不能单独证明依赖就绪。已有启动/初始化函数会配置服务，因此巡检不能通过调用setup或start函数来“检查”。

本轮只读核对确认本地两份格式2完整业务档案仍可认证，并匹配当前企业数据库绑定；没有执行新恢复，也未核验自动调度、异地保留或时效策略。档案认证与实际恢复需要分别记录。普通身份启动器固定8081端口，当前真实登录服务运行中，本批不为测试停止它。

目的：让管理员运行一次检查，就能区分主站存活、依赖可达、最小绑定核对和备份认证，并得到具体的下一步。不能将这些结果命名为企业业务签收或生产放行。

## 2. 实施选择

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| A，推荐先行 | 跨Windows/Linux的手动只读CLI、明确配置档、简明文字/JSON报告和可选备份认证 | 可以在当前本地运行中使用，详细诊断无需增加公开接口；自动负载均衡就绪接口仍需后续实现 |
| B | CLI与新的HTTP就绪接口一起实施 | 适合接入部署探测；同时需要服务内探测缓存、并发/取消预算及公开响应脱敏设计 |

以下为方案A的具体设计。选择方案B时先补充HTTP接口设计，不能把该选择解释为自动同意外部告警发送或服务重启。

## 3. 入口与配置

新增手动`platform:inspect`命令和Windows“检查IDMS本地运行.cmd”。检查过程读取配置并生成报告；用户需要处理问题时再使用现有启动、备份或管理员流程。

公开示例配置只包含服务地址、已存在的私密配置路径、所需组件、超时/容量和可选时效阈值，不含口令、令牌或业务数据。实际配置保留`.local`。采用明确的完整本地平台配置，不将缺失组件自动降级为已通过。云端在取得实际拓扑后配置自己的档案，不复制本机企业连接信息。

CLI从实际配置档或显式参数取地址，不依赖巡检进程恰好继承了启动器环境。携带凭据的请求只发往配置中已绑定的本机服务，拒绝重定向；不读取浏览器会话或尝试账号密码。私密文件拒绝路径链接及不符合用途的配置，错误输出采用固定代码及必要处理建议。

## 4. 检查范围与结论层级

| 检查 | 行为 | 能证明的范围 |
| --- | --- | --- |
| 主站 | 获取既有健康接口，核对版本及存储/身份模式 | 进程及协议可达，单独标为存活 |
| 企业数据库 | 使用既有应用身份，有限连接、只读事务、最小数据库/企业绑定查询 | 当前连接和所查最小绑定有效；不声称全量业务/审计核验通过 |
| 会话库 | 读取已有AUTH_SESSION_RUNTIME绑定，以现有受限身份核对最小结构和绑定 | 共享会话存储可访问；不创建会话或重建schema |
| 身份服务 | 核对配置中的OIDC发现文档与issuer | 配置的身份端点可达；不表示当前用户已登录或全部认证功能可用 |
| 工作流、预测和AI | 使用现有GET健康/状态契约，必要时带既有服务凭据，核对服务身份和配置模型摘要 | 端点契约及它明确提供的状态；不触发流程或模型生成 |
| 采集和MQTT | 获取已有只读状态；只有端口连接证据时明确标注证据不足 | 不能用TCP连接成功冒充设备在线、消息质量或现场接入验收 |
| 磁盘与资源 | 读取运行目录所在卷的可用空间及当前可取得的预算状态 | 未配置阈值时显示“阈值未设置”，不推造绿色生产容量保证 |
| 备份 | 列出明确目录内的有限候选，可选调用既有档案认证与清单校验 | “文件存在”“档案认证”“实际恢复”分别列示，不把解密成功当作已恢复 |

检查使用`PASS`、`FAIL`、`UNKNOWN`、`NOT_CONFIGURED`四种结果，并附证据级别。总结果只能在所有配置的必需项都有对应层级证据时通过；任一未知、配置缺失或扫描未完整都明确报告。可选组件不影响基本运行结论，但不得被隐藏或显示为已通过。生产放行始终是另一项验收。

## 5. 有界与数据保护

默认并发最多2项；单个HTTP探测观察预算3秒、响应读取上限64KiB；TCP探测观察预算2秒。数据库连接和查询观察预算各3秒，总任务调度预算默认30秒。到期取消并等待原任务的终态；取消/回滚收尾可能超过预算，报告分别记录观察超时与实际结束，不承诺30秒内强制终止。不能把观察超时当作任务已终止，也不自动再启检查进程；超出预算的未完成项是未知。

只读数据库检查复用现有取消/有限借连接机制，禁止调用建表、初始化、授权、迁移、业务命令或恢复入口。不能为证明缺失就绪状态而关闭实际数据库、身份服务或生产网络。

备份认证单独选择，逐份处理，沿用现有128MiB压缩dump预算和256KiB清单预算。每企业最多检查32个候选；超过预算或有无法核对的损坏候选时明确报告不完整，不能静默用旧档案代替新的失败档案。源数据库、企业和格式2清单均需匹配。解密dump仅在内存校验，使用后清空可变缓冲并释放引用，不写临时明文。

报告只写服务逻辑名、状态/证据级别、有限版本、时间、数量和处理建议。剔除口令、令牌、连接串、私钥、原始HTTP/SQL异常、业务正文和完整私密文件路径；不输出全进程环境或全容器配置。JSON报告和文字报告均保留在私密本地目录，不加入公开源码。来源提交、配置摘要和检查时间用于定位，不能替代实际运行版本证据。

## 6. 必要验证与本地交付

验证正常、拒绝连接、错误issuer、HTTP错误/超大或迟到响应、数据库超时及资源收尾、未知组件/缺配置、凭据和底层错误脱敏；备份验证覆盖正确档案、篡改、跨企业、损坏的新候选及扫描预算耗尽。检查前后比对私密配置和业务版本，确认无业务写入或授权变化。

使用隔离依赖验证失败分支，再对当前本地服务进行一次只读检查；不停止实际身份进程，不添加企业测试单。保留真实冷启动、真实账号和跨服务恢复仍未签收的说明，不反复运行旧Native大规模测试。

新增命令、配置示例、指南和必要检查通过后，按照既有源码清单/凭据扫描/维护分支/同提交CI流程保存。当前网站继续使用既有版本；手动CLI不需要重启主站。

## 7. 整体目标中继续保留的工作

方案A通过只关闭“管理员手动检查”这一部分。HTTP就绪接口、自动监测与外部告警的接收人/响应责任、实际冷启动、生产网络和容量、身份/工作流/采集配置的跨服务恢复、云端同版切换、域名备案/TLS及企业多岗位签收仍需取得各自证据。本设计不以手动报告替代这些要求。

## 8. 设计自查

沿用已有服务GET契约与专用备份格式，不新增账号权限或业务写入口。未知与未配置状态不能变成健康；档案认证不等同于恢复；当前配置不等同于真实运行；一次检查不等同于后台自动告警。无自动重试、重启、下单、付款、恢复或对外消息发送。
