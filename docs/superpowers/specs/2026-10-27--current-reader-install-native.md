# 新完整来源中的读者安装执行

新Native18保留Native17的全部64检查名称和实际原流程，另在每个分支增加一次完整安装检查，总计预期66。先完成旧原HELD下的全部SQL/材料/用户确认，再由原句柄正常释放旧guards/readers并停止旧reader JVM，之后才调用新Control3安装。旧SOURCE、旧review、原私密凭据文件和全部程序输入不改。

使用原元数据阶段实际创建的用户配置私密HMAC包，避免再次登录制造新用户会话；安装请求仍读取原保存的确认ID/时间/令牌。新控制入口完成实际档案、7库事实、当前用户、持久尝试、提交前授权和新连接观察。检查安装后重复请求及新控制器重开只读历史，不再阶段或认证当前用户。

独立QA另使用原旧密码实际登录拒绝、新密码实际只读登录成功，并在新的真实SQL事务捕全部角色/成员/数据库/密码/角色配置原始行与backend帧，比较只有两原读者密码变化，将完整私密见证按上下文密钥MAC保存。它明确是安装后的另一次QA观察，不伪称与控制器观察是同一SQL事务。全部root连接退出后目标PG由原生命周期句柄正常关闭；不启动新reader/HELD/MQTT/业务服务。

源清单保留原1472全部输入，追加新入口及其真实静态公共依赖和相应规范。预检不执行产品模块。成功仍需新的同案例独立消费者，不能把原针对Native17的检查器套用到66项，也不把正常提交冒充真实网络回复未知注入。
