# 治理工作台与有界读取

延续完整方案A，上一轮持久作业属于已完成进展，完整目标ACTIVE。此阶段把六动作接为真实用户工作流；原站点保持，旧发布源不改动。使用新的控制台入口、读取投影和队列worker派生版本，旧30源及全部历史交付继续可校验。

选择同业务候选根原子发布的治理读取投影。直接连旧HTTP会读取旧数据库；请求时重构整租户图会延续容量问题；因此新索引在维护准备阶段编译，列表/详情按固定键读取，不能在请求中重新编译。既有维护全图成本不作为普通写者的最终复杂度目标。

索引包含模板摘要/详情、批次白名单摘要、分页原始解析行与错误、独立原件分块及SHA；列表不含base64/全rows/更正baseRows。原件是不可分割的授权对象。范围与原dataScope.batch逐项等价，包含更正前数据，不额外把无已批准DEVICE的未知设备在所有scope下都拒绝。将每个维度的范围值计数写为不可变键，少量不同值可内嵌；大集合通过允许值计数之和等于总数证明全部行可见，避免读取10000行来检查一个批次。每请求设置键数、值字节、扫描数和返回数预算，不能跳过未授权证明而返回摘要。

治理索引绑定tenant/governanceAnchor/catalog generation。普通遥测追加不改变治理索引。治理任务UPDATING期间保留旧已完整发布投影，明确显示更新中；只接受ACTIVE/PAUSED或由本类型作业证明的UPDATING。初次安装由受管维护激活生成旧图投影，禁止安装到任意partial根。后续模板/导入命令在同候选根中发布新投影，失败/取消保持原投影。

列表与行分页游标加密绑定用途、租户/主体/当前角色权限和范围、部署、索引generation、路由、过滤条件、位置和期限。读取前先复核当前认证及租户状态，再接受旧游标；索引变化要求刷新。每次返回已证明的当前投影，不能把旧窗口授权当作永久权限。单条模板与批次详情、原件和行分页也使用当前scope。原件先独立验证所有分块、总字节与SHA，再在固定窗口输出；不拼入其他批次或完整历史。

工作台沿用现有产品术语与样式：登录身份、模板目录/编辑/提交/独立审核、JSON/CSV/XLSX导入、资料类型/映射/更正引用、批次行与错误/独立审核、作业进度与重新授权/取消。自审按钮隐藏仍由原业务规则最终拒绝。接受与业务完成、HUMAN_REVIEW与真实批准必须区分。使用真实createAuth共享PG会话与CSRF，不从浏览器传roles/context，不使用fixture身份作为产品登录。

客户端在发送前生成并保存command UUID及输入hash，只保存恢复键，不落地原件、Bearer或session值。未知接受结果按同键查作业；重试同一内容沿用同一UUID，不能因刷新/网络中断自动生成新命令。新控制台提供按本人command UUID查到已知作业的只读入口，再复用原作业API的当前权限证明。状态列表明确为本浏览器最近记录，提供按ID恢复，不声称是数据库全量作业列表。页面登出/切换用户隔离所有本地主体状态。

验收使用隔离fresh PG、真实投影编译/原子发布、旧dataScope规则独立比对、混合范围/更正前范围、最大10000行/大原件的有界列表和行读取、篡改/过期/跨用途游标、当前撤权、真实HTTP下载SHA、Keycloak/Chrome六动作及文件导入/独立审核、网络中断同键恢复与重新登录/取消、移动屏和XSS。新HTTP仅QI/READER，worker独立APP；验证原队列fence、原站点与全部旧发布保值。精确清理自有DB/OID/owner，禁止FORCE和终止数据库backend。
