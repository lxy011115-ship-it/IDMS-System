# 共享加密OIDC会话

延续完整商用方案A，补齐已验证双实例核心的浏览器身份状态。选择独立PostgreSQL认证会话数据库与专属owner/migrator/app/backup角色；不把令牌放到企业业务库或Cookie。不修改已经应用的业务v1/v2/v3校验和。独立schema1维护认证元数据和加密状态，业务备份仍明确不含此库。

浏览器只有256-bit随机Cookie；数据库只索引SHA-256后的随机ID，session/pending材料以AES-256-GCM加密，AAD绑定业务部署、issuer/client/audience/publicOrigin、记录种类、索引、版本、绝对过期时间和keyId。密钥与运行/部署凭据分离受限保存；运行角色不能DDL、改元数据/迁移记录、连接企业库。Key验证材料发现不一致时启动失败，不能回退本地Map。文件Demo/直接单元注入保留内存实现，Postgres真实OIDC必须持久化。

登录状态最多5分钟且跨实例一次性消费，Cookie校验后才删除，PKCE/nonce与原公开回调绑定；会话固定8小时最大寿命，不滑动延期。每次授权校验签名访问令牌和当前角色/数据范围；即将过期时会话行锁内刷新并保存新令牌，跨实例并发只刷新一次。刷新失败持久化撤销且不恢复旧状态；注销CSRF/Origin校验后持久化撤销，再尝试上游注销。网络/数据库不能分布式原子提交，刷新时崩溃导致无法确认新令牌时失败关闭/重新登录，不声称无损恢复所有供应商轮换。

通过同一公开反向代理/域名运行两个独立核心，登录A/回调B、共享Cookie和CSRF、同SID并发刷新、角色/范围收回、跨实例注销/重启、过期/回放/篡改、错误密钥与数据库断开、租户/客户端/Origin隔离均需验证。旧独立会话测试应升级为共享语义；真实Flowable/AI/采集和原企业数据只读回归继续。
