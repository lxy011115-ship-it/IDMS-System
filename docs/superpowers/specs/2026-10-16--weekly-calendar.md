# 循环班次与日期例外

延续按当前待办继续开发的授权。上一轮已完成日历/计划覆盖部署，为已验证进展。本轮补齐循环班次与计划例外；完整商用方案A仍ACTIVE。

沿operation-calendar独立人工发布/单设备编码族/作用域/幂等/冻结摘要。旧显式日历格式及其512段上限和历史SHA完全不改。循环日历新增recurrence声明与服务端冻结expansion依据，最多32条周规则、128个日期例外、366天范围及8192展开段，不提高既有HTTP/任务/SQL默认额度。无DDL。

选择：仅保存规则、查询时按当前时区展开会让旧批准内容随tzdb改变；手写偏移/夏令时算法容易错；采用锁定@js-temporal/polyfill 0.5.1和当前Node ICU/tzdb在草稿保存时展开并冻结UTC periods/来源SHA。读取只校验冻结配置/摘要/原治理事件，不重新展开。导入冻结包须与当前编译器/tzdb一致并复核重算结果；不同版本或声明/展开不符失败，不能静默改写。复制/编辑通过明确重建草稿去掉派生字段，再独立终审。

recurrence包含version=1、outsideShifts=STOP和明确默认停产依据、ISO星期1..7、班次start/end(HH:mm)/endDayOffset(0|1)、reason；班次最长24h。周规则不可重叠，包括周日跨入周一。例外按当地日期替换整日RUN片段，含此前跨夜班落入部分；未列出的时间按声明STOP，例外shifts限当日，不跨夜。例外跨两日需各声明一日，不能隐式取消整个相邻日期班次。

时区为命名IANA区，重复钟点策略EARLIER/LATER/REJECT必须显式；不存在钟点始终REJECT。例外日期本身须存在且落在声明范围内；当地日边界取实际startOfDay，因此23/25小时日及午夜跳变正确处理，完全跳过的日期不得伪装有24小时。班次clock端点若不存在仍拒绝，不能借earlier/later平移。编译先检查声明结构及重叠，再在例外日期内移除周班片段、加入例外片段、填显式默认STOP。裁切后每个冻结RUN段以其起点按既有规则分槽，不合并相邻班次来改变锚。periods reason包含周规则/例外来源，审批可查看完整展开和tzdb/编译器/来源及periods摘要。

模板新建循环入口与编辑重建说明，覆盖响应显示循环/例外数量、冻结tzdb与段数，原质量/未知/模拟标记保持。无现场接入、RUL、历史当时配置重放或生产验收声明。必须验证普通周/夜班/周界、节日及临时加班、23/25h/30min/整日跳过、午夜跳变/重复钟点策略、伪造/老tzdb冻结包、完整旧日历字节与原回归、真实PG/OIDC审批/来源/版本/重启/同RR/移动端与受控原站点保值升级。独立交付与记忆，不含密钥、原件、实际备份或原始日志。
