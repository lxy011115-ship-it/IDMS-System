## 原实例来源能力

新增 application lifecycle 版本保留原 fork、IPC 关联、完整 registry 沿革及全部正常退役检查。成功 READY 时，在父进程私有状态中缓存实际 registry header、JSON 配置图和 SITE 槽位；不能在进程结束后凭新提供的路径重新选择来源。

只有同一模块 WeakMap 中的原 handle、实际 READY、完整正常退出、全部资源退役、原 manifest 和 JSON 图字节仍一致，才可产生来源能力。取消启动、失败退出、序列化描述、复制 handle、旧版本 handle、同 PID 新进程和 caller 自报的许可均拒绝。

公开证据只包含原 owner/进程绑定、原部署身份、明确的站点开关、企业集合、配置数量和独立随机 MAC。私密路径及私密配置文件摘要保留在能力内部。JSON 图覆盖不等于证书、二进制、账户、现场设备或 broker 的完整材料验收。

能力关闭后立即失效并清除 MAC 密钥；读取和消费须再次核对原 holder、原退出、缓存 header 及原文件。重新序列化不能恢复能力。

## 原来源登记与兼容边界

新的 SOURCE 创建入口内部消费上述原能力，在原完整 SQL/根捕获及维护关闭期间记录 versioned fieldSource 扩展。现有 V3 SOURCE 读取与既有只读功能保留；旧 SOURCE 缺少扩展时，新的完整材料路径明确拒绝，不能补写或默认为禁用。

扩展必须同原 source 集群身份、全部企业、业务 map OID/目录、原关闭回执、原实例身份及最终完整事实绑定。新增 SOURCE hash 覆盖完整扩展。原实例绑定可能属于前一次已准入恢复，不要求它与本次新 controlId 相同，但必须证明同一实际源集群和所捕获的部署。

启用站点须核实际 platform/gateway/host 配置、全部已配置企业和通道、当前完整注册沿革及对应 map 事实。明确未在站点配置的企业与明确关闭整个站点是不同状态，均保留历史 FIELD 数据。不得按成功读到的通道子集声称完整。

## 当前恢复材料

在新的冷恢复 HELD 会话内，可信部署侧声明明确引用 FIELD 平台、签发/接收、全部 edge/profile、OPC UA 证书与可选口令、请求/事件密钥、MQTT 双端与 broker、spool/schedule、启动配置和实际构建产物。

所有字段同完整来源和实际 SQL/根对应，所有文件由原冷材料能力管理规范路径、单链接、全部字节及私密 MAC；不输出无密钥的口令或私钥摘要。保留原 30 秒材料期限、原守卫和读取后端、事务回滚、当前身份以及关闭时排空。

旧 FIELD RESTORING 操作意图与新的 cold HELD 属于不同协议。可以复用纯 profile、证书和传输解析，但不能伪造旧 control 或以任意 authorize callback 取得新所有权。新的内部材料入口直接绑定原冷会话与原意图。

固定证书的 OPC UA 只读观察和 MQTT TLS 观察只证明对应范围；MQTT 应用会话/ACL、摄入、lease、正式激活仍须后续实际验收。

## 恢复后既有只读角色的来源

真实 FIELD owner 案例 f1b2f28d0203 已通过 28 项和独立正常退役复核。它的原应用挂载已经准入的旧冷恢复控制。因此，新 SOURCE 不能要求重新在这个已封存、已恢复集群上创建只读角色。现有 WorkflowReviewSourceInstallerV1 明确只在真实未封存的 RuntimeFenceProvisionV1 内安装角色，且把目录固定在第一次安装位置；保留这项限制。

后续在最初新建来源时，由现有真实 installer 捕获只读合同，并在第一次 SOURCE 首次写入之前一并记录，完整来源哈希覆盖合同。恢复后必须通过新生产来源能力核验当前原管理进程、其固定 trust/SOURCE 哈希、原完整物理恢复与已准入目标、相同系统 ID、原角色 OID 和原全部 SELECT 权限、HBA、原工作流定义及签名绑定，再只读捕获既有角色。新能力不得接受调用方自报的 ACL/合同，不新建角色、不在已封存目标授权，不伪造原 installer 私有状态，也不要求安装进程跨越所有后续重启继续存活。

这项新捕获必须直接消费当前真实 FIELD owner 能力，并由完整 SOURCE 工厂使用相同的原能力。旧来源没有最初只读合同时明确拒绝；不能补写已捕获的旧 SOURCE。当前 runtime-cold-readonly-control-v6 仅完成 fieldSource 扩展进入首次 INSERT 的实现与边界预检，仍调用原 fresh installer 捕获，尚不能证明恢复后真实 FIELD 来源的完整创建。新捕获接入、真实启用及显式禁用 SOURCE 案例完成后，才可把该步骤记为完成。

## 验证与交付标准

必须同时覆盖实际 FIELD 启用、实际显式关闭、已配置企业子集和旧 SOURCE 缺证据。正例必须使用原 fork 和正常退役、真实非空通道、原完整物理恢复与七库、当前身份和完整原守卫；不能仅用关闭分支通过替代启用范围。

负例包括伪造/复制/跨版本 handle、取消或失败启动、实例 header 替换、JSON 图遗漏与字节漂移、丢失通道、错误企业/库/目录/密钥/证书、材料过期或关闭、原身份变化及恢复后漂移。独立复核须读取原见证与实际文件，保留所有失败及正常资源清理。

只有来源和当前核心、FIELD 材料全部组合通过，才能建立完整候选；独立批准和正式运行准入仍须后续显式步骤。当前所有完整材料、正式激活及最终目标完成标志继续为 false。
