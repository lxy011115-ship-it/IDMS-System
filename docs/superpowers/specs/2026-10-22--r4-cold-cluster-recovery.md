# R4 数据库整簇冷备与恢复准入

延续原完整目标，补齐新增 state_map、各领域队列、对账围栏及外部取消/锁定表的可恢复性。当前原系统与云配置不变，开发和验证使用新建私有 PostgreSQL 16 集群；本阶段不构成生产切换或完整灾备完成。

## 路径选择

采用完整 PGDATA 的受限加密冷镜像，保留数据库/角色/关系 OID、目录见证、序列、事务状态、密文、部署标识和原生取消记录。逻辑导出到新 OID 需要另外设计 AAD 与服务配置代际迁移，不能靠放宽见证或修改原任务解决。已有旧工作流 38 表逻辑归档保持历史用途，不将其标记为覆盖新 schema。

冷镜像要求正常停止整个独立数据库集群，并包含其全部文件。此选择允许部署维护窗口，不能代替持续 WAL/PITR、HA、跨平台迁移或逐租户逻辑恢复。当前格式只允许与源一致的平台、架构和固定 PostgreSQL 16 构建；外部 tablespace、链接、standby/recovery 信号或外置必需配置均拒绝。

依据：[PostgreSQL 16 文件级备份](https://www.postgresql.org/docs/16/backup-file.html)、[pg_controldata](https://www.postgresql.org/docs/16/app-pgcontroldata.html)、[正常关闭](https://www.postgresql.org/docs/16/server-shutdown.html)。

## 捕获边界

先通过当前源连接核对实际集群、数据库/角色清单及业务协议见证。独立操作记录保存原权限；业务进程正常退出后，登录与连接上限形成持久围栏，真实旧连接归零。源维护证据和归档范围必须一致，不能把一次只读查询当作停写。

只有源进程已终态、无 postmaster.pid、固定工具报告 clean shut down 时才扫描。完整目录树必须是普通目录/单链接普通文件，拒绝重解析点、路径别名、链接、特殊文件、外部 WAL/tablespace 以及源在复制期间重启或变化。每个相对路径、文件长度、SHA 与完整目录清单认证；上下限仅为拒绝界限，不作为容量声明。

独立随机 256 位密钥，流式 AES-GCM。格式与 key ID 在 AAD 中；manifest 与所有文件内容一并认证。私密临时文件和最终文件只在受限目录中创建，完整封装自验及源复核后才原子发布。同一操作重入以既有认证结果核对，不覆盖未知文件或把半包视为完成。

## 恢复边界

完整认证先于任何目标创建或 PostgreSQL 启动。目标是同一受控工作根下全新隔离目录；不能覆盖现有 PGDATA、部分恢复表或替换当前运行目录。路径、大小、重名、父目录/文件冲突、保留设备名和文件摘要逐项核对。还原后文件内容完全等于认证清单，源数据库无需在线。

恢复本身不启动或开放业务。后续隔离检查只使用固定 PostgreSQL 程序、明确的新目录/配置/端口及回环监听，防止归档中的路径指回源。恢复的应用登录/数据库围栏必须保持，不能自动恢复旧业务访问。

运行准入需要当前操作记录核对“旧源仍围栏/旧进程终态”，按角色/库原 OID 恢复精确既有权限，并验证全部运行见证和密钥。若重用服务配置中的逻辑端口，必须先证明旧监听退休，不能两份镜像同时接单。独立当前 OIDC 权威不从旧镜像回滚；已捕获访问令牌和租约必须到期或经过显式安全刷新，才允许新的用户动作。RELEASE_STARTED 只按已持久固定意图恢复，不能产生第二工单或覆盖维修进度。

## 证据与实施次序

先实现可独立校验的冷镜像格式、完整文件树捕获/认证/新目标还原和正常关闭证明，在真实独立 PG 上验证 SQL 数据、OID、序列、权限及所有 schema 都随整簇恢复。随后接入 R4 的业务/认证/流程真实状态，验证原密文可解、围栏可执行、当前授权与已开始释放恢复，再接持久控制器和正式启动准入。基础镜像成功不能代替后续步骤。

负例包括源仍运行/崩溃状态、链接或外置 tablespace、复制时源变化、路径穿越/重名/目录冲突、截断/错 key/篡改、目标已存在和恢复中断。中断不得发布或开放部分结果；清理只针对带身份清单的自有新路径与进程，检查最终绝对路径，不递归删除未知目标或终止未知数据库会话。

部署秘密、加密密钥与外部身份服务不默认为镜像的一部分。它们的独立见证、恢复和轮换仍属于原完整目标；公开提交只有源码、去秘密验证摘要与说明，不包含镜像、私密配置、密钥或原件。
