# 当前根冷恢复的持久审核上下文

继续原完整现场恢复、人审与最终激活设计。首先将经过真实 RuntimeColdControl 冻结/完整归档/恢复的目标持久置为 FIELD_REVIEW_V1，使旧 admit 与普通运行守卫保持拒绝。该阶段不等于批准，不运行现场机器，不恢复业务 LOGIN，不自动迁移旧审批。

claim 必须持有原 cold SQLite writer mutex，认证不变 source body/hash、RESTORED 事实、完整 AES 归档及原证据、原程序摘要、源真实离线与不同的目标目录、所有捕获清单和当前独立 Keycloak 权威。所有实际 state-map 租户都须覆盖；禁止提交单企业子集来掩盖别的恢复数据。源控制和归档保持不变，只有该控制记录的 phase/details/hash 原子更新。

每个租户使用本次工厂创建并实际持有的原 FieldRecoveryAuthorityLock，保留原 advisory lock、native gate 和原连接。维护内核只认可工厂 WeakMap 中的能力，前后重查其原连接持锁，核对唯一锁拥有者与实际 backend；不接受 PID 清单或领养外来连接。未知连接仍阻止维护。

新维护 V4 继续使用既有原 SQL，保留默认小快照限制，并另提供受控全事实路径。全事实遍历完整当前树，逐节点/值重新计算根及叶数，核全部 SQL 回执链，对当前数据库全部用户关系生成有界行摘要，再从同根证明完整重建业务/输入/幂等与审计。输出是私密流式文件，离线工具使用私有磁盘索引重建完整根和完整领域负载；不能仅验证几条当前成员证明。离线工具重算根/回执/领域，不把关系摘要认证冒称为离线重算所有 SQL 原始行。

全事实的两次读取不得持久改变 SQL 根、审计、围栏代数或任何原角色属性。初次 claim 在所有 SQL 连接及本次原锁真实关闭后，持久记录确切 recovery UUID、备份/源 hash、固定配置与材料摘要、全部租户基线/证据 hash、新部署与逐租户激活身份。SQLite 一次 COMMIT 保存阶段和全部绑定；不产生新的业务审计或 FIELD 注册。

同操作重试与新进程 status 仍重新查当前外态、归档、源离线、旧证据和全部目标事实。不同操作、材料漂移、原证据损坏、缺失租户、当前权威漂移、未知会话均拒绝；不回退 RESTORED，不给旧 admit 兼容例外。第一错误保留，清理失败单独标记，持有的原资源保留到实际退役，不能隐藏失败或丢弃连接引用。

本阶段只提供 root 运维 CLI CLAIM/STATUS。真正作者/独立审核人 JWT、全部贡献者与当前 Flowable、恢复计划/维护提交意图链、注册材料与 ACTIVE 发布、凭据轮换及最后 SQL COMMIT 尚须完整接入。当前 Flowable 普通启动会尝试 DDL/部署，不能为读取审批事实而提前开放业务；后续须具备独立的恢复只读路径。本阶段 source 的真实 Flowable 停止证明和持久状态随原冷镜像保留，不把它们当作已完成当前工作流审核。

演练从真实两租户 R4/认证/Flowable 及持久冷恢复控制产生上下文，额外合法 QA namespace 用来验证超过 256 键且包含未知命名空间的完整性。测试包括两租户全覆盖、未知连接与伪 PID 能力、当前真实身份权威漂移、持久 claim/拒绝旧 admit、同操作与新 CLI 进程重开、篡改证据副本，以及最终根/审计/CLOSED 与全角色仍封闭。全部 formal/full flags 保持 false。
