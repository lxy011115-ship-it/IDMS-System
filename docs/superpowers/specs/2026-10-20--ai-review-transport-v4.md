# v4 AI 审核持久传输

本阶段完成可组合的 PostgreSQL outbox、冻结请求、租约 worker、签名回执持久化和人工回退。沿用当前本地网关协议和固定 qwen3:4b 清单。业务发布适配器随后接线；本阶段的 RESULT_READY 明确表示“回执已保存、尚未应用业务”，不表示批次已审核或批准。

## 选择与边界

- 采用同业务库的独立受保护 schema；调用者在自己的事务中调用 enqueueInTransaction，可与最终业务根发布原子提交。独立库无法提供这一事务边界；直接 HTTP 调模型无法恢复未知接受。
- 请求和结果分别使用 AES-256-GCM、不同 AAD，绑定部署、数据库、租户、请求 UUID、批次、快照、版本和当前网关配置指纹。SQL 只保存非敏感头与密文。服务 token 只在私密进程配置中。
- 持久 dispatch 与网络失败计数分开；三次网络失败后人工回退，保存失败不消耗网络失败预算。30 秒 DB 租约、10 秒独立线程续租，fence/owner/token 防止迟到写入。SQL 行锁 SKIP LOCKED 允许其他请求继续。
- 有效回执需要原协议 HMAC、全部证据、固定模型名及 digest；无效回执立即生成本地人工回退，临时网络失败达到三次才回退。错误内容、任意模型正文和凭据不进入公开状态。
- 终态为 RESULT_READY，结果只追加一次；未知 COMMIT 用新连接恢复该冻结结果。保存失败不计作推理失败，也不覆盖已保存结果。
- 受信调用者必须提供当前租户准入检查；停用或配置变化不调用模型，保留待办。历史提交人的角色不是服务调用的当前授权。业务应用必须另外再次验证租户、版本和快照，更新全部投影并追加业务审计。
- 新 schema 仅用于新建隔离部署，绑定角色 OID/数据库 OID/目录 hash/非 MVCC DDL epoch。ALWAYS IUD/TRUNCATE 守卫，私有写上下文，禁止 APP 直接表写。DDL 锁遵循 state-map 1 → governance 2 → AI 4。

## 验证

单位验证 UTF-8 截断、样本覆盖、请求/密文/签名/配置绑定和无自动批准；真实 PG 验证同事务回滚、同键重放冲突、并发领取、三次网络回退、结果不可变、租约过期旧 fence 拒绝、线程续租、DDL epoch 及精确资源清理。隔离网关连接现有本地 Ollama，使用独立 SQLite、独立 token 和纯合成材料，验证真实模型和网关幂等重放。原站点与所有旧冻结交付保持。
