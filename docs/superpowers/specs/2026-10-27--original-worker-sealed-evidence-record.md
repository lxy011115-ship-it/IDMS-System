# 原验证子进程证据封装与独立核查

沿用方案A及完整新安装案例独立验收范围。源码检查发现：原worker owner V1在返回的预检结果中记录PID、起止时间、双流正常退出及文件未变标志，但未返回nonce、原输入摘要、终态文件摘要和文件身份。这些原件虽存在私有目录，仅按PID/时间与未变标志关联，不能声称签名预检逐项绑定了原件文件。

新增owner V2。原固定entry V1、原Node、完整慢算法、输入结构、进程拥有链、等待与退出判断、全部前后文件检查保持。正常完成后才额外获取原终态文件pin，形成只读记录：原nonce、输入/evidence/entry/Node/terminal五个完整文件pin、完整结果摘要及记录正文摘要。该记录附加到原terminal描述，由现有预检HMAC覆盖；不创建新的执行能力。失败结果不返回阳性记录。

新增目标映射和catalog validator V2，只将worker路由换为owner V2；SQL顺序、完整事务、七库与两完整map、静默/退休、全失败finally等待原子任务不变。旧源码和运行中的Native21不改，不能为旧签名结果补签这份新记录。后续新生产案例才可使用V2路径。

新增离线独立读取器。调用方必须先完成原拥有任务与签名预检认证；读取器核对固定entry/owner的原source pin及原任务Node摘要，严格record/schema/原nonce/路径/文件身份与摘要，唯一私有输入、实际原件、原终态JSON/一条原stdout、inputSha/result、PID/时间/双流。每个文件读取前后身份和字节保持，旧无封装结果明确拒绝。不得仅凭这些文件自行认定原拥有任务或签名预检可信。

新安装独立helper V2保留V1的完整schema、HMAC、唯一日志、原30秒、全部原始身份、catalog/password/frame、重复重开历史及单独QA见证验证。每份已认证preflight map先核对新封装记录，再保留原慢算法直接完整重建的原验证；不能以新记录代替重建。

组件使用新私有目录和新原Node worker验证两份完整原件，不重放SQL/OIDC/现场传输。覆盖缺失封装、nonce/摘要/路径/输入/终态/结果/时间/源码/Node绑定漂移、额外或重复输入、原件变化和伪造handle。源静态预检不等于真实worker或生产安装接受。运行中的完整测时任务不受修改；CPU密集组件在其真实终态后执行，避免干扰原窗口测量。
