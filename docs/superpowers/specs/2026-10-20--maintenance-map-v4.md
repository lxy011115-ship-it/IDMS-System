# 工单维修增量写入 v4

目标是让已迁移工单的领取、开始、提交、独立终审及 Flowable 回执应用在 v4 权威映射上工作，不重建企业全图。当前阶段实现内核和真实数据库/引擎验证；下一步再把内核接入当前 OIDC、HTTP 与工单界面。完整商用范围不因此缩减。

选择按对象证明读取、复用 changeWorkOrder 规则、同 CAS 发布实体/关联告警/建议/旧审计/业务幂等回执。继续使用整图维护内核会扩大普通维修成本；直接改工单字段会丢失独立审批和证据规则，均不采用。模板绑定保留原冻结字段验证。独立维护索引只记录工单到原规则第一个建议的稳定关系，不缓存实体值；由完整验证的初始化器发布。任何未来预测/工单创建写者必须同时安装该关系。

本地旧工单保留本地模式。带 Flowable 标记的工单不能降级：先冻结与旧引擎字节兼容的命令、提议业务状态和 beforeDigest，并在同一次 CAS 写入 PENDING 与队列索引；网络调用发生在事务之外。引擎通过 commandId/requestDigest 幂等。收到回执后，验证绑定和工单版本，重新取当前身份/权限/范围，再以同 CAS 发布业务状态、关联状态、确认审计及队列完成。多个 worker 可发送同一不可变命令；保证引擎幂等和本地一次应用，不声称网络只发送一次或数据库租约。

实际网络失败持久计数，7次转 HUMAN_REVIEW；有效响应后的本地存储失败保持原命令，不计网络失败。明确拒绝/无效回执转人工；人工重试使用同一命令内容和 commandId，追加队列位置并留下审计。队列按持久序号处理；单条暂时失败会阻塞后续，是本阶段吞吐边界。维护围栏/租户挂起/当前授权失效不发网络，也不推进工单。

授权解析器是宿主提供的必选受信回调，冻结 context 只作证据，不能作为当前授权。当前 QA 用显式可信上下文，不能冒充真实 OIDC 接线。远程引擎要求 HTTPS，loopback 可明文；固定服务配置、限制响应、禁止重定向/请求方指定地址，token不写入映射或日志。回执只能由真实配置的传输对象产生的内存品牌接收。

初始化拒绝尚未处理的历史 PENDING/HUMAN_REVIEW 工单，不能忽略旧 workflow_outbox 或补造历史；其余历史 outbox 的安全迁移和新建工单流程保留为后续完整迁移任务。索引发布前完整核对实体未漂移；普通写入遵守当前 control/read_catalog 锚。通过现有治理分支更新后索引仍指向相同关联，不依赖陈旧整图摘要。

验证：真实 PG 的本地全生命周期、领取/版本/范围/自审/摘要/模板负例、并发同键与不同键、维护/挂起、SQL中途失败原子回滚、实际 COMMIT 回复丢失、新实例恢复；真实独立 Flowable 的同命令重放、丢网络回执、当前撤权不应用、7次网络失败/人工重试、有效回执后存储失败恢复、双 worker 一次业务审计。每次读取统计和完整重构后验，原站点与全部冻结源保持，资源精确清理。
