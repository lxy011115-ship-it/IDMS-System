# 当前用户核验的可重建原始记录

当前 Gate v1 会真实校验签名及当前身份，但保留的 actor 结论不足以让另一消费者重建当时的决定。正在运行的 Native16 源码/案例不变；该案例的当前用户结果仍须与可重建证据要求区分，不能仅凭新的 true 字段宣称独立核验完成。

新增记录读取器固定可信身份配置，复用原生产 CurrentRecoveryActor 验证提交权限及当前用户；另从固定 issuer 实际读取公钥，用捕获的同一公钥再验证该实际令牌，再读取当时 realm/client/user/realm roles/sessions，前后重新核验原当前 actor 不变。只保留决定所需的响应字段：不保存服务账号令牌、客户端密钥、未知属性或完整管理员响应。原用户令牌属于私密材料，后续仅保存在原控制上下文绑定的私密证据文件，不能发布到 Git/CI 公共输出。

读取器串行持有自己的异步操作和身份读取器，30秒窗口内完成；关闭先中止、等候全部原请求，再关闭身份读取器并清理自有私密副本。它只提供历史数据，不创建用户批准、持久确认、SQL、HELD、启动程序、MQTT 或正式启用能力。

另一个纯离线消费者不导入生产读取器、Gate、当前用户验证器或任何网络工具。它必须收到原控制日志/原执行证据认证的预期摘要与准确 issuer/client/tenant/权威 marker/观察时限，从原始令牌和公钥实际重验 RSA 签名，并从已选择的原始响应自行重建权限、企业、范围、撤销时限和唯一会话，再逐字段比较 actor。公钥本身由本次实际身份读取获得；自包含的 JSON、令牌与摘要不能替代签名权威或原日志提供的来源绑定。

新组件覆盖原始响应语义变化后的重摘要负例、令牌签名/算法、公钥、跨企业、权限/范围、撤销/会话、权威 marker 和窗口。下一版本完整新用途流程须将这些记录接入原控制/身份锁内的持久确认日志，并在新的完整真实 Keycloak 案例中消费后接受；组件协议夹具不能替代该案例，也不能替代最终整站验收。
