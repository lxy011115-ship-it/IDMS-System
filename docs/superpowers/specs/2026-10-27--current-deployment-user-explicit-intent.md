# 当前部署审查的真实用户明确请求

实现已定实施计划中“用户当前认证意图”的前置能力。由可信协调器固定原 SOURCE、新用途私密合同、当前身份权威及各企业身份读取配置。外部请求只带对应新用途/意图摘要、完整企业集合的当前访问令牌和明确请求。每份确认绑定来源、全量事实、部署和程序清单摘要、唯一确认 ID 及确认时间；禁止传入 actor、approved、路径、SQL 或验证回调。

复用生产 CurrentRecoveryActor，实际验证 RS256 签名、issuer/audience/client，并从身份服务读取当前 realm/client/user/roles/session。请求人必须具有提交权限、完整企业范围，系统管理员及已撤销会话不能代替企业用户。完整原 SOURCE 中每个企业均须有自己的明确确认；这不是独立审查人的批准。

在实际签名权威日志和当前 realm marker 的两次核对之间验证全部用户，并重新读取当前用户事实。整个原窗口为30秒，确认最多120秒，输出能力有效期取原合同、确认、令牌安全期限及30秒窗口的最小值。再次核对不延长时间，不刷新密钥，不使用旧只读用途、旧 HELD 或旧批准。对象副本/JSON 不能取得 WeakMap 能力。网络检查开始后一次性消耗该 gate，失败拒绝复用；关闭中止并等候所有原身份读取，清理本对象的私密副本。

本模块只产生短期、内存中的明确请求能力，**尚不证明持久防重放**；协调器还必须在原控制/身份锁中保存带域分隔签名的确认日志，在新凭据安装及新原会话前再次消费。没有目标 SQL、程序启动、MQTT CONNECT、独立批准、业务写入或正式启用权力；返回字段逐项保持 false。后续控制器不得只复制公开证明来授予这些权限。

组件验证使用隔离的实际 HTTP 协议夹具、真实 RSA 签名/JWKS 及真实签名 SQLite 权威链，证明本模块对当前撤销、跨企业/跨用途、摘要变化、缺少明确确认、伪造能力和关闭的处理。夹具不是 Keycloak 全量运行，不能当作完整 SOURCE/新 HELD/正式准入验收；这些必须在之后新的完整原生案例中接入并独立核验。保持所有已验收源码及案例不变。
