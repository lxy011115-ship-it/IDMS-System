# 工单产品接入 v4

继续完整方案A，把维修增量内核接到真实 OIDC/加密共享会话、最小权限 HTTP、持久命令调度、Flowable 与工单界面。旧发布根源冻结，新模块及新隔离部署，不在线变更原库。

选择独立 maintenance_jobs_v4 SQL 队列，复用已验证治理队列的不可变密文、30秒租约、独立续租线程、未知接受关闭和授权重授协议。HTTP只有QI/READER，WORKER持业务APP及固定Flowable材料。同步让HTTP拿APP会打破分权；给worker进程内临时命令会丢恢复点，因此不采用。

动作队列将维护completion的原生map receipt与SQL COMMITTED同事务发布，失败/取消不产生业务推进。命令、授权引用使用独立用途派生AES-GCM，绑定队列部署/DBOID/用户/命令/修订。Flowable入队同事务创建独立原执行者授权记录；后台每次发送前和实际应用前重新解析共享会话/令牌。原用户可为原流程重授会话；审核人重试不替换原责任身份。原授权引用不写业务map、HTTP结果或浏览器存储。

后台Flowable沿用幂等重发与本地一次应用，持久next_attempt退避最多60秒；授权失效进入等待本人重授，不消耗网络失败预算。worker SQL应用还绑定授权修订与当前deadline，旧修订不能发布。现阶段队首阻塞仍明示，未宣称全局吞吐或所有商业资源边界。

工单读取直接用v4_collection/v4_order当前完整根分页，最多48扫描/20返回，当前范围与本人任务规则先行；游标固定根、身份/权限/部署/目录和期限。详情按键读取并复核当前授权，不能选择任意根。UI提供领取/开始/结构化维修字段/提交/独立终审/退回/流程重试和本人重新授权；恢复只保存UUID及摘要，不保存维修原文或凭据，迟到回复不得跨身份落地。

验证顺序：新schema/真实PG原子与角色守卫、丢COMMIT和授权修订；真实Keycloak/共享会话、独立HTTP/WORKER/Flowable、全维修生命周期及撤权重授、断网/重载/未知接受关闭、身份切换和三宽度；旧治理/AI/审计保持，资源精确清理、原运行保值。旧未解决outbox迁移、新建预测/工单及全站迁移仍继续，不按此阶段宣称整体完成。
