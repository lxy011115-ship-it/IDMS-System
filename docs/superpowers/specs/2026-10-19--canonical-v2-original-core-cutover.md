# 原核心实际切换

延续已授权方案A，使用已通过509单元/13组集成的canonical v2与913源修订2。目标是准确替换原5356核心，维持原edge、workflow、六依赖与PG，原会话/权限/六资料/CSV/旧审计游标及源数据连续。上一阶段QA档案不替代本次原库档案。

新协调器先固定原进程出生时间、父子/命令/可执行文件、4010监听、12项保留进程和业务/auth PG客户端端口归属。未知连接即拒绝，不凭application_name认领。存在后于核心出生的未知子进程即拒绝；PID复用的更早孤儿不算当前子进程。退休请求必须先独占创建并flush，固定operation/plan SHA/原核身份和当次备份、会话、维护门事实，然后才操作已绑定出生时间的原内核句柄。OS退出、监听空闲、旧父进程和全部原app/auth后台分别确认；观察超时保留同一实际进程状态，不启动第二个核心。

先建立两原OIDC只读身份，SID/CSRF/旧加密审计游标仅留内存，再取得两原业务库PG维护门。门持有期间执行before与after原生加密档案/真实隔离恢复，核对完整facts/business、源OID和非MVCC审计序列，准确删除自己的临时目标/凭据，不FORCE、不回灌原库。档案和独立新密钥留在私密目录，公开只有范围/摘要。

冻结入口以原绝对业务、auth key、MQTT/工作流/AI配置和服务token启动，真实v2函数绑定且HTTP初始关闭。后台写入由PG门约束；接入registry必须保持相同摘要，不能在门内自动变更配置。原SID/CSRF/游标、全/限域、伪造租户403、六原件14513B的字节/MIME、资产和测量CSV、桌面/390/320界面逐项核对。全部过后先记录激活请求，再释放门/开放epoch0→1；IPC丢回复只读同一子进程状态。开放后真实注销/清理两个临时身份，观测原采集ACK及PG守恒。

失败在退休请求之前释放本门并清理临时见证，保留原核。请求之后不自动回退或重启，原核/新核实际状态、门和子进程留给继续核验。门随控制器死亡释放，仍不是持久围栏。本机v2升级不等于商用安装包、跨服务灾备或生产验收；完整目标继续。
