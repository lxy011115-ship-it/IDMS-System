# 统一审计查询与维护状态恢复 v4

在 AI 导入新入口上增加当前权限审计工作区，并修复可确定的维护结束后按钮恢复缺口。旧已归档模块和原运行站点不改。使用新模块/新前端修订；按用户已授权的待办自主实施。

## 查询与证据

统一读取同一不可变旧审计链，包括认证、资料/模板、AI、采集和其他业务事件。分页最多返回20条、扫描48条，有固定逻辑键/字节预算。服务端过滤 objectType/action/actorType/actorId/objectId/correlationId/起止UTC时间，不生成基于隐藏记录的计数或筛选建议。无匹配但仍有后页时明确允许继续，不能把一页当作全历史无结果。

加密游标固定30分钟窗口，绑定部署/数据库目录、身份/角色/范围、全部筛选、页大小、根和目录代。普通审计追加保持窗口；治理目录改变要求刷新。事件详情定位器另有用途和事件位置绑定，不允许客户端指定任意历史根或以裸UUID读取。详情/单事件JSON下载重新鉴权，核对当前和窗口权限。

沿用原 dataScope 的可见性：企业/auditor全租户；受限身份只看当前及历史都可见的对象；本人任务匹配当前及历史assignee；认证受限身份仅本人；混合范围导入整件不可分。DATA_IMPORT 用已验证的当前/历史 console coverage/counts，避免读完整行和原件；设备不存在时保持原 device-only fallback 语义。其他实体使用按键读取，不重建 TenantPayload。

每条事件校验原hash、成员证明和窗口内相邻链接；筛选、受限页及单事件下载均不宣传完整全租户链验证或第三方公证。页面显示核验范围、固定窗口时间和部分视图提示；JSON包括记录及服务器核验说明。服务端不导出隐藏邻居内容。

## HTTP 与界面

新同源GET接口、固定资源/响应/超时预算、原OIDC/session/actor-tenant防切换机制。HTTP继续QI/READER，不拿业务APP、AI key或token。界面审计页有筛选、分页、详情和单记录JSON，所有文本用textContent；epoch/ticket阻止迟到结果跨身份/筛选覆盖，不把事件、游标或导出内容持久化到浏览器存储。

稳定的 FENCED/PLANNED 维护期间可读此前完整根，所有当前权限检查仍生效。维护状态轮询在没有未完成本人作业时也继续，恢复ACTIVE后重启按钮且不清空草稿/跨身份保留数据。旧首次点击超时仍缺精确栈；只对本次重现的同类缺陷作修复声明。
