# 旧预测作业接管网页

沿用完整方案 A 和 B 的既定授权，完成现有工作台中原人接管的操作闭环。选择独立 r2 页面和新静态包装 CLI；不修改已有验收的页面、后端接管协议、SQL 或活动站点。相比单独管理页，这能复用设备任务和原有 retry/authorize 控制；相比直接改旧页面，新版本保留历史验收的精确输入，后续可由新 site 版本受控组合。

设备任务展示未绑定作业时，本人可“核对并接管原任务”；其他人只显示原人确认说明。恢复区也支持原命令及接管控制编号。确认页从后端获取当前候选，显示原人、原命令、设备、原状态、人工审核要求和潜在外部建单；用户明确提交当前授权。此前已关闭接受的命令须单独明确勾选恢复。已经绑定的任务转回设备任务，不创建新控制。

发送前持久化原控制 UUID、命令 UUID、期望 nativeHash、恢复关闭布尔值、可选动作/作业号及状态。只有这些有限元数据可进本地存储，不能存 context、SID、正文、计划、服务信封或结果；沿现有租户/actor/部署恢复命名空间。未知接受只能查询或用户明确重发同控制；轮询只 GET，不自动新 POST。未确认的同命令接管禁止新控制。被替代控制显示终态，可重新获取当前候选，但不复活原决定。

身份、CSRF、角色或范围变化继续 epoch fence/abort；所有候选、详情、结果、草稿视图清空，旧响应不回填。候选刷新采用独立 ticket。恢复 GET 与明确重发都核回执控制、原命令及作业号，完成显示必须来自已核原生证明的后端。接收状态与业务完成文案分开；HUMAN 继续由异人独立 retry、原人新 grant，使用已有控制接口，不能自动复活。潜在外部已创建时保留原计划；外部创建不明且原生已取消仍展示需要人工对账的拒绝，不造取消成功。

复用现有字体、颜色、表格/卡片和窄屏单列控件，所有摘要、UUID、错误文案可换行。真实独立 PKCE/共享会话/旧 SDK 根/新 schema/规则/Flowable 验证本人接管、丢接受回复重载、原控制重发、跨身份迟到、当前范围撤销、HUMAN 与关闭恢复、390/320和错误观察。使用独立 QA journal/realm/进程/标签，精确清理。没有浏览器证据不得称 UI 通过；原系统、C outbox、整站切换与商业验收不在本 UI 阶段偷换为完成。
