# 工作流安全维护与可验证迁移设计

日期：2026-11-05。状态：待用户评审；仅完成隔离探测，尚未修改产品代码、迁移企业数据库或切换运行服务。

## 要解决的问题

实际运行工作流JAR仍使用Boot 3.5.7、Spring 6.2.12、Flowable 7.2.0及Jackson 2.19.2。此前重点公告复核尚不足以完成企业安全交付。当前增量读写架构设计的批准状态与本设计分开，不把自动继续目标当作两者批准。

本设计只负责工作流安全维护，覆盖现有普通业务、恢复读取、撤销协调及撤销预留接口。整体优化中的遥测、企业UAT、生产拓扑、统一恢复集、运维制度和D盘迁移仍需分别完成。

## 本轮已取得的事实

1. 实际JAR的90个嵌套依赖全部纳入坐标筛查。69个库含Maven元数据；其余21个库用Maven Central HTTPS发布的摘要匹配实际嵌套JAR字节后确认坐标。包含多个内嵌坐标的库按实际元数据全部查询，共97个坐标版本查询，命中14个坐标、63个去重公告ID。命中是索引版本匹配，不是可利用性或63项独立攻击路径。
2. OSV本次未返回已经由维护者公告确认的`GHSA-m8xf-2cr7-77ph`。后续必须合并维护者公告和索引筛查，不能以索引零命中代替验收。[OSV查询接口](https://google.github.io/osv.dev/post-v1-querybatch/)
3. Spring公告列出的6.2.20修复为商业支持；开源修复发布线包含7.0.9及以后版本，6.2.19仍在受影响区间。[Spring公告](https://spring.io/security/cve-2026-59283/)
4. 在独立源码副本中只替换Boot为4.1.2、Flowable为8.0.0，保留所有Java及资源字节。有效POM实际解析为Spring 7.0.10、Tomcat 11.0.27、pgJDBC 42.7.14、Commons Lang 3.20.0、Logback 1.5.38、Log4j API 2.25.5；这仍不是已经通过业务测试的修复包。
5. 上述默认POM同时管理Jackson 2.21.7和3.1.7，仍在维护者公告受影响范围。必须分别核对和锁定修复版本，不能只升Boot。[Jackson公告](https://github.com/FasterXML/jackson-databind/security/advisories/GHSA-m8xf-2cr7-77ph)
6. 21组合成跨语言摘要向量，在实际原JAR中的Jackson 2.19.2与来源/摘要核验后的2.21.8下，均与Node产生相同规范字节和SHA-256。覆盖中文、控制字符、Unicode、嵌套回执、空值及有限数字样例；没有执行实际Controller、HTTP、BPMN或数据库，不能扩大为所有输入或Jackson 3兼容。
7. Flowable 8官方说明要求Spring 7/Boot 4，默认使用Jackson 3并保留Jackson 2过渡层。[Flowable发布说明](https://github.com/flowable/flowable-engine/releases/tag/flowable-8.0.0)。其PostgreSQL升级SQL除调整版本标记，还为历史流程实例增加`END_USER_ID_`及`STATE_`两列。因此需要显式迁移与回退，不能仅更换JAR。[历史表升级SQL](https://github.com/flowable/flowable-engine/blob/flowable-8.0.0/modules/flowable-engine/src/main/resources/org/flowable/db/upgrade/flowable.postgres.upgradestep.7202.to.8000.history.sql)
8. 拟选的16个重点修复坐标在本次OSV预查询中零命中；它们尚未组成或验证最终运行包，且索引缺项已实证，不能据此关闭安全项。
9. 隔离Maven实际完成依赖解析、依赖树和6份原Java源码的编译尝试，编译退出码为1：Boot旧自动配置包及`com.fasterxml.jackson`旧类型不可解析。前一次因TLS失败尚未进入编译的记录另外保留；后续通过正常上游TLS及发布摘要校验的回环下载通道完成1162项请求，传输错误0。后一次失败是源码兼容问题，不能算候选通过。实际树使用Jackson 3.1.7，不包含Jackson 2 Databind；POM管理的Jackson 2版本不等于已打包的库。自有Maven和下载通道均已终止，原10服务、原JAR和源码保持。
10. 新依赖树没有单独列出OGNL，但实际MyBatis 3.5.19字节与原包完全相同，其内嵌元数据仍包含OGNL 3.4.4。不能由树中没有独立节点推断已修复，也不能只添加独立OGNL新依赖去覆盖重定位后的旧代码。后续必须复核实际嵌套/重定位内容并处理承载包。

## 路线比较

| 路线 | 做法 | 代价和边界 |
| --- | --- | --- |
| A：开源维护线与Jackson 3迁移，推荐 | Boot 4.1.2、Flowable 8，应用使用Jackson 3；保留现有业务契约和摘要规则，显式迁移数据库 | 同时验证API、解析差异、历史数据及引擎升级；得到可持续维护的开源路线 |
| B：Jackson 2过渡 | Boot 4/Flowable 8，应用暂用官方Jackson 2过渡支持，两套Jackson都修补 | 过渡模块已弃用，仍需要后续迁移；不作为最终维护目标。[Boot说明](https://docs.spring.io/spring-boot/reference/features/json.html) |
| C：商业支持旧框架线 | 购买并验证Spring商业补丁，保留Flowable 7.2；其他依赖独立修补 | 需要真实许可及支持承诺，不能假设已购买，也不能用公开旧版本冒充商业补丁 |

## 推荐A的组件边界

### 构建和依赖

在独立代码目录实现，全部源码、POM、插件、依赖树及打包JAR留摘要。保留原JAR和运行绑定，不在在线`services/workflow/target`构建。使用稳定发布版，不取RC或浮动版本。基础候选为Boot 4.1.2、Flowable 8.0.0；Jackson 3至少3.1.8，若最终依赖树仍包含Jackson 2则至少2.21.8；若包含OGNL则至少3.4.13，不为版本检查额外引入未使用的库。后续发现的新公告必须纳入最终包复核，不能将这里的下限当作永久安全承诺。[OGNL维护者公告](https://github.com/orphan-oss/ognl/security/advisories/GHSA-crwc-vw2r-qr6m)

兼容调整包括Boot模块/自动配置包变化、Jackson类型与方法变化、实际版本报告。服务状态不得继续硬编码7.2.0。不得通过删掉恢复/撤销功能、排除实际使用的库或忽略编译失败取得通过。

MyBatis等承载包的嵌套/重定位依赖也进入验收。采用实际包含修复代码的正式承载包，保存其源码/发布说明、嵌套坐标和字节证据，并验证Flowable的SQL、事务、表达式和恢复行为；没有证据时保持该项未关闭。独立依赖覆盖及仅查询顶层MyBatis坐标均不能替代这项检查。

### 业务和JSON契约

保留现有命令字段、企业身份头、独立终审、权限、版本竞争及事务边界。命令回执与引擎变更继续同事务提交。原命令ID与摘要的重试返回原回执；原键异内容必须拒绝。

原始签名、命令摘要、历史回执及流程定义字节不重签、不批量重写。Jackson迁移要以Node请求摘要、旧Java结果、新Java结果三方比较为依据。新旧解析差异必须显式处理，不能为接受异常输入而放宽字段/类型校验。原始BPMN仍保持版本1及同一资源摘要；引擎升级不触发重新部署流程定义。

### 数据迁移与回退

先在含非空工单、在途任务、原键回执、撤销协调及预留记录的合成双企业库实施。完整保存升级前事实、引擎历史、角色权限及数据库档案。迁移步骤独立、版本化并受维护身份限制；普通启动保留校验模式和`databaseSchemaUpdate=false`，不自动初始化或升级。

先验证同版原状态还原，再显式升级结构、启动候选并完成原流程。回退使用升级前档案和原JAR，必须实际运行旧流程核验。升级后的新业务不自动合并进旧分支；如最终切换有新写入，须另有明确恢复点和业务处置规则。

### 运行和诊断

只使用自有隔离端口、配置和新生命周期控制器，不接管原Java PID或放宽身份门禁。每个子进程派发后立即注册终态监听，保存真实退出码；观察超时继续观察同一进程，不重复启动。正常停止须证明引擎/连接池关闭、进程终态及端口释放，不能用Windows强制结束冒充。

当前主机WSL、Hyper-V及Sandbox可选功能均未启用；本设计不包含启用全局功能或重启电脑。隔离工作流验证不等于保留完整原平台端口和身份绑定的跨服务恢复。

## 验收要求

1. 独立构建实际成功；逐库依赖清单、来源和摘要与运行包对应。筛查覆盖全部打包依赖，逐项核对维护者公告及实际触发配置；记录未关闭项、责任和结论，不把npm检查或OSV零命中当全平台安全通过。
2. 双企业覆盖创建、认领、开始维修、提交、退回、重新提交、独立终审；错误企业/身份/角色、同人终审、陈旧版本、错误证据摘要全部拒绝。
3. 业务命令及撤销协调/预留均验证原键重试、原键异摘要、并发竞争、保存失败回滚和恢复后重放。外部效果次数、回执及数据库事实一起核对，不只看健康接口。
4. 全部9个现有HTTP路由均验证。恢复读取保持专用身份、只读和重复身份头拒绝；不能降级成普通服务令牌可读或开放管理接口。
5. Jackson 3对现有合成21向量及实际协议新增边界向量，与旧Java和Node摘要逐字比对；同时验证HTTP消息转换器、固定record字段、未知/缺失字段、错误类型、Unicode、数字边界及持久回执重读。任何允许输入的摘要变化均阻止迁移放行。
6. 升级前、升级后及旧版本回退各自实际恢复非空数据，核对全表事实、任务/历史、命令回执、定义摘要和权限边界。旧版普通启动必须拒绝不兼容结构，新版不得隐式迁移。
7. 所有自有实例正常停止；当前原10服务身份、原JAR和485项运行源码摘要保持。完整平台切换仍需合格配对恢复集、原服务正常收尾和受控绑定验证。

本设计只请求后续独立实现与验证路线的选择；不把路线批准等同于生产换版、企业签收、商业采购或公网放行。此前采集恢复B已执行，不重复申请或运行。
