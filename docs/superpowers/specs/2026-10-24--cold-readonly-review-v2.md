# 整库冷恢复的受控只读审核阶段

沿用完整 R4 源捕获、已登记角色、维护 CLOSED 回执、实际 JWT/租约期限、独立当前身份权威和完整加密 PGDATA 归档。新增显式 V2 trust/source，不让 V1 准入解释新状态。原 source installer 的真实对象在维护 CLOSED、原角色属性仍完整时重新捕获只读契约；不能接受调用方伪造摘要。

归档与刚恢复目标保持所有角色 NOLOGIN/0、所有业务数据库连接上限0。source reader 的 HBA/角色/定义契约随 source body/hash 保存，但源密码不能因此在恢复后得到可用窗口。

新只读准备操作使用原恢复 UUID。先持久化不含密码的意图和私密凭据文件摘要；私密文件预先生成 reader 密码、SCRAM verifier 和 HTTP token。认证完整原归档、源真实离线、当前独立权威、目标真实 system/OID/目录、原 fence/结构与 HBA。完整 catalog 逐库在实际 bootstrap 事务中暂存原属性并核对，然后整笔 ROLLBACK；不把未提交属性当成其他连接可见。

最后一个 SQL 事务仅轮换专用 reader 凭据并提交到选择性只读 profile，所有业务角色仍封闭、原业务 fence CLOSED。最终成功前后重验实际材料和当前权威。该阶段不授予正式人审、业务准入、现场租约或注册激活。

提交结果不明时必须关闭原 SQL socket，并由新连接证明原实际后台事务终态，才能按完整角色/数据库 profile 与预先固定的 verifier 判定提交是否发生。私密、认证的原后台 witness 只作终态证据，不接管 PID、不终止外来会话。已提交补原结果，未提交才以同意图重试；冲突保持拒绝，不自动另造凭据或新业务操作。

先在完整真实 R4 数据源验证全封闭归档/物理恢复、源旧密码失效、只读真实 Flowable、同操作重入和拒绝漂移。当前根维护 profile、实际 owned reader 连接能力、真实作者/独立审核与最终激活仍需组合完成，完整目标不缩小。
