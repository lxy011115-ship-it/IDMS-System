# 备件事务一致性与取消处理

更新：2026-10-30。用户已批准备件容量设计，本阶段已实现并更新本地运行。仍保留生产门禁，完整审计分段证明、档案锚和企业岗位签收继续在总计划中验收。

## 当前读写路径

主站备件写入和操作历史不再通过旧工作区读取后额外借一条库存连接。命令、分页读取和历史查询均使用统一的事务/资源入口；当前用户和范围仍由原认证链路派生，不从请求体接受角色或权限。

写入使用可重复读事务，固定按“原业务状态共享锁→备件状态写锁”顺序执行，防止当前批准设备/工单事实与备件提交分离。只对输入及至多256个实体引用闭包涉及的设备、工单标识查询，当前公共引用最多512个标识；设备用最新已批准修订，工单用规范记录，并重新检查当前范围。没有下载企业全部设备或工单作为权限下拉框。

当前范围、关联资料、全链审计、库存及票款聚合、领域规则、真实实体变化、事件和幂等回执均在同一连接快照内完成。重读旧幂等回执前也校验当前范围和完整审计，设备撤出范围后不能借原请求读取该回执。

只有提交尚未尝试、ROLLBACK已明确确认且属于序列化/死锁冲突时，才以相同请求及幂等键完整重试一次；重新查询原业务事实。其他失败不自动重试业务。COMMIT已尝试而确认丢失时返回503“结果尚未确认”，由原键核对，不能把连接错误当作“保存失败”后另建。

操作历史在同一只读快照内核对原业务证明、当前设备/工单可见性和完整审计链，SQL计算每条历史涉及记录是否仍在当前范围。隐藏事件仍参与链校验；应用只保留本页必要摘要。事件正文和当前公共档案仍可能需要数据库线性扫描，本阶段未启用分段缓存。

旧根 `/spares` 全量接口仅为显式兼容入口，保留原容量拒绝；现有主站不调用它。直接提供引用数组的领域对照适配器保留给隔离验证，HTTP写入和历史使用当前数据库引用路径。

## 取消、超时与连接归还

所有上述入口纳入现有SQL公平调度和任务内存计量。当前本地企业池最多4连接，连接获取等待3秒；单事务锁等待2秒、单条语句15秒、空闲事务20秒，总事务保护30秒。队列等待沿用现有容量策略。这些是当前配置，不是生产SLA。

取消正在执行的SQL时，使用借出连接自己的后端标识及临时密钥发送PostgreSQL CancelRequest。它使用一个短控制通道，不额外借数据库连接、不创建数据库登录、不调用管理员取消其他会话的SQL；密钥不记录或落盘。发送取消不等于取消成功，必须等待原查询结果、执行回滚，再废弃该连接。

如果控制通道不可用，继续等待有界SQL结果，不提前把后台工作算作已停止。请求在COMMIT开始后取消，仍核对提交结果；提交确认成功不报告为回滚，未确认则保留原键核对语义。异常或取消连接不放回池中供其他请求复用，避免迟到取消干扰后续业务。

通信完全中断或总保护触发时，按错误/未知提交处理，不能宣称已确认远端停止。当前专项没有模拟全部生产网络故障，正式部署仍需结合实际网络与监控验收。

最初隔离测试发现，单纯关闭应用端套接字后，数据库的长查询可能继续运行；该实现已替换。失败尝试使用的确切QA库在确认无连接和合成标记后正常删除，没有强制终止企业会话。

事件行和历史摘要有显式内存持有/释放计量。完成、拒绝、取消、超时和回滚后归还相应资源；不会累计保留已丢弃的历史页。备份仍保留完整事件原文，后续档案与跨服务恢复单独验收。
