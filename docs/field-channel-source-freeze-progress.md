# 现场恢复：源业务持久停写

新增 freeze-source 部署命令，落实正式归档前的企业业务停写。当前阶段通过真实 PostgreSQL、实际 CLI、6 种进程中断、连接认证失败及同源目标拒绝验证。485 项核心单元测试、212 项构建/语法与类型检查通过。此项仍属于现场通道第 6 项进展，原 4010 未部署或重启。

## 冻结行为

工具要求已有同一 RESTORE 操作的 RESTORING 正文和标记，先核对源数据库、集群、宿主、角色 OID、完整根、保护审计及编译权限。冻结意图先原子持久化，再排空精确识别的应用/迁移会话；按 PID、backend_start、角色和数据库核对，等待真实数据库终态。未知会话或其他普通身份不擅自终止。

取得全部既知业务表的锁后，工具在同一事务中把应用及迁移角色变为 NOLOGIN、撤销迁移角色的 owner 成员关系、把应用对 public/idms_field 的表权限收为 SELECT，并撤销其序列和业务 schema 函数权限，同时写入唯一冻结确认保护审计。只读备份权限保持。仅确认该事务真正提交后才报告 sourceFrozen。

提交前失败可能仍停在 REQUESTED，不能据此开始正式归档；已经提交的冻结不会被失败或重试重新开放。提交响应丢失时，原操作核对实际角色、权限和审计恢复，不重复根修订。完成后保留 RESTORING 及待完成标记，没有自动恢复 ACTIVE 或重新开放源写入的命令。

此范围是当前企业数据库的普通应用与迁移路径。外部已发出的流程/AI请求不会因此回滚，也不代表跨服务停机或灾备完成。部署超级管理员仍属于受信边界。

## 目标必须先规划

冻结前必须提供目标运行配置，与 begin 时的目标摘要一致；目标使用新数据库和新 app/owner/backup 名称，不复用源角色。目标库及这三个角色在受控集群尚不存在，源与目标的基础模块标志必须一致。非秘密目标绑定保存在冻结意图中。这里只准备配置，不提前创建目标库或角色。

当前工具核验同一 host/port 对应的受控集群；远端 authority、Linux 写后端及跨宿主移交仍待独立实现，不声称已验收。后续实际创建目标时仍需再次核对归档及创建所有权，不能仅凭早先检查覆盖后来出现的对象。

在原恢复控制命令基础上，使用私密配置与原操作编号：

```powershell
node scripts/field-recovery.mjs --action begin --authority-config <部署配置> --runtime-config <源运行配置> --tenant acme --control-file <控制文件> --expected-control-digest <当前摘要> --target-runtime-config <新目标运行配置>
node scripts/field-recovery.mjs --action freeze-source --authority-config <部署配置> --runtime-config <源运行配置> --migration-config <源迁移身份配置> --tenant acme --control-file <同一控制文件> --operation-id <原操作UUID> --target-runtime-config <同一目标配置>
node scripts/field-recovery.mjs --action resume --authority-config <部署配置> --runtime-config <源运行配置> --migration-config <源迁移身份配置> --tenant acme --control-file <同一控制文件> --operation-id <原操作UUID>
```

已有冻结意图的 resume 需要源 migration 身份配置；缺少时明确拒绝，不改用普通应用登录或重新开放权限。只读 status 仍只报告文件状态，不能代替实时冻结核验。

## 冻结后的核验

冻结操作使用部署 authority。为复用不可修改的基础和现场验证器，独占验证连接在未提交事务的 savepoint 内临时投影原编译权限，再降为应用身份执行校验，随后回滚投影；验证事务不提交。没有向投影开放任意调用方回调。另一个真实会话已验证：投影期间仍无法更新业务表、推进序列，迁移身份也无法 SET ROLE owner。回滚后严格只读状态保持。

6 种进程中断覆盖意图发布后、请求审计提交后、实际冻结 COMMIT 前后、提交响应丢失和结果发布后。重试前确认旧进程及每个已记录 PG 后端真实终态；已提交的根不被重试改写。另验证真实认证失败时已连接和未使用的连接均能结束，以及错 OID、损坏结果、未知会话/登录授权和额外现场写权限被拒绝。

源业务及导入保全检查通过；本组冻结数据中的现场表为空，不能把它当作非空现场数据的完整归档/恢复验收。冻结后的完整事实扫描已经通过，实际非空现场数据、dump、加密、恢复和重新批准还须联合验证。

原企业真实应用登录、基础权限、owner/backup/migrator 状态及迁移成员关系另行只读核验通过，原库无现场 schema。原 Acme 根、业务/导入和迁移保持；Sandbox 既有演示采集继续运行，其根记录不被误称静态。66 份完整文件契约和十轮双份每份 1571 文件冻结 SHA 保持，无第 11 份最终快照或私密配置/密钥/数据库备份交付。
