# 隔离恢复清理 R5 阶段记录

已修复 R4 记录的失败路径缺陷：清理观察器抛出异常时，管理连接关闭可能被跳过。新 R5 把操作、资源清理和连接关闭按顺序执行，保留所有失败原因；清理未完成时保留恢复凭据。所有变更均在独立新文件，当前活动 R4 和原运行站点保持不变。

最终真实验证为 `10309bffcf78`。在一次性合成 QA 源库上取得实际维护门、执行实际 pg_dump/pg_restore，并在恢复后加入本轮自有的外来管理连接，使原生观察器拒绝。捕获和对账函数返回失败后，实际 pg_stat_activity 确认 R5 管理连接均已消失；外来连接仍可 SELECT，目标与凭据保留。业务主动失败与清理拒绝同时发生时，两个实际错误按原顺序保留。

对已恢复的 QA 目标新增一张测试表会使完整事实核验失败，内外层连接均关闭，凭据保留；移除该表后完整档案认证、事实、业务及固定 OID 核验通过，再精确清理。成功路径另完成一次实际隔离还原和非 MVCC 审计序列核验。整个源库的全部事实和业务内容前后相同，真实维护门一直保持。

最终一轮的 4 个数据库、7 个角色均记录 OID 并按名称/OID 复核不存在。三轮累计已登记的 9 个数据库和 18 个角色均不存在；首轮成功目标未在夹具 journal 留存名称/OID，因此另外只读检查整个生成恢复目标命名空间，库/角色均为零。没有强制删除或终止未知连接。

首轮 `874de0d7f929` 验证较早源通过。第二轮 `d8cdd2967d9b` 暴露 R5 新增对账 afterClose 在业务失败后也删除凭据的问题；失败记录保留。修正为必须确认实际目标删除后才移除凭据。该失败轮遗留的一个测试目标使用保留加密档案、完整事实/业务、固定库与角色 OID 及实际零连接核验后，独立精确回收。该记录不当作最终源通过证明。
