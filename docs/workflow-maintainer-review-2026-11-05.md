# 工作流维护者公告复核与连接防护

2026-11-05。本轮沿用已批准的开源迁移路线，在独立候选上补充维护者公告核对、数据库连接防护和日志库修复。原运行服务没有换版，完整平台上线门禁保持。

## 本轮改变

三类数据库连接池统一使用WorkflowDataSources：只接受固定回环地址、有效端口和数据库名，不接受附加驱动参数；登录等待10秒、建连5秒。按pgJDBC的Windows/Unix默认位置，在建立连接前拒绝空、过大、链接和非普通证书/密钥文件，并限制读取量为1MiB。没有关闭SSL，也没有替换驱动的证书校验方式。

Logback从1.5.38显式锁定到1.6.6，保留Boot 4.1.2、Flowable 8、Jackson 3.1.8、MyBatis 3.6.0及原BPMN。相比上轮，98个嵌套库中的96个保持相同字节，两个Logback库更新。实际JAR内也已包含适配源码的NOTICE和Apache 2许可证。

最终JAR 33869430字节，SHA-256 1ef22eca3d2005d43cb6a1ebf37d22518d1a90b4de0a85d6d93d50bb6df8e214。构建实际exit0；Windows共19项测试，18通过、1项Linux设备/FIFO/链接检查按平台跳过。Linux同提交CI随后独立记录，不能将本机跳过项算作本机通过。

## 为什么不能只看索引

105组实际坐标的OSV查询全部成功且零命中，但[pgJDBC维护者公告](https://github.com/pgjdbc/pgjdbc/security/advisories/GHSA-hcjv-f5jh-r55v)仍明确列出42.7.14及以下版本的证书读取资源消耗问题，尚无补丁。它依赖客户端证书路径受影响，本轮采用受限配置和有限等待等防护；不宣称上游缺陷已修复。

[Logback稳定版说明](https://github.com/qos-ch/logback/releases/tag/v_1.6.6)及[维护者新闻](https://logback.qos.ch/news.html)还记录了旧线之后的MDC及反序列化防护。用与实际打包库相同的旧、新字节分别运行无Appender探针：旧版返回路径样式MDC值，新版返回默认值。没有实际进行越界文件写入；本应用当前也未配置该Appender。这是验证维护修复，不能冒充发现了线上文件越界。

## 实际运行验证

五个独立JVM负例中，URL参数和空/目录/大证书配置均在任何数据库TCP连接前拒绝；真实驱动面对只接受启动包而不返回认证的自有测试服务器，在约13秒内自然退出，没有到达测试的25秒保护截止。早一次验证错误期待原始驱动错误正文，而应用本来就隐藏该正文；失败记录保留，后续按真实握手、耗时、终态及安全分类验收。

使用正常停止的非空升级分支，两个企业六个连接池实际启动，全部九类路由与原/新命令回执完成重放，357张用户表事实不变。没有重复执行已经通过的迁移、备份回退或维修写入矩阵。新测试JVM正常关闭Web、引擎和连接池，PG正常smart停止，原10服务身份、原JAR及485项运行源码保持。

## 继续保留的门禁

当前防护只覆盖已有本机回环数据库配置。客户端目录必须由可信运维控制；文件替换竞态、异常阻塞文件系统与未来生产TLS配置仍需部署约束。不会把默认SSL协商当作生产verify-full，也不执行远端TLS或原平台换版。无补丁项的企业责任人及生产接受结论仍待指定。

本报告不是完整代码渗透测试、企业多角色签收或主站/身份/AI/边缘/撤销的一致恢复验收。主站和原Java依赖没有因候选源码改动自动升级。完整优化目标继续，后续从生产配置、跨组件恢复及其他七类未完成项推进。
