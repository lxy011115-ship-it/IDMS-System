日期：2026-10-29。对象：当前 `D:\IDMS-System` 及本地4010主站。结论：具备受控路演和企业试点的基础，尚不宜直接承诺为已验收的企业生产系统。优先完成发布与操作可靠性，再提升业务表达和界面，最后用试点数据验证差异化能力。本报告保留优化前检查基线；本轮已完成的首批改动见第8节。

## 3. 路演界面应如何美化

### 3.1 首屏先回答四个问题

“今天要处理什么、风险在哪里、下一步做什么、数据从哪里来”。保留现有深蓝侧栏、青绿主色和六大菜单，将工作台排成：紧凑页面标题和企业/岗位信息 → 待办/风险指标 → 今日任务清单 → 数据来源与更新时间 → 次要分析。

当前工作台主要是产量、良品率、停机和数据覆盖，备件待办只是汇总文字。建议以“我的待办、待独立审批、缺料项、逾期采购”作为明确可进入的入口，不能把操作者不可审批的单据显示为可审批动作。管理看风险，维修看本人任务，仓库看收发和缺料；先按当前权限生成内容，不增加越权切换身份。

### 3.2 统一视觉与交互

| 内容 | 当前表现 | 优化设计 |
| --- | --- | --- |
| 导航 | 六个主入口已简化，但文字字符图标和较大纵向间隔影响精致感 | 统一线性SVG图标、44–48px点击区域、清晰选中态；保留六大结构 |
| 字号 | 表格13px、次级信息12px，投屏时仍偏小 | 正文14–16px，关键数量24–30px，投屏表格14px；增加舒适密度选项而非全局放大溢出 |
| 主操作 | 一行常出现多种同权重按钮 | 每页突出一个主要任务，辅助动作弱化；危险/独立审批动作保留明确语义 |
| 采购详情 | 状态、金额和多张表纵向堆叠 | 顶部单号、状态步骤、供应商与交期，中部数量/金额摘要，下部明细和收货历史；从原单发起收退料 |
| 空状态 | 备件页“暂无记录，请先建立基础档案”没有区分岗位 | 管理员给建供应商/仓库/备件步骤；申请人提示联系备件管理员，不能显示自己无权执行的操作 |
| 可信度 | 真实输入、历史样本和预置预测场景在同一工作区出现 | 每个指标就近显示“批准上传/模拟采集/预置场景”、窗口和截止时间；演示与真实数据分区 |
| 数据新鲜度 | 工作台固定绿色圆点配历史截止时间 | 无时效规则显示“未配置时效标准”；按明确规则判断时效，不能用绿色暗示设备在线 |
| 表单 | 多字段及技术说明首屏密集 | 必填优先、可选信息渐进展开；错误定位到字段；成功、刷新失败、未知提交分别呈现 |
| 路演呈现 | 默认入口偏上传操作，难以说明业务价值 | 固定讲解路线：工作台风险 → 设备档案 → 工单用料 → 采购收货 → 实际更换与追溯；使用隔离演示资料 |

不要为了美观移除样本/开发标记，或添加随机波动的趋势图。没有统计窗口、样本或成本口径时保留“未评估”；不能把工程规则分数包装为经过现场标定的预测准确率。

### 3.3 路演准备

建议8分钟主线：1分钟说明目标岗位和流程；2分钟设备与问题证据；3分钟工单、缺料和采购库存；1分钟实际更换与审计；1分钟试点范围和验收方式。该时长是讲解编排，不是系统性能承诺。

路演资料应包括一套隔离企业的完整但明确标注的合成案例、分别登录的演示岗位、一页系统边界、流程图和故障时备用截图。需要真正录制操作视频时再采集同版系统，不使用静态截图动画冒充操作。

## 5. IDMS可形成的差异化方向

以下是建议验证的产品方向，不声称是市场独有发明或已完成的新功能。

1. **维修问题到缺料影响的一条业务链。** 在一张设备卡中看到告警依据、当前工单、适用备件、现存量、在途采购及下一步责任人。先做可追踪的关系展示；库存预留和补货建议需补数量模型，不能直接自动下单。
2. **有依据的补货建议。** 使用安全库存、已批准采购未收量、实际领退料和交货期解释建议；若未来加入预留，清楚区分现存和可用。数据不足只提示缺料，不生成伪精确消耗预测。
3. **实际更换验证周期。** 利用已分开的领用与实际安装记录，逐步统计同设备位置的实际更换间隔与异常早换。将供应商、批次和故障原因用于后续质量分析；批次追踪必须先补数据采集，不能从旧流水推造。
4. **数据可信度作为产品能力。** 每项指标能打开批准来源、记录窗口及缺失条件；AI给出关联证据与待确认项，最终审批仍由独立人员完成。把已有审计优势变成普通用户能理解的追溯入口。
5. **轻量试点交付。** 使用设备/备件编码和CSV迁移模板，从小范围岗位闭环开始，再接只读设备数据及ERP。以企业自身的缺料次数、处理时长和资料完整率比较试点前后变化，不预设降本百分比。
