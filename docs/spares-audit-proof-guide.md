# 备件审计复用与历史翻页说明

更新：2026-10-30。依据已批准备件容量设计实施；本页记录本地阶段，不能作为生产验收结论。

## 使用变化

操作历史继续支持采购关联、日期、动作和关键词筛选。查看更早记录时，页面令牌绑定当前企业、使用者、岗位、授权范围、筛选条件、每页条数和两个业务版本。如果业务资料或范围变化，系统拒绝混合新旧页，提示从最新一页重新查询；点击“重新读取”即可。重启服务后旧令牌失效。前端不解析令牌。

当前HTTP历史接口的`before`为服务端返回的不透明签名令牌，不再接受自行填写的数字序号。显式旧引用适配器仅用于兼容及完整参考验证，主站不调用它。关键词仅匹配公开业务摘要，不能通过供应商联系电话等未展示字段探测记录。

## 完整性与资源边界

每256个事件为一段。每次请求均在同一RR事务内扫描该企业的全部段元数据，核对从1开始的序号、数量、连续范围及最终业务版本。按数字序号排序的指纹含sequence、tableoid、xmin、ctid；发生变化或没有缓存的段会重新读取正文，核对原始哈希及前后段连接。隐藏工厂的事件同样参与完整性核验，可见范围在当前请求另行判断。

复用证明绑定连接端点、服务器启动时刻及地址端口、数据库OID、数据库用户、事务ID代际、事件表OID/物理文件/目录行版本等。读取物理代际前持有事件表ACCESS SHARE锁，允许正常追加，阻止核验期间重写。最多1024份驻留证明，4MiB总缓存预算、单项2048估算字节、60秒闲置逐出；单事务待发布证明也至多1024项，并单独计入任务内存。只有全链验证成功且COMMIT确认后才发布证明；回滚、取消或提交确认丢失均不发布。缓存没有事件正文，不落地可信JSON检查点。

元数据每批最多16段，变化段正文使用原生逐行流；历史候选按数字序号倒序、每批最多32行，摘要最多保留每页条数加1（每页上限100）。历史核验与可见摘要查询分离，不为了翻页重新传输所有正文。维护/旧兼容/备份核验没有证明事务作用域时保留完整正文流式核验。

列表先在SQL中选出至多101条基础记录，再按UUID索引查询关联名称。隔离验证曾暴露分页前关联表扫描放大导致15秒超时；修复没有提高超时、提高记录门槛或提前ANALYZE来掩盖问题。

这些证明用于短期复用，不是外部数字签名或管理员不可篡改凭证。数据库仍需线性扫描全部段元数据；大量筛选未命中时仍会遍历候选摘要。不能据此声称恒定查询成本、无限容量或生产SLA。系统列的短期性质见[PostgreSQL 16系统列](https://www.postgresql.org/docs/16/ddl-system-columns.html)，锁语义见[LOCK官方文档](https://www.postgresql.org/docs/16/sql-lock.html)。
