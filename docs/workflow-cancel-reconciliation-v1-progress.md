# 取消建单人工对账：流程服务边界已隔离验证

新增显式启用的 Java 控制器、持久阻断/决定 SQL 协议、目录见证、受品牌保护的 Node 传输和独立离线构建/验证入口。旧流程控制器、旧 target jar、原运行服务及 r3 的 62 个已验证输入源保持。未在原数据库部署此协议，也未切换云端。

最终同源验证有 17 组实际 Flowable/PG 检查、14 个输入源固定摘要，两个租户使用独立数据库及独立 ProcessEngine。未配置时路由关闭；启用后实际验证已创建原回执、未创建持久阻断、原请求及任一编号替换的迟到创建回滚、同控制幂等/冲突、调用期间修改信封隔离、跨租户同 UUID、认证与畸形输入、最小数据库权限及不可变账本。

两种并发顺序通过实际 PG advisory lock 等待队列证明：原创建先获得锁则保留实际原创建，阻断先获得锁则完整回滚后来的 Flowable、case、command。没有以模拟响应代替真实引擎。实际禁用触发器及可跳过阻断插入的 INSERT 重写规则均被目录见证拒绝，未产生虚假决定。错误版本、缺字段及错误任务的持久回执被拒绝；实际后续领取工单不改变原创建回执。
