# CSV分批导出与下载

后续[冷读取分段证明](cold-proof-guide.md)使首次/失效的完整来源证明也不再构造完整原件/审计/回执；CSV双遍/块核对语义和默认期限保持，输入事实/服务器排序/CPU边界仍在。

PG平台数据中心的设备档案和测点记录CSV，使用同一个经完整来源证明的REPEATABLE READ READ ONLY快照内双遍服务端游标。生产HTTP路径取消原10000行上限；文件Demo和显式返回完整数组的兼容适配仍保留该保护。上传文件/JSON的原限制保持，导出并不提高导入容量。

## 使用

页面点击“按已应用条件导出 CSV”。仅导出最近一次成功查询的筛选结果；表单尚未查询或查询失败的修改不影响导出条件。OIDC页面使用同源Cookie、单个可复用隐藏iframe交给浏览器下载，不构造完整Blob。下载失败时查看浏览器下载记录；服务端在发送前返回的JSON错误会显示在页面，身份过期后刷新登录状态。隐藏iframe最长12分钟后清理，退出同时清理。

接口保持：`GET /api/v1/data-management/assets/export`及`GET /api/v1/data-management/measurements/export`，沿用原read权限、经验证的企业/工厂/产线/设备范围和当前批准版本。禁止分页参数、未知/重复参数；空结果为BOM和表头。Bearer客户端可直接请求API。文件保留UTF-8 BOM、CRLF、CSV引号、文本公式转义及原血缘/测点定义列，不能作为上传模板直接回传。

## 一致性及资源

1. 取得导出队列、SQL槽位和任务预算，在只读RR快照内完成原MVCC完整来源/投影证明。证明不能只看revision；冷读仍可能完整重建全部来源。
2. 第一遍游标每次FETCH最多128行，逐行核对企业和当前资产范围绑定，以固定64KiB字节块编码；只保存全文件摘要/长度/授权行数及每块SHA-256清单。超字节限制在CSV响应之前拒绝。
3. 第二遍使用相同SQL和同一快照，输出块先匹配清单；每次等待HTTP写回调后再继续取数，保留末块。全文件行数/字节/SHA和清单完全一致、COMMIT成功、连接与SQL/task槽归还后，才从固定HTTP窗口发送末块并结束。
4. `Content-Length`、`X-Export-Rows`和`X-Export-Sha256`给出完整结果；`Cache-Control:no-store`、`X-Content-Type-Options:nosniff`保持。响应前错误为JSON，响应后错误直接关闭连接，不发送末块；已传输前缀核对通过，整个文件因长度不足而不能正常完成。

不创建导出暂存文件。应用编码暂存按5×64KiB预留、每批保留行对象的估算权重、摘要清单每块256字节保守预留；HTTP只保留最多64KiB固定响应窗口，但整份计划仍受responseBytes文件限额约束。任务和响应预算生命周期独立，断连/失败/成功都归还。

默认导出active≤2、每企业active1、全局pending≤8、每企业pending≤4，分别受现有SQL容量进一步约束。等待采用现有30秒期限；企业队列满429，全局/额度不足503，排队取消不执行。慢导出持有同企业导出槽位，但普通JSON读取仍可使用剩余SQL槽。关闭先停止新HTTP准入，排空已接受导出，再关闭SQL调度器/连接池。

私有`IDMS_CAPACITY_CONFIG`新增`exportPrepareMs`（默认120000）和`exportSendMs`（默认300000，配置最大300000）。写空闲期限15秒。每轮SQL按剩余阶段时间设置事务内statement_timeout，查询取消后仍保留原超时错误并回滚；检查点限制编码和发送期限。同步CPU不能被这些检查点抢占，网络/驱动/故障清理仍需实际观测，不能把配置值当成严格SLA。

## 错误与验证

- 422 `CSV_EXPORT_BYTES_LIMIT`：超过当前文件字节限制（默认256MiB），缩小筛选。兼容数组/FileDemo仍可能因10000行上限返回422。
- 504 `CSV_EXPORT_PREPARE_TIMEOUT` / `CSV_EXPORT_SEND_TIMEOUT`：查询或传输期限；发送后通过不完整连接报告。
- 503 `CSV_EXPORT_INTEGRITY`：绑定/双遍字节/计数/提交不一致；不返回内部数据库细节。需要核查完整性，不能下载静默截断的结果。
- 401/403：登录及read/数据范围权限；不能用查询参数切换企业。

`npm run csv:verify`创建可清理的隔离PG/真实Keycloak账号/实际index核心，验证100设备、20k记录、公式/点定义更正、独立模型字节一致、组合筛选/范围/空结果、双遍间真实独立审批、第二遍篡改、慢连接/断连/预算/SQL取消/发送超时/队列/关闭，以及Chrome原生下载/Excel回读/390和320移动端。输出仅摘要，不含账号秘密或实际原文件。

`npm run csv:live:verify`只读核对原4010：真实原件长度/SHA/MIME、CSV与独立模型、原生页面下载、完整及分页审计、移动端、原业务摘要保持。升级前后使用同SID/CSRF/既有审计加密游标探针、离线全payload/逐表历史核对和业务加密备份隔离恢复。

## 范围与后续

没有新DDL；业务迁移4、实体布局3、payload2、独立认证schema1。历史迁移、canonical摘要、完整entity读取和写后核对模型保持；revision-projection仅增加共享SQL正文包装，CTE/DDL不改。SQL分页选择与CSV共用，增加最终source_ordinal作为排序平局键，JSON DTO不变。

这里解决应用导出数组/CSV和浏览器Blob驻留，不等于整个系统恒定内存：第一/变更读取完整来源证明、输入事实、写前图/工作区/wire、最大原件行、服务端MATERIALIZED CTE/排序及两遍SQL和同步CPU仍存在。摘要清单随文件块数增长，单行/单元格仍有原输入长度及行解析成本。逻辑预算不是RSS硬限制。数据库/上游HA、长期分段存储、现场数据、模型/RUL、SaaS/私有化及安全/灾备/商业化/UAT继续，生产验收门禁保持关闭。
