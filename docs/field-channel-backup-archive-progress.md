# 现场完整归档：流式加密容器

已实现独立的流式加密容器、严格清单和安全临时文件模块。485 项核心单元测试、209 项构建/语法及类型检查通过；真实 PostgreSQL 同快照 dump、25 类无效归档及 160MiB 流式检查通过。此项仍是现场通道第 6 项的阶段进展。

## 格式与校验

新格式使用独立标识 IDMSFLB1、独立密钥文件、AES-256-GCM、96 位随机 nonce 和 128 位标签。清单绑定企业、归档/恢复操作编号、源与目标恢复身份、源连接绑定、恢复控制及意图摘要、public+idms_field 完整事实，以及 dump 长度和 SHA。它不接受旧 v1 业务备份格式，也不改变旧工具和旧格式。

清单拒绝未知字段、缺失现场表、错误角色/连接绑定、未变化的目标激活、重复 JSON 键、非规范 JSON、错误 UTF-8、过深或过大的结构。严格校验后复制并深度冻结，调用方后续修改原对象不能改变归档身份。事实扫描的根更新时间现于散列前明确转换为 UTC 字符串，真实 JSON 往返仍保留事实摘要。

加解密按 64KiB 增量读写。解密先把未验证明文限制在自有私密目录；完整 GCM 标签通过后才解析清单，再验证完整 dump 长度、PGDMP 标识和 SHA。全部通过后才向调用方返回 dump 路径和冻结清单。容器模块不连接数据库，也不执行 pg_restore；正式恢复工具还必须在该返回点之后才能发起目标 DDL。

## 文件与中断行为

输入拒绝符号链接、junction 和多硬链接，检查打开句柄的身份、大小和修改状态。处理过程中修改已经读过的源文件或归档头，也会在完成前被发现。阶段文件同步完成后，以不覆盖既有名称的方式发布归档；崩溃若留下双硬链接，读取守卫拒绝该文件，需要按自有操作材料核对，不自动删除未知材料。

显式取消会等待正在进行的 I/O 返回、关闭句柄并清理自有临时文件；不会返回部分 dump。清理遇到外来文件或身份不符时保留目录和材料。进程被强制终止或物理断电后的自动清理/归档操作恢复，尚未纳入正式协调器验收；本轮没有声称这些情形会自动清理成功。

当前明确限制：清单 1MiB、dump 明文 8GiB、单行规范 JSON 64MiB。解密临时空间可能同时保存明文封装和提取后的 dump，需计入磁盘预算。真实大库容量、配额和 SLA 尚待验收；8GiB 是拒绝边界，不是已完成的满量负载测试。

## 已验证范围

隔离实际 PG16 使用独立只读备份账号导入源导出快照，生成真实 custom dump；加密/完整认证后，以实际 pg_restore --list 检查现场点、回执、业务原件表及派生视图。所有自有 pg_dump/pg_restore-list 子进程确认真实终态。此测试不执行数据库恢复，其恢复操作元数据是明确的自有 fixture。

25 类无效归档覆盖头/nonce/密文/标签、截断/追加、错企业/密钥、密钥文件重复键，以及标签正确但清单/事实/正文错误的输入。另验证名称冲突不覆盖、错误源摘要不发布、链接路径拒绝、外来临时文件保留、显式取消、输入中途变化及清单不可变性。

160MiB 检查使用带 PGDMP 前缀的合成二进制，专门验证增量处理，不是可恢复的数据库备份。5ms 采样的 ArrayBuffers/RSS 增量记录在验证 JSON 中；不把采样峰值作为所有负载的物理峰值保证。
