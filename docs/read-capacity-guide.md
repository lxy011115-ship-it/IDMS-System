## 改动与实际语义

数据中心设备档案、测点查询及两种完整筛选CSV导出，直接进入独立的`REPEATABLE READ READ ONLY`事务。校验、统计、分页、字典、来源和导出共用一个连接与快照；不先加载原文件/全审计到Node，也不经过本机写队列或取得企业状态SHARE锁。并发写入时，读请求返回完整的旧版本或新版本，不能混合计数与结果。快照语义见[PostgreSQL事务隔离说明](https://www.postgresql.org/docs/16/transaction-iso.html)。

其他GET继续按企业排队和企业状态SHARE锁，因为部分旧服务在另一连接读取投影。它们也使用一致快照和变更校验，未变化时复用冻结的企业工作区，不再每次重建原文件/记录/审计。数组、对象与幂等Map只读；写操作开始/结束使目标企业缓存失效，失败回滚后同样必须重新应用已验证状态。见[企业工作区指南](tenant-workspaces-guide.md)。锁等待遇到并发提交时，仅在进入业务回调前有限重试，不能重复已经输出的响应。

变更校验不是只看业务`revision`或缓存时间。每次仍从数据库读取所有依赖关系可见行的MVCC版本摘要，绑定数据库OID、服务器启动时刻、64位快照的XID代际、关系OID/物理文件代际/目录版本、`tableoid/xmin/ctid`及兼容视图定义。原文件只读取元组身份，不在热路径解码或传输其正文。

工程设计依据是：在同一受控PostgreSQL存储代际中，正常SQL更新会产生新的可见行版本；物理表重写、服务器重启或XID代际改变会使证明失效。这是本系统的缓存失效设计，并非将这些系统列当作业务ID或长期身份。相关约束见[系统列文档](https://www.postgresql.org/docs/16/ddl-system-columns.html)。指纹只压缩行版本身份，不能替代磁盘校验和，也不保证识别绕过PostgreSQL的物理字节篡改。

指纹变化时，必须重新通过v3内容摘要、原文件SHA-256、冻结映射/设备类型、审计链、工单镜像、事实/类型投影和更正账本检查。失败返回503，不缓存失败结果。同一指纹的并发冷校验合并；证明缓存只保存少量元数据，不保存原文件、记录或审计数组。数据库中断时仍必须查询指纹，不能用旧证明返回数据。

每个请求继续验证签名身份，SQL按当前可信工厂/产线/设备声明过滤。证明按连接池和企业隔离，既不缓存用户查询结果，也不缓存用户权限。混合批次整批保护、独立批准、原来源及历史版本继续保留。

## SQL与冻结输入优化

容量测试发现，原查询把大份有效记录反复自连接，某些工厂/质量筛选和完整导出计数超时。现在先一次解析最新更正，再将设备、定义和测点类型结果各计算一次；类型结果直接携带正文、来源和版本，去除重复连接。设备的点数/记录数按设备汇总一次。[PostgreSQL CTE文档](https://www.postgresql.org/docs/16/queries-with.html)说明了显式物化和重复求值的关系，具体性能仍以本系统实测为准。

冻结输入行拆分改用按规范化内容建立的匹配索引；保留每个重复输入位置及有效行顺序，缺失匹配仍拒绝，不更改原文件或批准结果。业务schema仍为v3，认证schema仍为1，已应用迁移校验和不修改。

## 复现与证据

```powershell
npm test
npm run build
npm run reads:verify
```

专项使用隔离的两个企业数据库、真实Keycloak用户/客户端、两核心及100台设备、100个测点定义、20,000条测点记录、多MB原文件。大数据由领域建批/独立审批后迁移至隔离库，原JSON包含合法空白填充，用于放大原文件重复传输的成本；不是单次大文件HTTP上传或磁盘吞吐验收。新JSON/CSV逐字段对比文件领域契约；可成功返回的旧SQL结果逐字一致。旧基线采用完整工作区验证和冻结的原SQL，省略旧路径额外的工作副本克隆，因此不会用额外克隆成本夸大改善；超时如实记录。

通过Node测试进程IPC收集查询次数与SQL返回行的JSON编码字节量，不提供公开诊断接口，也不记录查询结果正文。它是SQL返回内容的可比代理量，不是数据库网络协议总字节数或浏览器下载大小。时延样本为本机少量交替设备/测点请求，不能据此制定生产SLA。

最终数值与检查见`outputs/read-capacity-verification.json`：热读取不再查询完整工作区；旧路径实际等待写锁时，新SQL读取仍能返回已提交快照；写入后重新校验；同业务revision下的批次/文件/投影/审计篡改均被识别；表重写使证明失效且并发校验只执行一次；数据库不可用不返回旧数据，核心重启后共享会话保留并重新校验。测试仅清理自己创建的库、角色、身份和私密配置。
