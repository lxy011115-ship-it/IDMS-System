# 冷证明中的逐批输入与逐行事实

后续[批内双流证明](cold-inputs-guide.md)已移除bindings-only中的整批rows/validRows驻留，保留原完整canonical及全部来源；本页数字和实现说明属于对应历史阶段。

原4010已部署，实现标记：`coldImportProof=batchwise-input-fact-proof-v1`。本阶段把独立SQL读取和启动的完整企业输入/有效行/事实图改为逐批/逐行证明，保留原business_state.payload_digest和全部来源。没有新DDL、历史摘要重算、认证schema变化或容量默认提高。原站点连续性、离线全表及升级前后恢复均已验证，见本阶段证据快照。

## 完整性范围和顺序

所有语句位于调用者同一个REPEATABLE READ快照，启动保留原SHARE锁/权限/历史配置检查，独立SQL仍READ ONLY。先读实际业务集合及最小批次header；逐行重放完整审计及链，包含旧和隐藏事件，只保留每批接收次数/全部标记/首事件摘要和类型模板最新治理锚。然后完整命令回执流。

按原批次ordinal读取一个真实元数据和全部输入，恢复该批完整BatchBody与独立有效行副本。原共享输入值公式以有界canonical流核对所有冻结snapshotDigest；原写摘要包装保持原算法。按原canonical属性顺序放入该批数据和最多49152字节文件片，每片连续偏移/长度/总长及原SHA均核对。需要的实际接收事件从同RR重读并与整链记录的事件摘要匹配，再执行原映射/类型继承/更正冻结治理。处理完释放该批。

所有root批准事实按原ordinal逐行重放，同时计算原projection rows_digest并核对计数、来源类型/系统/批次和快照。全部导入请求回执也必须重放。输入和文件全关系计数与各目标累积匹配，foreign/孤儿/漏/重/乱序失败关闭；不能用WHERE丢弃未覆盖来源。

最终原根SHA一致、typed SQL和全部更正ledger也通过，才产生可用证明。更正索引只保存被更正来源键、版本、前批次/行、before/after和上一StoredRow摘要及设备编码。按root/revision流读取实际根与全部版本，只保留一个当前版本，核对连续版本、实际前记录/原值、设备编码不变、本批真实输入及冻结血缘。重算根/审计/批次摘要仍不能使伪造前记录通过。不保留完整root事实索引。

## 明确消费者

`verifyColdImports`只返回经过完整证明的tenants/历史Flowable与AI模型绑定和revision；不造含空records/文件的TenantPayload。启动白名单折叠和独立SQL/批次页/CSV使用该入口。精确MVCC指纹SQL仍原样，只复用同内容/同代际的成功证明，不只看revision。

旧报表/质量/历史/模板等需要完整ImportView的分支明确使用ReadCollector，收集用于同一canonical证明的真实业务/批次和事实，全部校验完成后才冻结返回。单独证明后不再查询一份未与该次根绑定的冷视图；没有截断BatchBody/假空正文或异步getter。该完整只读契约仍保留全部输入/有效副本/事实；其温重建保持原轻SQL。命令及维护仍完整原件/审计/回执模型，写前/写后、职责、幂等与回滚语义不改。

## 生命周期与资源

批次、业务集合、更正摘要、接收锚索引和瞬时行/文件片有逻辑租用，额外固定scratch覆盖编码/摘要缓冲；成功、故障和取消均归还。一个PG流最多额外保留一行，行错误仍排空已执行语句；尚未执行的后续来源不为失败继续发起。根完成后的typed/更正阶段取消也不能缓存证明。正常已开始命令的完成语义保持。

默认512MiB任务/1GiB总任务等保持。最大单批真实输入/有效副本、业务集合、批次header/接收标记和更正摘要索引仍增长，单事件/元数据及字段、服务器排序/往返、完整来源传输和同步canonical/治理CPU仍有成本。不是RSS、物理硬限、生产SLA或完整写容量验收。
