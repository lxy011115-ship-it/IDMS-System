# 当前数据集中的现场测点与回执

本阶段在当前站点状态映射中实现现场接收事务和有界历史测点查询。使用既有事件HMAC、租约签名、读取见证、流绑定和提交后签名ACK协议。现场事件仍与SIMULATOR保持各自协议，旧public/idms_field数据集没有被作为当前接收目标。

`FieldMapTransactionsV2`复用上一阶段的真实事务原语，并公开冻结的存储绑定。`FieldMapReceiverV1`在同一次CAS根提交中追加审计、回执、测点、事件/流序列/读ID冲突索引及设备分页索引。当前准入先于重放查询；原事件补传复用原审计和回执。新事件按事件ID、流序列、读ID的既有优先级记录拒绝回执，不增加测点。准入拒绝追加独立审计并保留既有数据。签名ACK只在实际提交确认或原提交回执解析成功后产生。

提交前在同一基础根重新计算准入指纹，边界变化取消整次事务。取消、模拟权威撤回、关闭接收器或SQL围栏拒绝写入时，不返回业务ACK。关闭会等待自有操作排空并清除复制的事件密钥。实际身份、恢复和SQL围栏当前状态门禁仍由必须显式提供的宿主guard承担；本阶段模拟guard没有证明真实宿主的全部行为，特别是没有写入的重放也必须在实际宿主中覆盖撤权场景。

接收初始化是一项明确的维护操作：它扫描通过核验的完整当前企业负载。已有FIELD_EVENT审计而没有当前接收标记时，报`FIELD_MAP_LEGACY_INTAKE_REQUIRES_MIGRATION`，不会按空数据集覆盖。这证明阻断错误初始化，不代表旧SQL接收数据已经迁移。后续必须保留并迁移这些旧点、回执及审计的关联证据。

`readFieldMapPointPageV1`提供同根倒序分页，单页最多16点；每个测点都核对回执、审计位置、历史注册/租约和历史准入。无需持有事件HMAC密钥即可检查已提交证据，不能因此声称重新认证了HMAC。历史公钥由调用方明确提供。策略暂停后，既有点仍可作为历史证据查询。该接口尚未接入HTTP、设备授权范围、界面和预测器，不能仅凭内核查询成功声称最终站点已展示这些数据。

Windows九项规则测试、十五项原生检查和独立检查通过。原生验证使用新自有PostgreSQL、真实map/队列/SQL围栏及当前接收器，覆盖原规则逐字段对照、原子接收、重放、三类冲突、并发CAS、提交前取消、模拟权威撤回、真实COMMIT后人为丢弃客户端结果并解析原回执、持有事务时关闭、围栏拒写、V6独立模型审核后暂停及旧索引缺失拒绝初始化。缺失标记场景是在隔离QA中暂时移除并恢复已有标记，未操作生产数据。

独立检查不开库、不重启，核验59份当前根成员证明、七份回执、四个点、八条原规则对照、11个事件HMAC、10份业务ACK签名、四个取消/失败事件没有数据或ACK，并验证损坏成员证明确实拒绝及PG干净离线。正常四点查询读取35个成员、89,862字节；这些是本次样本的实际值，不是容量或性能验收。Linux由本次独立GitHub workflow核验。

事件见证在本阶段来自明确的协议模型，未运行真实OPC UA或mTLS MQTT。权威撤回、丢提交结果均为明确QA注入；没有执行真实OIDC/恢复权威或统一控制器门禁。下一步将当前签发/接收器接到真实边缘/MQTT和统一HTTP宿主，再完成设备授权、界面/预测消费、逆序排空、同请求恢复和旧数据迁移。保留全部原TODO及原核心V20未解失败；未备案idms.xin只做部署准备，最终同版本图文说明和实操视频仍须交付。
