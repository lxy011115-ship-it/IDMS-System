# 本机平台端口恢复

2026-10-16，原PostgreSQL的55432及相邻55433端口被QQLiveService的Windows Bound端点占用，普通Node试绑定不能证明PostgreSQL可监听。此次保留第三方进程，将IDMS改为127.0.0.1:45432，数据库目录和身份不变。

新增工具`npm run postgres:port -- --port 45432`只用于已停止的本机开发平台。它核验原PostgreSQL停止、Windows端点无占用、4010/8081/4016等依赖已停止、四份数据库配置端点一致，然后保存受限回退副本并替换端口。遇到不一致或其他进程占用会拒绝，不终止第三方程序，不自动猜测端口。工作流配置在`platform:start`前由原部署配置重新生成。运行中不要更改端口。

本次执行顺序：

1. 预检并保存受限配置副本；55433仍被占用后改选实际空闲的45432。
2. 启动原PostgreSQL，分别对acme/sandbox生成认证加密备份，并在随机新库隔离恢复验证；不覆盖原库。
3. 运行独立v2迁移，逐企业确认原完整业务快照不变，迁移版本为1、2，原事实未重写。
4. 启动原Keycloak、真实Flowable、独立预测、只读OPC UA/MQTT和AI SHADOW网关。
5. 最新代码加载后，在真实4010站点只读回归；再次比较原业务/导入摘要、核心事实和原审计前缀，核验最小数据库权限与完整审计链。

配置回退副本、业务备份和恢复密钥保存在受限`.local`子目录，不放在交付包或聊天中。`outputs/platform-recovery-verification.json`只有非秘密验证摘要。只读站点回归证据为`outputs/live-data-management-verification.json`，原acme保持6批、0工单；登录及sandbox模拟采集会按设计追加审计，不冒称审计数量完全不变。

当前用户入口保持 http://127.0.0.1:4010/ ，双击`启动IDMS.cmd`可按新配置启动。改变数据库端口不改变浏览器入口。该恢复仅证明本机开发集成可运行，不是高可用、跨服务灾备、RPO/RTO或生产安全验收。
