# 恢复审核业务与工作流一致性：阶段进展

新的恢复准备器从原完整根事务的重建 payload 提取全部工单和全部已发布策略，并与原持有连接的真实 Flowable 快照逐条校验。拒绝孤立流程、遗漏、重复、跨企业、工单版本、最后命令、任务、历史及维修证据错配。原来源事实与第一次准备结果保持不变。

Windows 通过33项单元测试、32项完整原生检查和独立V1复核。新的隔离数据源由真实 Keycloak 用户经预测与维修业务接口创建，Acme 包含独立批准关闭流程，Sandbox 包含已领取流程；之后保留全部整库加密备份、异目录恢复、实际COMMIT丢回复、七库完整SQL与完整根、外来连接及来源漂移拒绝、原维护锁和只读引擎正常关闭验证。独立复核另从四份完整根证据重建审核输入并与实际采集记录逐项比对。

此前C36的真实证据中另由离线独立重建确认两企业存在测试夹具直接生成的孤立引擎案例，新校验明确拒绝。旧31项恢复完整性结果不改写成曾经覆盖业务一致性；新的正向案例通过真实业务入口建立对应关系，不从库存中过滤不匹配记录。

当前用户身份授权、全部贡献者复验、持久审核计划与批准、正式现场激活、整站与商业验收、服务器最终候选和同版本中文图文手册/实操视频仍未完成。本阶段通过只证明审核输入和工作流一致性，不授予审核批准或业务写入。Linux以确切新提交的真实终态为准。
