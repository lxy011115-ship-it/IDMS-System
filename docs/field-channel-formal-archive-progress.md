# 现场数据正式加密归档进度

本阶段串联真实恢复操作、源库持久冻结和完整加密归档。新增 `archive` 动作，仅处理已经确认冻结的源库。成功后仍为 `RESTORING`；目标数据库恢复、维护模式和独立激活审批继续开发。原 4010 未部署 FIELD。

## 操作入口

先按恢复控制流程完成 `initialize`、带独立新目标的 `begin` 和 `freeze-source`，再执行：

```powershell
node scripts/field-recovery.mjs --action archive `
  --authority-config <私密部署配置> --runtime-config <私密源运行配置> `
  --tenant <企业标识> --control-file <私密恢复控制文件> `
  --operation-id <原恢复操作UUID> --migration-config <私密迁移配置> `
  --backup-config <私密只读备份配置> --key-file <独立现场备份密钥文件> `
  --archive-directory <已创建的受限归档目录>
```

使用相同参数和原 `operation-id` 重试归档动作。只读 `status` 显示文件状态；通用 `resume --migration-config` 核对源冻结，并不表示归档已经完成。密钥格式为独立 `idms-field-backup-key-v1`，不得混用原业务备份密钥格式。

## 数据和证明

- 正式清单为 `idms-field-full-backup-v2`。包含完整恢复意图、冻结意图与结果，以及 BEGIN、REQUESTED、FROZEN 三条保护审计，绑定源/目标身份、独立目标角色、完整事实和 dump。旧 v1 容器仍能读取，但其 fixture 元数据不能作为正式恢复凭据。
- 捕获同一导出快照中的 31 个 public 物理表、1 个派生视图和 3 个现场表。真实 backup 账号执行 PostgreSQL 16 `pg_dump`，同快照读取序列。旧视图必须等于规范化完整根，并复核原件校验、导入投影与完整审计链。
- 源验证只使用可回滚的权限投影，所有验证事务均回滚。导出及发布前后重新扫描全量事实，序列单独核对，明确其值不受 MVCC 快照保护。未支持的扩展、外部对象、复制配置、事件触发器、大对象和已准备事务等拒绝归档。
- 三条审计摘录各自校验哈希和语义；完整链在真实源库中验证。后续恢复仍须用实际恢复数据重验完整根、全部历史及现场数据，不能把摘录视为整条链的离线证明。

## 中断后的行为

持久意图固定备份编号、源事实、密钥绑定和输出目录。`pg_dump` 的完整参数、程序摘要及执行者身份先写私密日志，明文 dump 仅保存在私密操作目录。恢复时按精确命令参数识别自有原生进程，核对 PID 与创建时间，等待其真实结束；剩余 PG 会话按原操作标签、数据库及角色 OID 排空。

归档采用 64 KiB 增量加密、AES-256-GCM 和完整 dump SHA。就绪记录固定密文、清单与 dump 摘要后，才使用同目录 Windows WRITE_THROUGH 非覆盖移动发布最终文件。已完成文件必须再次完整认证并匹配原记录，随后复用相同编号和密文字节。未知文件、损坏日志、已完成文件缺失或错密钥/目录均拒绝自动修复。未就绪的精确自有阶段路径，在旧执行者实际结束后可以重建。

归档成功不创建目标库或角色，不执行 `pg_restore`，不重新开放源库，也不提供跳过独立终审的激活入口。

## 验证范围与待办

实际隔离 CLI 验证使用真实初始化控制文件和已提交的 2 条现场协议样本、2 条回执，完整认证后由 `pg_restore --list` 确认 dump 可识别。包括证明篡改、错密钥/目录、未冻结、源序列/外部对象/旧视图变化拒绝，以及同操作重复执行。协议样本不代表真实设备或外部 OIDC 验收。

结果记录损坏、成品文件缺失、密文改变，以及缺少就绪记录时出现有效成品，也分别拒绝修补或覆盖。测试仅在自有隔离目录恢复原文件，随后复核相同归档可以继续使用。

进程中断验证与核心单元、构建、旧控制/归档回归的实际结果见同名进度验证 JSON。原生 dump 退休测试使用真实固定程序等待自有本机握手，单独证明进程识别与终态；它不是导出数据中途崩溃的证明。此前 160 MiB 合成容器流式检查也不代表大数据库归档容量验收。

下一步是非空现场数据的实际隔离数据库恢复、最小目标角色受控重绑定、FIELD 关闭的维护实例及恢复计划独立终审；之后完成证据冻结、离线 CLI、全链与原核心受控部署。Linux 写入、跨宿主移交、大数据库容量和完整商用验收仍待。

最终本阶段验证：485项核心单元、217构件/类型，六个新中断阶段及旧源六崩溃、控制八崩溃、基本控制CLI和原SQL/25类无效档/160MiB合成容器回归通过。两份公开进度说明及JSON逐字相同；不建立新的最终证据快照。
