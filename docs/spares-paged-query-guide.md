# 备件容量改造：分页查询接口

更新：2026-10-30。用户已批准设计，第二阶段服务端和第三阶段主站消费者已实现并切换本地运行。第四阶段已补齐命令/历史同连接及本地取消/超时/有限重试，见[事务说明](spares-transactions-and-cancellation-guide.md)。分段证明、档案锚、生产网络与最终联合验收继续。

## 接口契约

新增用料计划、库存依据和更换登记间隔的源码接口见[备件洞察说明](spares-demand-and-insights-guide.md)。它们要求专用 capacity=2，独立源分支实现不等于当前主站已经切换。

以下路径位于 `/api/v1/spares/`，仅支持 GET，沿用企业会话及当前备件读取权限。接口不接收前端提供的角色、企业或权限范围。

| 路径 | 参数 | 返回职责 |
| --- | --- | --- |
| `summary` | 无 | 全部授权范围的低库存、个人可独立审批、采购逾期、到期更换、票款待核对和启用档案计数 |
| `list` | `kind`、`limit`、`q`、`cursor`；采购可带 `supplierId`；收货/流水/凭证可带 `purchaseId`；设备相关类型可带 `deviceCode`，流水/更换可带 `workOrderId` | 当前页业务记录及必要关联名称 |
| `detail` | `id` | 一张授权采购单、至多50条明细、准确票款及净收货金额；收货和凭证另行分页 |
| `options` | `kind`、`limit`、`q`、`id`、`cursor`；工单/位置可带 `deviceCode`，位置可带 `partId` | 可搜索的备件/仓库/供应商/位置/设备/工单；既有选中项单独核对返回 |
| `workorder-usage` | `workOrderId`、`limit`、`cursor` | 指定当前授权工单按备件聚合的库存净领用，保留各备件单位 |

`list.kind`：`stock`、`part`、`warehouse`、`supplier`、`purchase`、`receipt`、`movement`、`link`、`replacement`、`adjustment`、`document`。

默认30条，最多100条；数据库最多返回101条以判断是否还有下一页，HTTP页不超过100条。未知或重复参数、空游标、非法标识和超长查询明确拒绝。关键词是字面子串，`%`和SQL片段不改变其意义。

分页返回 `items`、`hasMore`、`nextCursor`、`limit`。游标由进程内密钥签名，绑定身份、企业、权限范围、查询条件、原业务及备件版本；进程重启使旧游标失效。资料、范围或查询条件变化时返回409并要求重新从首页查询。不要自行拼接或解释游标。

库存使用备件/仓库标识稳定排序，保留同工厂零余额组合；其余业务列表使用创建时间及ID排序。汇总独立从SQL全范围计算，不能以本页记录替代总量。个人待审批计数排除本人编制、参与和提交的采购以及本人库存调整。

## 一致性与边界

同一条连接、同一可重复读只读快照内核对原业务完整性、当前已批准修订设备、规范工单、备件版本及完整审计链。HTTP接入使用已有 `verifySqlRead`，不再为这些新接口嵌套借出原工作区和备件两个连接。企业容量索引迁移缺失时明确拒绝。

范围修订后，相关设备/工单记录立即按当前快照重新筛选；仓库余额仍按该备件/仓库全部流水汇总，不因隐藏了部分设备领用而少扣库存。已停用的选中档案可作为 `selected` 单独显示，不能混入可供新业务选用的启用列表。

已纳入现有SQL调度、任务内存计量、请求取消检查和语句/锁超时。取消前未借连接或在原业务证明结束后取消的释放已测试；运行中的SQL即时取消、耗尽/超时联合场景仍待后续验收，不能据此声称完整取消机制已验收。当前仍完整流式验证备件历史，分段证明缓存尚未启用。

SQL只向应用返回当前页和聚合值；数据库内部仍可能扫描全部符合范围的数据及历史。该改造没有承诺恒定延迟或无限容量。选项使用公开的必要标签，列表关联名称不返回供应商联系人和电话。

## 隔离实测

`scripts/verify-spares-growth.mjs` 创建独立随机QA库，由领域规则生成10001条备件实体、20001条有效审计事件作为历史种子，再用实际应用角色执行业务。第二阶段结果位于 `work/spares-capacity-20261030/growth-query-verification.json`。

本次最终10017条实体、20020条事件，20次应用角色成功调用（包含幂等重读）；仓库余额1000毫单位。新读取发起34次请求、恰好借出34次连接，最大非流式结果101行。采购/收货/流水/位置/更换/凭证等小结果集逐页与完整领域视图对照；大备件集验证首页、相邻页不重叠、末尾旧档案搜索和选择器，不声称已遍历全部100多页。

核对还覆盖原业务设备修订撤出范围、库存余额保持完整、工单净用量5000毫单位、停用选项、个人独立审批计数、两个版本的游标失效及旧事件篡改拒绝。增长专项使用隔离的合成public投影，不能把它当作完整企业原业务证明或真实岗位验收。客户业务测试写入为0，QA库按确切命名清理。

另用现有acme、sandbox应用连接，在只读事务中调用真实 `verifySqlRead`，核对summary、库存首页和设备选项。每个连接池最大连接数设为1，全部通过，备件版本前后一致。证据 `work/spares-capacity-20261030/actual-query-readonly.json`。这是内部只读验证上下文，不是浏览器登录或多岗位UAT，没有创建账号或改变授权。

## 已切换的主站消费者

九个备件页签保留，列表每页30条，关联仓库及实际更换表分别翻页；搜索覆盖当前类型全部授权资料。采购详情按ID读取，至多50行采购明细；分批收货单独分页，不再以当前列表中是否存在该单据决定能否显示详情。

表单点击“搜索选择”才加载相应档案，支持关键词与前后页，选中项不因搜索和翻页丢失；采购行最多50行。搜索尚在加载时输入新关键词，以最新查询为准，旧响应不能覆盖。设备更换位置按原领用的设备/备件过滤；设备改变后清除旧关联工单。

工作台和审批页使用全范围summary；首次建档提示使用完整启用档案计数。工单卡点击“读取净领用”后只查询该工单，最多缓存16个已展开工单页，不下载企业全部流水。不同计量单位分别显示。
