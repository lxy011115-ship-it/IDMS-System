## 独立存储与迁移

新模块使用同一企业库的 `idms_field` schema，包含 migrations、points、receipts 三张只追加表。原 public 表集合、基础迁移 1 至 5、旧规范化数据和安全校验器保持。模块校验和绑定编译 DDL、精确权限、编译目录合同、基础版本和企业角色。校验器逐项核对列、约束、索引、触发器、函数引用、schema/表/列/默认权限及实际数据库身份；持表锁直到父事务结束。

应用只有点与回执的 SELECT/INSERT，模块迁移只读；备份角色全部只读。运行启动不会自动建表或修复未知对象。迁移使用已有专用部署迁移账号，并要求停止该企业应用数据库连接。明确指定配置及企业：

```powershell
node scripts/migrate-field.mjs --runtime-config <运行配置> --migration-config <迁移配置> --tenant <企业ID>
```

此命令仅迁移现场模块，不能替代备份、恢复或受控上线。

## 接收与幂等

平台先由固定主题确定来源，在有界工作槽中核对规范 JSON、独立 HMAC、原签名租约和只读见证。父事务锁定并验证完整业务根，校验现场模块、当前注册和审批、原持久签发及捕获绑定，再查询旧回执。最多补传 7 天。原租约过期的已捕获事件可在当前绑定不变时接收；它不提供新的读取许可。

当前暂停、审批变化或注册变化不能被旧 STORED 绕过。暂停只追加拒绝审计，不查询或改写旧点/回执。精确重放核对原信封、受保护审计、历史绑定和原点；事件 ID、流内序号、readId/tag 冲突生成明确拒收。返回列与预期不符会整笔回滚。

点、回执、父审计与业务根共用同一连接和事务。延迟审计外键在真正 COMMIT 时生效。根写入后再核对预约生效边界，变化则整笔回滚。提交失败或响应不明时不签成功；提交确认后才用平台私钥签 Ed25519 业务回执。未来观测可以收到 REJECTED，不能收到早于观测时刻的 STORED。

## mTLS 接收与多实例

平台配置 `IDMS_FIELD_PLATFORM_CONFIG` 提供已批准公共 profile、请求/事件密钥与签发私钥；新增可选 `IDMS_FIELD_INTAKE_CONFIG` 提供平台 MQTT 私密材料。接收配置使用 `idms-field-platform-intake-v1`，结构是 tenants → tenantId/channels → edgeId/mqtt；mqtt 包含 url、caFile、serverCertificateFile、clientCertificateFile、privateKeyFile。证书与密钥文件均须在该配置目录内，固定 URL/材料摘要必须匹配同一批准 v2 profile，完整覆盖配置中的 v2 来源。未配置时接收关闭。

每企业一个专用 PostgreSQL 会话持 advisory lock，所有现场接收事务也在该会话执行。备用实例不连接固定 PLATFORM 客户端，避免 broker 按证书 CN 固定 clientId 时互相挤掉。原会话真正断开并失去锁后，新实例才能接管；旧会话中的未提交事务不能在新实例获得锁后提交。检测到过期注册的实例退出该企业接收，不能反复抢回旧配置。此机制验证了接收所有权围栏，不构成完整 HA/SLA 验收。

接收器限制一个待发送业务回执。收到可信事件并完成事务后，先允许 MQTT 处理入站协议，再等待出站 PUBACK，避免在同一个消息解析回调中相互等待。并发超限会关闭连接并保留未确认事件供重发。应用负责有界退避；任何连接替代都等待旧连接及本机任务实际终态。健康接口新增 fieldTransactionalIntake 状态，不输出证书、密钥或 broker URL。
