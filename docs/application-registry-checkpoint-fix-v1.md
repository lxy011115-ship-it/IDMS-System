# 应用登记库并发检查点读取修复

`6188b90` 的 Linux 已登记应用组案例 `5b077d014a95` 完成 24 项后，部分启动观察因 `APPLICATION_FILE_CHANGED` 失败。独立清理实际通过：3 个 PG 目录干净离线、7 个业务数据库移除、4 个工作流正常停止、20 个池关闭且 JDBC 为零。原失败保留，未重启该任务。

登记库是持续变化的 SQLite 数据库。原入口复用了不可变 JSON 配置文件读取函数，在文件读取前后要求大小和修改时间一致；正常 WAL 检查点也能改变这些字段。修复保留 JSON 的原校验，将数据库入口改为绑定实际普通文件身份、拒绝软硬链接和路径别名，并在 SQLite 事务前后核对文件身份。内容继续验证可信头、每条事件的哈希链、序号、最终摘要和生命周期约束。

Windows 的 19 项回归实际通过。新增案例由独立子进程写入完整 33 事件生命周期并执行实际检查点，父进程并发读取一致快照；随后核实硬链接和篡改链均被拒绝。此为登记库并发回归，不能替代全系统或真实服务取消验证。

独立 Linux 并发工作流随修复提交。实际结果须以该提交的任务为准。旧提交另有 Linux 核心组合 31 项及独立清理成功的证据，但整批 10 个工作流为 9 成功、1 失败，未据此制作上线候选。
