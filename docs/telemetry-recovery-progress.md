# 采集内存与缓存恢复进展

2026-11-01，按已批准的[方案B](superpowers/specs/2026-10-31--telemetry-budget-and-spool-recovery.md)实施。**基础能力已开发并完成下列隔离验证，真实缓存迁移和本机切换尚未执行。**

## 已实现

- SQL流读取的临时租约，在完成绑定检查后同步转移为实际业务对象计量。前镜像、克隆、后镜像及写后校验索引仍分别计量，默认512MiB限制不变。
- 受限维护详情提供固定阶段和计数，区分内存、队列、完整性、未知COMMIT和ACK未确认；不输出事件、企业标识、SQL或密钥。提交、ACK排队、Broker确认及最终送达保持不同证据。
- 显式边缘维护基础函数支持只读提案、一致备份、独立恢复核对、未来游标校准和版本化收据。旧消息不改序号、不重签。调用者必须持有部署协调锁并验证原写者终态；实际维护CLI及描述升级尚未交付，不能直接用于真实切换。
- 迁移后的合法拒绝ACK将完整原消息、尝试记录和原ACK原子转入隔离区。原消息篡改、ACK错误、转移中途失败或超限时，pending保留。普通启动不自动升级v1库。
- 隔离区限10000条、128MiB UTF-8字段逻辑字节，消息/ACK各8192字节；另观察数据库256MiB、WAL64MiB阈值，达到后暂停相关写入。逻辑预算不是磁盘硬上限，维护需至少1GiB可用空间。
- 私密本地导出保留原字节字符串，独立检查事件/ACK签名、顺序、数量、摘要和专用HMAC清单；拒绝覆盖目标，不包含密钥。没有新增公共消息接口。
- 页面、就绪及巡检持续显示“隔离待处置”，不因pending下降宣称无错误。

## 验证证据及限制

`node scripts/verify-telemetry-recovery-memory.mjs`使用全新的自有PostgreSQL16.10和合成数据，不连接企业库。75171及85171条审计分别完成完整读取、审计链/摘要、业务写入、逐行写后校验、回滚和提交，最终载荷摘要匹配。默认任务预算536870912字节，账本峰值532264207字节，最终归零；采样RSS最高592584704字节，逻辑账本不能当作RSS硬限制。此规模剩余空间有限，全历史事务的CPU及增长成本仍待后续增量改造。

`node --test server/edge-recovery.test.ts`覆盖实际SQLite文件的备份/独立恢复、未来游标、重复维护、来源/密钥、未停写、提案过期、结构缺失、消息篡改、转移回滚、ACK错误、容量及导出篡改。10000条合成原消息逐条接受本地签名拒绝ACK，全部原字段摘要一致；第10001条拒绝转移保留pending。**测试ACK在隔离夹具内签发，不代替真正PG/MQTT/SQLite组合提交验证。**

本地服务端全套665项通过；另37项就绪/巡检/适配器/采集UI回归通过；构建检查323项运行资产及脚本和TypeScript通过。随后原消息防篡改补强经针对性回归和类型检查。最终同提交CI以GitHub实际记录为准。

3个自有PG夹具正常停机后，按精确目录、独立系统ID、控制信息及进程终态核对，已清理827347990逻辑字节，保留报告。未复制实际大库做压力测试。

备份使用固定Node版本的`sqlite.backup`并已实际验证；该API会覆盖既有目标，维护函数预先独占创建自有文件，遇到既有目标拒绝覆盖。参考[Node官方备份说明](https://nodejs.org/api/sqlite.html)。
