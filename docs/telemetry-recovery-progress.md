## 已实现

- SQL流读取的临时租约，在完成绑定检查后同步转移为实际业务对象计量。前镜像、克隆、后镜像及写后校验索引仍分别计量，默认512MiB限制不变。
- 受限维护详情提供固定阶段和计数，区分内存、队列、完整性、未知COMMIT和ACK未确认；不输出事件、企业标识、SQL或密钥。提交、ACK排队、Broker确认及最终送达保持不同证据。
- 显式边缘维护支持只读提案、一致备份、独立恢复核对、未来游标校准和版本化收据。旧消息不改序号、不重签。部分副本保留，备份/恢复各最多三代；已验证副本原样复用，已完成文件若变动则拒绝继续。SQLite提交结果丢失时读取同一收据，不重复迁移。
- 准备CLI支持检查、只启动原数据库、生成/查询提案及私密导出校验。迁移执行/续办与运行描述升级尚未接入CLI，当前不能直接用于真实切换。
- 迁移后的合法拒绝ACK将完整原消息、尝试记录和原ACK原子转入隔离区。原消息篡改、ACK错误、转移中途失败或超限时，pending保留。普通启动不自动升级v1库。
- 隔离区限10000条、128MiB UTF-8字段逻辑字节，消息/ACK各8192字节；另观察数据库256MiB、WAL64MiB阈值，达到后暂停相关写入。逻辑预算不是磁盘硬上限，维护需至少1GiB可用空间。
- 私密本地导出保留原字节字符串，独立检查事件/ACK签名、顺序、数量、摘要和专用HMAC清单；拒绝覆盖目标，不包含密钥。没有新增公共消息接口。
- 页面、就绪及巡检持续显示“隔离待处置”，不因pending下降宣称无错误。

## 准备与检查入口

在项目根目录运行：

```powershell
node scripts/recover-edge-spool.mjs --inspect
node scripts/recover-edge-spool.mjs --prepare-database
node scripts/recover-edge-spool.mjs --plan
```

入口仅使用已登记的部署，拒绝任意数据库路径或来源覆盖。数据库准备要求原主站/边缘/模拟器的身份已终态且端点空闲；已占用的数据库必须证明属于原部署。它不初始化、迁移、改密码或终止进程。只读提案逐行核对当前签名、原摘要、完整审计链、来源注册和测点血缘，保留前后结构/权限证据；当前适配器仅处理既有模拟来源，遇治理历史须明确核对。

终端返回操作UUID后，可使用`--status UUID`查询；已升级库可用`--export UUID`和`--verify-export UUID`处理受保护快照。提案保存在私密目录，包含旧描述副本和冻结依据，不能上传GitHub。当前入口拒绝`--apply`，避免在运行绑定接入前误执行迁移。
