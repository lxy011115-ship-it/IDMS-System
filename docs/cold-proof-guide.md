## 处理过程

调用者在同一个REPEATABLE READ快照内读取明确的轻对象：业务实体、批次元数据、原输入/独立有效行、原批准事实以及工单镜像。每个来源仍核对企业/身份/ordinal顺序、孤儿、有效行映射和镜像；结果为冻结ReadWorkspaceData，不创建含空originalBase64或空audits的伪TenantPayload。

第二条有序来源SQL提供state、全部审计、命令回执、每个原文件元数据及最多49152字节的bytea片段、导入回执。应用按原canonical属性/数组顺序重放根文本，同时增量计算根SHA。文件片段长度为3的倍数，逐片Base64拼接与原整文件Base64完全一致；同时核对片段偏移/长度/总长度、文件SHA、批次及元数据和空文件。未知、漏、重、乱序、foreign和孤儿均拒绝。

审计逐行核对SQL冗余列、合法int64顺序（允许合法序列间隙）和完整企业链，包括隐藏及旧事件。只保留各批次接收锚的首条、总次数和绑定标记，以及设备类型最新模板锚。原映射、类型继承/冻结解析、更正/原表头和独立审批规则共用显式证据接口；完整写入适配仍读取实际原件及完整审计。文件/根/全链未完成前不会产生可用的冷证据。

根匹配后，逐行核对全部approved事实及更正SQL ledger，保留typed字段SQL不一致检查。原当前版本CTE及投影DDL不改。新根、仅revision、仅本页、仅新增行都不能替代完整来源校验。

## 缓存、启动及资源

完整MVCC指纹仍涵盖所有原关系行版本/表与数据库代际及兼容view定义。只有完整证明成功才缓存该指纹，相同指纹的并发冷证明合并。缓存接收明确轻对象，温缓存重建沿用相同轻读取；原文件、完整审计和回执不回填缓存。失败和取消，包括canonical完成后在投影核对期间取消，都不能缓存证明。

启动先核对原权限、schema和历史迁移，在RR内取得原SHARE锁并完成分段证明，再接收租户、Flowable与AI模型绑定。仅对锁取得前的40001进行最多两次重试；已经消费/提交失败不重试，不重复发布绑定。企业停用状态不被提升。完整维护装载和写事务继续使用原完整模型。

轻来源按行保留临时租用，完成组装后转为轻图预算；原输入与有效行保持独立对象。文件元数据/瞬时片段和单条证据按需租用，下一行归还，编码缓冲有固定预留；驱动额外rows最多1。错误排空同一查询后返回连接，关闭/取消沿用原调度和调用者期限。默认容量配置字节未改。

## 实测证据

`npm run cold:verify`创建隔离业务/认证库与真实Keycloak/实际index核心，100设备、20000条测点、22170962字节原件（六基础文件加一笔合法更正）、12500条附加审计、2000命令回执和500导入回执。

两条测量都使用当前完整投影校验，比较的是完整重建参考与分段证明，不作为历史整程序的RSS或耗时对照。同一数据上，完整readEntities重建加完整投影校验的任务逻辑峰值采样155726708字节，新分段证明110658506字节。两者之间的私有133192607字节限额下，原重建拒绝并释放，新实际启动及带既有OIDC SID的冷GET成功。该限额仅用于受控验收，默认512MiB任务/1GiB总任务保持。采样属于逻辑账本，不是RSS或完整生命周期峰值。

独立旧canonical字节与完整payload对照、0/1/2/3字节、Base64余数和48KiB边界/空文件、Unicode、全部section缺失/重复/乱序、隐藏旧审计/文件/回执/state/根/孤儿、重算有效链及根后仍无效的映射/类型/更正治理锚、额度/错误排空均有针对性单位覆盖。真实SQL/HTTP验证15类wire/lean/projection故障和6类启动失败，失败不缓存；两次分段间实际篡改原文件或旧审计时，当次保持旧RR快照，下一请求在revision不变时拒绝。canonical后投影期间取消也会排空、归还并重新证明。

实际普通上传、同键跨核心回放、本人终审拒绝/独立批准、SID/CSRF和旧加密审计游标跨重启、原件SHA及20000行CSV保持。`npm run cold:live:verify`只读核对原4010原件长度/SHA/MIME、CSV独立模型/原生下载、完整及分页审计、角色及移动端；升级还需同会话/旧游标、离线逐表/完整历史以及前后业务加密备份隔离恢复。
