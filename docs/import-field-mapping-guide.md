# 企业上传字段映射

更新日期：2026-10-15。方案A本机开发功能，不是生产验收。支持七类CSV/XLSX；JSON继续使用标准机器字段。

## 使用顺序

1. 企业管理员进入“企业模板”，选择“新建上传映射”。默认草稿为DEVICE设备台账、manual-excel来源。按企业样表修改模板编码、版本及manifest.importMapping：dataType、sourceSystem、templateVersion和columns。
2. columns每项只声明sourceColumn原表头、targetField标准字段。目标字段必须来自对应标准模板；可以配置中文原表头，不执行值转换、日期猜测、单位换算、默认值或脚本。
3. 保存并提交冻结版本。另一名具备template:publish的用户核对配置并批准；创建/任何编辑/提交者即使叠加角色也不能自审。发布模板不等于批准业务数据。
4. 上传人员进入“数据上传中心”，选择同数据类型、同来源系统的已发布映射，再选择文件。进入上传/模板页会刷新模板列表；旧页面提交失效配置仍由服务端拒绝。
5. 查看标准化预览和“冻结字段映射”，核对原表头、标准字段、版本与摘要。校验失败时行错误和CSV导出同时带原字段与标准字段。
6. 另一名业务终审人员复核后入库。设备、测点定义、测点记录仍需依次批准；映射不能绕过编码、单位/范围、质量、时间、去重、独立终审或只读设备边界。

默认草稿的原表头为：原始记录编号、设备编号、设备名称、工厂编码、产线编码、设备类型。设备类型可选；实际文件可以省略映射中的可选列，不能省略必填列，也不能多出未配置列。来源记录/设备/工厂/产线编码值仍是标准编码，不因中文表头而允许任意中文编码。

## 文件和版本

CSV为UTF-8，XLSX仅一个data工作表，不支持公式、宏、加密或外链。现有10MiB、10,000行、Excel展开和单元格限额保留。表头匹配仅去首尾空白；原表头原样保存，修整后重复、空值、保留名称及控制/不可见字符拒绝。缺列或多列是文件级400，不创建伪造“第2行”错误。

批次保存原文件、SHA-256、物理行号、标准化输入、原表头、mappingBinding与独立审批。映射发布新版本时旧版RETIRED，只禁止创建新批次；旧批次按冻结版本完成，原请求重试返回原批次。退役不等于紧急吊销；如需停止某待审批次，由终审人员退回/驳回并留理由。

批次快照覆盖映射、原表头、文件摘要和行号；启动与审批校验绑定内容、原发布模板及原接收审计，发现删除/篡改时失败关闭，不静默重建。旧标准上传的业务、审批和摘要不改写。已有业务记录更正仍未实现，相同ID不同内容继续拒绝覆盖。

## API

文件接口保留POST /api/v1/data-imports，multipart新增mappingRef文本字段，JSON内容含templateId、version、contentDigest。租户从经验证身份取得，调用方不能提交映射规则本体。必须使用本企业已发布映射，并匹配dataType/sourceSystem；幂等摘要包含映射引用，同键不同映射返回409。

JSON接口POST /api/v1/data-imports/records仍只接收标准字段；mappingRef、旧预留mappingVersion均拒绝。需要中文表头的第三方可使用文件接口。源文件、批次、审批、原错误接口保持原路径；模板复用/templates的草稿/编辑/提交/审批/导入/导出。详见api/data-upload.openapi.json。

## 验证证据及边界

npm run mapping:verify在随机隔离企业库、临时OIDC用户/客户端测试真实页面发布、CSV/XLSX、两设备类型、独立终审、租户/来源/类型隔离、旧版幂等/并行版本、SQL故障整体回滚、重启、损坏绑定阻断、XSS和320/390手机。仅删除本次成功创建的QA数据库/角色及临时身份，不操作客户业务数据。结果见outputs/import-mapping-verification.json。

这不是自由低代码平台：没有值转换、AI自动映射、紧急模板吊销、已批准字典更正或完整模板差异继承。企业字段映射已具备基础机制，不等于所有客户80%差异已被配置覆盖，也不代表细粒度权限、生产部署、容量或整套灾备已验收。
