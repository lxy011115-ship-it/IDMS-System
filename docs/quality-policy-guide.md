# 独立质量规则与历史评估

设备类型的质量参数仍随批准定义批次冻结。独立质量策略用于为具体设备建立可版本化、独立审批、按明确时刻生效的检查规则，不需要为修改阈值而更正测点定义。

## 建立与发布

在“企业模板”点击“新建质量策略”，填写策略编码、版本、已批准设备编码、变更意图和依据，再填写生效条目及各条规则。每台设备限一个质量策略编码族，同族不能换绑设备或继承别的模板。

每条规则可选择全部已知测点或指定测点、批准上传/设备采集/两种来源、检查指标、比较符、阈值、严重度和依据。保存是草稿，提交后内容冻结，须由另一位有终审权限的人独立批准。生成、编辑和提交参与者均不能终审。退回或驳回保留版本，修改需复制为更高版本。模板包导入后仍是本企业草稿，不继承发布状态与审批身份。

质量策略包的浏览器导入上限为 8 MiB，仍受服务端 schema 与事务资源预算约束；其他模板保持 100 KB 上限。完整包不会因超过旧模板文件大小而被截断。

首次建立选择 `INITIAL`。`PROSPECTIVE` 只修改未来，必须完整保留批准记录时刻及之前已生效的条目；`RETROSPECTIVE_CORRECTION` 明确修订历史并说明依据。发布会在持久批准事件的精确逻辑时间再次校验，若跨过边界使未来调整变成历史改动，发布、旧版退役及审计一起回退。高版本替代当前版，旧版及批准事件保留，按资料截止仍可选择旧版本。

生效条目可显式暂停规则；暂停显示未知，不能当作质量通过。多个条目须按带时区的生效时间严格递增。复制版本时不会带父版本或批准身份，仍需复核意图和全部规则。

## 指标含义

| 指标 | 数值与条件 |
| --- | --- |
| 非 GOOD 记录比例 | 本段 `quality != GOOD` 的记录数 / 本段全部记录数 × 100；无记录时未知 |
| 重复采样时间记录数 | 同设备、测点及采集源、同毫秒的额外记录数；n 条同时间记录计 n−1 |
| 单位不符记录数 | 与截止前批准定义的单位不同，不自动换算 |
| 超物理范围或无效值记录数 | 与历史批准定义的物理录入范围比较；空或非有限值计异常，单位不符时范围比较保持未知 |
| 记录槽覆盖 | 有记录的计划槽 / 本段计划槽 × 100 |
| GOOD 有效槽覆盖 | 至少一条 GOOD 且满足定义及采集接收/映射绑定的计划槽 / 本段计划槽 × 100 |
| 缺少计划槽数 | 本段计划槽数减有记录的计划槽数 |

比较符为大于、大于等于、小于、小于等于；比例阈值是 0–100 的有限数，计数阈值是 0–25,000 的整数。阈值和依据须经企业复核，示例不是行业标准或厂商健康限值。物理录入范围不等同健康报警阈值。

每段显示记录数、计划槽、有效槽、缺槽和部分槽，分别评估阈值，不跨不同版本或分母平均。明确停产且没有计划槽时，覆盖指标为不适用，不能把零分母显示为 100%。没有明确日历或批准间隔时，相应覆盖指标未知。

## 历史评估与导出

进入“质量规则评估”，填写来源、已批准设备编码、时间窗口和资料截止。时间须带 Z 或明确 UTC 偏移，窗口左闭右开、最长 31 天。后端在同一可重复读快照中先验证完整业务根和当前设备范围，再选择截止前的定义、有效更正、已接收记录、配置观察、日历及已批准质量策略。

规则和日历边界合并切片，先按资料截止选策略版本，再按事件时间选本段规则。截止后的规则修订、定义更正、迟到记录或点表变化不改旧截止结果。采集首次配置观察之前的点表不可推断，返回 422。

每条规则显示数值、阈值、严重度、触发/未触发/未知/不适用及原因，来源例证最多 5 条，计数和摘要覆盖完整输入。无策略、策略未生效、明确暂停、未匹配规则/测点、无记录、缺批准定义、接收或映射不可信均保留条件，不能因此显示通过；点表外记录单列且阻止总体通过。

“规则未触发”只表示本次明确检查没有触发，不代表设备健康、产品质量放行、现场验收或自动工单依据。原质量页的工程检查、设备类型冻结参数及旧覆盖报告保持原算法，不会被新策略隐式替换。

点击“导出完整质量评估包”可取得完整输入、所选策略及批准来源、规则版本、结果和摘要。运行：

```text
node scripts/verify-quality-evaluation.mjs --file <评估包.json>
```

工具会独立重算并比较全部摘要和结果。该包不是持久终审报告；普通 SHA 和包内来源仅证明内部一致性，工具返回 `externalAuthenticity: NOT_PROVEN`、`persistentApprovalReport: false`。它们不能证明外部签名、签发者或可信授时。持久审批报告仍使用上一阶段的冻结覆盖报告入口；其他分析报告继续开发。

## 权限、限制和运维

当前角色与设备范围同时约束策略列表、草稿、提交、批准、模板包导出、评估及旧幂等回执。撤权不会因历史批准或旧成功回执而恢复访问。租户管理员和审计员仍沿用原企业范围语义，受限终审员按工厂/产线/设备范围检查。

每个策略最多 64 个生效条目，每条最多 32 个规则；一次评估最多 129 个合并段、2,048 个测点/段、4,096 条规则评估及 25,000 条完整输入。分页不会缩小汇总或摘要，超限、预算不足、取消或证据损坏失败关闭，不返回截断成功。逻辑资源账本不是物理内存或生产 SLA 证明。

新用途复用原模板和审计存储，不新增表、迁移或应用权限。迁移 1–5 及旧校验值保持；质量策略随企业业务库备份恢复。身份、密钥、流程、边缘及模型的跨服务恢复和 RPO/RTO 仍未验收。原平台核验只读取客户业务，不向原企业写测试规则或数据。

核验入口：`npm test`、`npm run build`、`node scripts/verify-quality-policy-sql.mjs`、`node scripts/verify-quality-policy.mjs`。实际 PostgreSQL 上传与采集固定向量在 `scripts/fixtures/governed-quality-v1-golden.json`，`governed-data-quality-1.0.0` 的结果与摘要不能被无意改写。

API 契约见 `docs/api/data-upload.openapi.json`。健康标记：`qualityPolicyGovernance=approved-effective-quality-rules-v1`。完整商用方案 A 仍在推进，生产验收尚未通过。
