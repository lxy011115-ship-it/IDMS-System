# 现场通道：正式目标数据恢复命令进度

本次继续完整方案A第6项。新增 `restore-target` 数据恢复协调器，将已完成的归档认证、受控目标准备、分段数据恢复和最终核验接入同一个恢复操作。结束仍为RESTORING；应用与迁移身份保持NOLOGIN，备份身份只读。维护实例、当前外部状态复核、独立终审、激活和部署继续原计划。

命令沿用 `scripts/field-recovery.mjs`，明确提供 `--action restore-target`、原操作ID、权限配置、源配置、控制文件、三份目标配置、归档及密钥文件。配置与密钥均保留在私密工作区。归档须为含捕获上下文的v3；完整GCM认证、dump SHA及原操作、源冻结和归档记录绑定成功后才允许目标DDL。源数据库不需要在线。

恢复先持久运行和工具记录，再生成或执行固定PG16工具。每段计划绑定实际dump、SQL、前置与阶段标记文件、程序摘要、原阶段及新阶段。pre-data、data、post-data分别由psql单事务执行，数据库阶段注释与该段SQL同COMMIT。重试按真实库内阶段和不可变计划辨认已提交段；不能再次COPY。旧原生进程、检查助手及匹配数据库后端必须确认实际终态后才能复用工作文件。未知会话与对象不接管。

post-data后先核对精确的未授权还原基线，再一次性套用编译权限并封闭迁移身份。已经封闭的目标只核验，不自动修复权限漂移。通过原始完整事实校验后，真正重绑定两套迁移表的部署角色；原时间、校验和、其余字段及触发器O/A模式保持。再追加唯一 `FIELD_TARGET_RESTORE_VERIFIED` 审计、仅增加一次根revision，并在同事务写入VERIFIED阶段摘要。最终完整重扫成功后才持久结果。

新增两个已由真实测试发现的边界处理：

- 根记录原始JSON文本保留PostgreSQL微秒精度，先与源表完整SHA核对，再用于重建旧根和派生视图；旧facts-v1 Date语义不改。
- 核验审计的唯一编译序列使用事务性RESTART。提交前终止时审计、根、角色重绑定和这次序列分配一同回滚。独立只读会话先验证旧存储，拥有事务实际读取新序列并核对新审计；真实COMMIT后再次独立扫描，完整摘要相同才记结果。源事实入口的强制权限及独立只读备份检查保持。依据：[PG16 ALTER SEQUENCE](https://www.postgresql.org/docs/16/sql-altersequence.html)，并以实际双会话和中断验证确认。

验证使用独立自有QA库，真实初始化、2点2回执、持久冻结和v3归档；将源库改名使原连接不可用，目标使用非UTC会话并保留ALWAYS迁移触发器。测试覆盖同操作重试、提交前后中断、提交后应用回复丢失、旧行/序列与唯一审计、权限漂移和未知会话拒绝。原4010实例没有重启或部署FIELD；既有66个完整文件契约和十轮双份快照继续校验，不创建第11份最终验收快照。

本进度不能代替全链验收。活跃SQL事务期间的原生工具崩溃、维护实例及当前OIDC/工作流独立终审、跨宿主恢复、大库容量与Linux写入仍需后续验证。完整商业目标保持ACTIVE。
