# 原版本重启恢复与隔离还原观察器 R4

本阶段恢复原冻结 v2 本地实例。未升级线上核心，也未将独立 v4 控制台接入原站点；云端和域名公开入口没有变更。

## 变更

旧隔离还原观察器把 PostgreSQL 原生 autovacuum worker 当成外来登录，导致备份校验后的临时目标无法正常回收。新增 `scripts/core-upgrade-archives-observed-r4.mjs` 和对应 `reconcile-private-restore-targets-r4.mjs` 修订，保留原 R3 源码。

R4 读取实际 `pg_stat_activity`：精确角色名称和 OID 的 client backend / parallel worker 属于该还原；仅 `usesysid` 与 `usename` 同时为空、`backend_type` 精确为 `autovacuum worker` 时识别为原生清理进程。所有进程均等待自然退出，实际观察到零连接后才继续。未知身份立即拒绝；不强制断开连接。此检查不是数据库 DDL 并发隔离的完整证明。

## 已验证

- 四项单元测试：角色身份、原生 worker、未知登录立即拒绝、自然退出后实际空集。
- 实际 PostgreSQL：外来管理连接被拒绝后仍可查询；自有连接自然退出后观察到零。
- 恢复尝试 R2：原物理集群和 913 个冻结源文件保留，九项服务身份及实际数据库连接归属核对通过。
- 两租户恢复前后各一份加密备份，共四份完成实际隔离还原；失败尝试 R1 的七份密文只重新认证保留，不冒充成功的恢复后轮次。
- 两个实际浏览器 PKCE 新会话验证原文件、CSV、范围、会话/CSRF、加密审计游标和维护门禁；测试身份、会话、Cookie 和自有标签已清理。没有声称保留了重启前会话。
- 恢复写入后，24 个新增采集确认逐个匹配实际签名信封、SQL 回执、测点和唯一审计记录。该数字是一次读取快照，不是持续吞吐指标。
- canonical 571 项单元测试和 16 组历史只读保值检查通过；Git 工作副本不包含既有九项未发布 legacy-edge 测试，测试总数另记。

## 保留限制

R4 继承旧捕获函数的失败路径：若清理观察器抛出异常，后续 `admin.end()` 可能被跳过。R1 的三个泄漏管理连接已依据精确进程、端口和 PostgreSQL 身份验证后随自有旧 owner 退出而消失。R2 成功路径已完成；后续应以独立 R5 修订修复嵌套 finally 并增加真实失败路径验证，不能直接改动仍被活动 owner 固定的 R4 输入。

原界面在 320px 视口有 15px 根滚动条横向溢出；受限 Chrome 页面观察到三项异常，尚未完成产品与扩展来源分类。恢复检查中的旧横向宽度守卫通过不代表完整响应式验收。未宣布商业验收、现场预测有效性、HA/PITR 或公网部署完成。

下一步继续预测任务的真实身份、独立 worker、HTTP 和界面接线；保留旧 outbox 迁移、整站受控切换及其他商业验收待办。域名继续等待备案后的公开启用流程。
