# 现场归档：真实数据导出中断验证

本阶段继续完整方案A第6项，补源pg_dump实际导出数据过程中的控制进程终止验证，并修复进程连接环境受继承PG服务配置影响的问题。恢复保持RESTORING；本阶段不开放激活或部署原核心。

两组场景分别使用控制器直属pg_dump、监督者独立持有的真实固定PG16 pg_dump。监督者绑定源QA数据库、只读backup角色、导出快照及唯一application_name。代理先完整转发至少一组非空COPY TO数据并观察真实服务端COPY完成行数，再截住下一COPY的数据或结束消息。因此被中断工具已实际接收数据，并非仅停在本地握手。

源服务器可能已将小表写入TCP缓冲，故检查并报告实际active或idle in transaction状态及仍保留的backend_xmin，不冒称始终处于服务器活跃查询。中断前还实际读取未完成文件的PGDMP前缀，固定pg_restore离线完整数据提取必须非零退出。离线检查只生成私密SQL，不连接目标或执行未认证的数据语句。

控制器终止后，确认没有ready/result或加密产物；未完成dump仍留在私密操作目录。独立持有场景要求原生工具及代理socket继续存活，明确其物理父进程是监督者。下一正式archive先退休原生、检查助手和精确源后端；新工具登记前，探针实际确认旧PID与创建时间已终态、旧导出后端不存在、旧partial已删除。随后使用不同runId重导，保留原backupId与意图，按正式协调器前后复核全部源事实。

新归档完成全GCM认证、清单和dump SHA核对，再执行完整目标恢复：源库改名使原连接不可用、非UTC会话、ALWAYS迁移触发器、2点2回执及35关系完整事实核对。重复archive保持同一完成密文；重复restore-target保持唯一核验审计、根和序列。没有把未完成dump作为可恢复归档。

连接环境回归先用真实固定pg_dump、本地测试端点及虚假数据库凭据复现：无效继承PGSERVICE/PGSERVICEFILE让工具未连接显式端点即失败。生产启动现在先清除继承PG变量，再设置绑定的连接身份、只读和超时。修复后实际连接指定测试端点，取消并等待真实close；两组真实导出故障也继承无效服务配置，仍必须连接已核对的源。其余恢复协调器与权限路径沿用上一阶段。

协议正文、认证数据、配置、密钥、dump、SQL及原始日志不进入公开进度。所有自有控制器、实际原生工具、代理socket及源后端确认终态后才清理已核对的QA资源。原4010、原两企业及旧66完整契约和十轮双份快照继续保全。

本阶段不替代大库容量、跨宿主或Linux写后端验证。后续继续FIELD关闭且业务停写的维护实例、当前OIDC/工作流外态与独立恢复终审、新注册、证据冻结与离线CLI全链，再执行原核心受控切换。完整商业目标保持ACTIVE。

本阶段最终验证：两类真实源数据导出中断及相应正式目标恢复、真实继承服务环境前后对照、旧v2/旧v1意图原密文复用与无DDL拒绝、旧八控制中断/基本CLI/SQL/25非法档/160MiB合成流回归通过；485项核心测试、230构件及类型检查通过。dummy端点使用虚假账号，真实authority持锁另用已有配置，二者不混称；这项环境握手对照不替代两类真实COPY OUT场景。原运行、角色、66契约及十轮双份快照已重新核对；13恢复生产文件不变，归档生产变更只含连接环境helper及其spawn引用。公开本文与JSON双份逐字一致，仍未部署/激活/商业验收。
