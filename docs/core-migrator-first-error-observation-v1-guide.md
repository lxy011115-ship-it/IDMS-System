# 原核心迁移首错观察

当前主开发分支的核心 V20 曾在站点工厂建立期间失败，公开位置为 `database-migrations.mjs:127`。该位置包含 ROLLBACK 与重抛，具体原始异常尚未取得。后继 V23 保持原核心 import 顺序和 37 项场景，Windows、Linux 均已通过，但这些成功不能说明原失败的触发条件已经消失。

新的 `scripts/run-core-migrator-observation-v1.mjs` 固定加载原 V20 文件，并先核对它的完整 SHA-256。原 V20 与生产迁移模块保持原字节，参数保持，子进程没有继承额外的 `--import` 或 `NODE_OPTIONS` 注入。

观察器只针对迁移账户的 Promise 形式 `pg.Client.connect/query` 失败。它返回原 Promise，继续抛出同一个异常对象，保持原 SQL 与参数对象；不重试、改 SQL、调整超时、关闭连接或发送控制信号。回调形式保持原调用，不改写回调。原入口结束后恢复此前的方法；方法被其他代码改动时报告冲突，不覆盖陌生实现。

最多输出 64 条错误记录，内容为本次客户端序号、查询序号、固定操作类别、SQLSTATE、允许的错误码、消息摘要和固定 pg 驱动状态分类。正文、参数、账户、密码与私密 URL 不输出。首个查询失败与后续 ROLLBACK 失败分别记录，观察器自身输出失败不改变原异常。

4 项单位检查覆盖返回 Promise/参数/异常身份、首错与回滚错的顺序、回调透传、日志上限和真实 TCP 断连。真实 Windows TCP 关闭返回 ECONNRESET，测试接受该实际网络错误及 pg 的连接终止分类。新的完整 Windows/Linux 原生结果需以实际退出和独立检查为准。

诊断分支只运行这条原入口观察工作流。其他主开发分支门禁及其历史失败保持。若本轮没有复现原错误，应继续记录为未复现，不能把未观察到错误当成根因已修复。Broker、边缘、签发与接收、AI/模型和整套部署、图文及演示视频要求继续保留。
