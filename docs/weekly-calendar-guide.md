> 后续已增加独立日历生效安排及knownAt审批截止复核，见[日历生效安排](calendar-history-guide.md)。下文CURRENT模式仍按当前发布配置；EFFECTIVE仅重放日历，定义/数据/点表仍为当前授权结果。

原本机4010已受控部署并只读验证，实现 `calendarRecurrence=frozen-weekly-exceptions-v1`。循环配置沿已有运行日历、批准设备范围、草稿冻结与独立人工终审；计划覆盖继续分别检查批准上传和设备采集。完整商用方案仍在开发，现场接入仍未验收。

## 使用

企业管理员进入“企业模板”，选择“新建循环班次日历”。填写设备与模板编码、明确带偏移的声明范围、命名时区，编辑 `recurrence`。保存时服务器展开UTC区间，并记录编译器、时区数据库版本、规则来源摘要和展开摘要。提交后由另一位有设备范围权限的终审员复核完整配置及展开结果，再批准发布。

新入口默认工作日08:00–16:00，未列班次的时段明确声明为STOP；这只是待修改的作者样例，不是企业实际计划。周末或节日不会由系统猜测。编辑/复制循环配置时，编辑器仅显示作者规则，保存会按当前时区版本重建，再次独立终审；旧发布版及其展开区间、摘要和审批不改变。

```json
{
  "deviceCode": "DEV-01",
  "timeZone": "Asia/Shanghai",
  "from": "2026-10-11T16:00:00Z",
  "to": "2026-10-18T16:00:00Z",
  "recurrence": {
    "version": 1,
    "outsideShifts": "STOP",
    "outsideReason": "明确计划：非班次停产",
    "ambiguousTime": "REJECT",
    "nonexistentTime": "REJECT",
    "weekly": [
      {"id":"day","isoWeekdays":[1,2,3,4,5],"start":"08:00","end":"16:00","endDayOffset":0,"reason":"工作日白班"}
    ],
    "exceptions": [
      {"date":"2026-10-12","reason":"该当地日整日停产","shifts":[]},
      {"date":"2026-10-17","reason":"仅安排临时加班","shifts":[{"start":"10:00","end":"12:00","endDayOffset":0,"reason":"批准加班"}]}
    ]
  }
}
```

以上为 `manifest.operationCalendar` 的作者内容；模板外层仍需 `purpose: operation-calendar` 和原只读设备/独立人工终审策略。首次保存不需要手写 `periods` 或 `expansion`，它们由服务器产生。质量工作台的“计划采样覆盖”会显示当前日历版本、周规则/例外数、冻结段数与时区版本；完整区间在模板详情中查看。

## 周界、跨夜与日期覆盖

ISO星期1为周一、7为周日。每条周班次有唯一编码、星期集合、HH:mm起止与明确 `endDayOffset`：0为当日、1为次日；班次大于零且不超过24小时。结束可用24:00，开始不能用24:00。周规则之间不允许重叠，包括周日夜班进入下一周的部分；不自动推断优先级。

日期例外替换**该当地日期内全部班次片段**，包括前一日夜班落入的部分；空 `shifts` 代表该日全部声明停产。例外班次只能在当日，跨两日安排须分别填写两日。它不自动取消相邻日期的整个夜班：例如周一整日停产，仅排除周一00:00–24:00，原周一夜班落在周二的部分仍按周二是否另有例外处理。星期六的加班例外也会替换该日原有计划，而不是与之叠加。

例外范围外或未列的时段按显式 `outsideShifts: STOP` 和填写的依据处理。声明范围之外仍是未知。裁切后每个冻结RUN段沿已有覆盖规则，以其起点固定分槽；例外造成的分段会形成新的RUN起点，不把跨停产的槽拼成连续槽，也不合并相邻班次改变采样锚。

## 时区与冻结

当地钟点可能因偏移变化重复或不存在。[Temporal 的时区说明](https://tc39.es/proposal-temporal/docs/timezone.html)解释了两种情况。本应用要求明确选择重复钟点的 `EARLIER`、`LATER` 或 `REJECT`；不存在的班次钟点始终拒绝，不能借EARLIER/LATER把它悄悄平移。可用对应日期例外声明有效的新班次。

当地日长度按实际时区计算，支持23/25小时日和半小时切换。日期例外的“整日”按当地实际日边界，午夜跳变不虚构缺失的一小时。整日跳过的当地日期没有实际时间长度，周规则不为它生成24小时，并在 `expansion.skippedDates` 列出；显式引用该不存在日期的例外会被拒绝。跨入不存在钟点的班次端点仍需调整，不能猜测。

当前使用锁定的 [@js-temporal/polyfill 0.5.1](https://github.com/js-temporal/temporal-polyfill)，并记录Node提供的tzdb版本。普通读取不重新展开，因此已批准日历不会随运行时tzdb更新而漂移。导出的冻结包同时保留声明和展开；导入须校验当前编译器/tzdb及重算结果，声明/展开不一致或版本不同会拒绝。需要采用新的时区规则时，应从作者声明显式重建新草稿，不能替换旧发布版的派生字段。

## 限制与权限

周规则最多32条、日期例外最多128日、每例外最多32班、声明范围最多366天、冻结展开最多8192段；超过时应缩短范围或减少班次，不返回截断结果。旧显式日历仍保持512段限制和原JSON/摘要语义。HTTP、任务、SQL等默认预算未提高；展开过程受现有事务预算约束，失败不留下草稿或审批审计。大量日历的完整模板列表和同步编译CPU仍有既有资源边界，不是生产容量/SLA承诺。

设备必须已经批准并在当前身份范围内。创建、编辑、提交、审批、列表、导出和旧幂等回执重放均按现有设备范围检查；自审仍被拒绝。来源类型、模拟标记和条件不足保持；覆盖率不是设备健康、模型精度或质量放行结论。历史查询仍使用当前批准定义及当前发布日历，历史当时配置重放和报告冻结尚待实现。
