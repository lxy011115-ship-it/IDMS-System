# PostgreSQL 原位补丁与回退演练（2026-11-05）

结论：新建合成业务集群已实际完成16.10至16.15的同目录启动、升级后写入、旧检查点回退，以及升级后新写入的独立恢复。当前原企业系统仍运行16.10；本页不是原平台已经升级或生产放行的证明。

## 对象和执行范围

使用新生成的D盘数据目录、回环端口、账号和密钥。16.10初始化后执行当前业务迁移，包含两个合成企业、独立应用/迁移/备份角色、1,000条业务审计，以及经过独立审批的部分收货采购。演练未启动、迁移或写入原C盘PGDATA，也没有重用已激活的采集恢复操作；原实例身份另通过既有只读绑定检查核对。

旧版正常停止后，通过既有整库冷备原语创建升级前的AES-GCM加密物理档案，完整认证并校验每个文件。随后16.15实际打开同一个测试数据目录，核对目录身份、进程创建时间、程序摘要、数据库系统ID及SQL报告版本。

## 实际结果

| 阶段 | 验证结果 |
| --- | --- |
| 升级前检查点 | 两企业当前业务及备件结构可用；1,000条业务审计通过完整校验；合成采购已收4只 |
| 同目录16.15启动 | 表事实、规范业务/审计、备件锚、所核对角色/数据库/关系及函数OID、授权、成员关系和序列值与升级前一致 |
| 升级后业务写入 | 当前备件事务补收6只，库存变为10；原请求摘要和幂等键核对通过，重放未新增回执或重复库存，审计删除权限仍拒绝 |
| 新写入保全 | 正常停库后，为含新收货的16.15状态另建完整认证的整库冷备，分别保留两个恢复点 |
| 旧版回退 | 从升级前冷备还原到全新目录，以16.10实际启动；完整业务、审计、表事实、所核对目录对象及序列回到旧检查点，库存为4，后续收货回执不存在 |
| 新写入独立恢复 | 从升级后冷备还原到另一个全新目录，以16.15实际启动；完整核对升级后状态，库存为10，原新收货回执存在且按原键重放不重复入库 |
| 还原准入 | 旧档案使用不匹配程序集还原时，在创建目标目录前拒绝；正常还原完整认证及逐文件摘要核对通过 |
| 正常停止与空间 | 所有自有测试实例正常smart停止，核对零其他客户端、无预备事务、进程身份消失及干净离线控制状态；三个原始测试数据目录回收245,963,718逻辑字节 |

两份加密整库档案共164,376,393字节，与密钥、完整SQL核对记录、进程和清理收据一起保留本机私密目录。它们仅包含本次生成的测试集群，不是原平台的整库备份。

## 中断和续办依据

演练先后遇到两处验证器问题，失败记录均保留：Windows正反斜线比较未归一化；提交后观察库存时直接读取分区表，被现有权限拒绝。修正只涉及本机测试验证器，没有修改应用权限或运行源码。

第一次根据原启动意图、原生启动助手成功终态、PID出生时间、目录身份、程序摘要和SQL身份，重新绑定同一个已启动实例，没有重复派发启动。第二次先确认测试库已正常停止，再按已有回执、审计中的原请求摘要及原幂等键确认已经提交的6只收货；库存观察改用已授权父表，分区直接读取仍被拒绝。没有用新请求键重做业务动作，也没有重新初始化集群以绕过失败。

## 回退边界和剩余工作

这次证明了两个独立恢复点。恢复旧检查点不会自动包含之后提交的收货；后续状态已由另一份冷备实际恢复，但没有自动合并两个分支，也没有覆盖Flowable、AI或其他外部效果。不能把本次结果写成“无条件回退不丢数据”或生产RPO/RTO承诺。

原系统仍需覆盖现有全部数据库、身份/会话、工作流、AI和边缘缓存的同版一致性与恢复，以及真实服务排空、围栏、配置/密钥与模型保护、企业多岗位签收和生产部署。本次合成集群演练不替代这些要求，也不完成原C盘运行文件迁移或增量架构整合。总体状态继续按[交付验收清单](prelaunch-acceptance-status-2026-11-05.md)核对。
