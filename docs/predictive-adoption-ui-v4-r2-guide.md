# 旧预测任务接管工作台（WIP）

此版本把原人接管、同编号恢复和原有独立重试控制放进预测页面。使用独立新页面和静态包装，保留先前 UI、接管后台、worker 与 SQL 源文件。原站点和云端没有自动切换。

部署入口为：

```
node scripts/predictive-console-adoption-ui-v4-r2.mjs <explicit-private-runtime.json>
```

私密配置和权限分离沿用接管后台指南：HTTP 使用 QI/READER，worker 使用 APP 和真实服务材料；新目标需先安装 fresh `predictiveJobsSchemaSqlV4R2`。页面路径仍为 `/predictive/`。不要在当前活动库在线追加 DDL，或把测试配置、登录凭据与服务密钥放进仓库。

操作流程：

1. 使用原操作人的当前账号登录。在设备任务旁选择“核对并接管原任务”，或到“提交与恢复”选择“待接管的本人原命令编号”。其他用户不能代替原人接管。
2. 核对原状态、设备、原命令和操作人。可能已在外部建单时，页面明确提示沿原命令恢复。此前关闭过接受的命令，必须展开对应选项并明确勾选恢复。
3. 点击“确认使用当前授权接管”。“已接收”表示请求已保存；只有原生结果核验后才显示完成或取消。发生中断时先查询原接管决定，需要重发时仍用同一接管编号。页面不会在轮询中自动提交新决定。
4. 人工审核状态不会因接管而消失。由另一位具备权限和范围的审核人选择“待独立重试的作业编号”提交独立重试决定，再由原操作人登录、打开原作业并明确重新授权。
5. 后续明确决定替代旧决定时，旧卡片显示“已有后续决定”，不会再执行；新决定沿用原作业和计划。接管决定编号也可手动查询恢复。

身份、角色或范围变化会清空当前结果、候选和草稿视图，迟到响应不能回填到新身份。无法读取的候选会结束加载并给出可操作说明。浏览器按租户、操作人和部署分开保存最多 30 条恢复元数据，只含编号、摘要、动作及状态，不保存会话、正文、计划、信封或结果。

被取消且外部创建状态不明的复核任务仍要求人工对账，页面不会补造成功或取消结果。独立重试不能替换原执行者。当前是独立接管工作台；新统一站点接线、C workflow outbox 迁移与整站受控切换仍待继续，idms.xin 仍按备案前准备范围处理。
