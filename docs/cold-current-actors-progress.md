# 原恢复会话中的当前人工审核身份：阶段进展

新inspectCurrentActors在原恢复准备器和原持有会话内验证整组参与者。配置issuer绑定原独立权威，工作流authority/BPMN和轮换只读token匹配原意图；不使用外部HTTP工作流入口。作者、全部声明贡献者和独立审核人用真实JWT签名及当前用户、角色、全租户范围、notBefore、客户端和在线会话校验，并在两次原引擎捕获前后重复核验。完整工单和发布策略仍从原完整根事务提取。

Windows通过47项单元测试、37项完整原生检查及独立V6复核。真实Keycloak测试覆盖两企业6名参与者；撤权、贡献者撤权、禁用、范围缩小、会话删除、跨企业、签名篡改、实际到期和贡献者自审等10个负例拒绝。另在身份窗口启动后由独立实际管理请求撤销权限，当前观察拒绝；权限恢复与全新登录后再次通过。所有原32项恢复检查、两类实际COMMIT丢线、七库SQL、完整源与目标根和正常关闭继续保持。

独立复核重建8个运行中完整根输入，核对68份原连接/维护锁证据和新增8份原worker快照，绑定两份双侧身份观察及真实中途撤权记录。JWT原文不保存，签名校验由冻结原生入口实际执行；独立离线复核不声称重新验证JWT原始签名。

保留首次1485输入案例因重复peer校验导致30秒窗口超时的真实失败。修订版仍保留原见证和每次捕获前后的完整peer检查，仅合并冗余外层调用，30秒窗口未变。另保留1492输入因QA部分PUT造成账户资料不完整的失败；新QA仅改为保留和恢复完整用户及客户端快照，生产身份验证逻辑不变。

另保留1497输入案例在等待观察窗口时遮蔽原请求拒绝的失败；该次原始拒绝原因未留存，不能倒推为已定位。新版先保存两个原始结果，并在窗口未出现时优先抛出原请求错误；真实中途撤权仍要求同次观察明确拒绝。

有效reader生命周期V6先等待原操作队列，再严格核同一个WeakMap能力、owner peer与HELD状态，保留所有原JVM/SQL前后核验。6个隔离源码时序测试复现旧版提前拒绝并覆盖失败、释放、替换、伪造拒绝；另以真实原JVM未完成PROBE与严格SQL校验重叠，验证原四连接并退役该测试租约后再创建正式只读会话。旧Linux两次24项失败及本地V5同码失败均保留，不能把事后复现当作旧V3被遮蔽原因的恢复。

本次完整原生使用两端TCP_NODELAY的自有QA提交故障代理，保留真实提交前丢线与提交后回复丢失的完整检查；独立Linux短对照4项通过，但完整Linux恢复仍以本版本实际终态为准。
