# 源码发布与版本核对

更新：2026-10-30。目标仓库为 `lxy011115-ship-it/IDMS-System`，当前候选分支为 `release/prelaunch-20261030`。分支发布、CI、主分支合并及服务器运行是不同状态；以实际提交和检查结果为准。

## 当前版本的依据

`package.json` 是软件版本号的唯一来源；`server/version.ts` 按模块位置读取它，健康接口不再维护另一份固定字符串。当前版本号为 0.1.0。版本号本身不能区分开发中的每次修订，同版交付还需提交 ID、文件 SHA-256、迁移能力和环境记录。

本地服务可能仍运行重启前的模块。发布时必须实际读取 `/api/v1/health` 并核对部署提交及清单，不能仅凭磁盘文件或旧健康结果证明切换成功。跨目录启动的隔离 HTTP 检查防止启动器工作目录改变版本来源。

## 公开文件范围

源码快照使用明确目录：server、services、public、src、scripts、docs、integrations、infra、tests、.github 和保留的 deploy 历史目录，以及根配置、锁文件和启动入口。不包含 node_modules、.local、work、outputs、演示存储、数据库、加密档案、密钥、账号文件、日志及构建结果。

实际枚举执行排除策略，拒绝路径越界、链接、重复和中途改变的输入。快照逐文件检查当前已配置凭据、私钥材料和可疑凭据字面量，并记录长度和 SHA-256。逐项补充 `.gitattributes`、历史 `deploy/idms-pilot.service`、`src/App.vue` 以及脚本实际引用的三个 `owned-verification-restricted-host-v1/v2/v3.cs` 源文件；不放开其他未知类型，也不把离线演示包的扩展名清单当作全部源码范围。此扫描有明确覆盖范围，不等同于完整安全审计。

清单不包含自身摘要，以避免循环；清单文件的摘要记录在独立发布记录中。内部证据中的业务档案、配置、原始日志和用户截图不随源码公开。公开说明指向这些本地证据，不表示它们已上传到仓库。

## 发布步骤

1. 从远端已核实的 main 建立独立候选分支，保留已有提交历史。
2. 完成敏感内容检查、不可变快照和文件清单；逐项核对新增、修改、删除及历史部署资料。
3. 对同一候选执行服务端检查、构建、打包边界和隔离 HTTP 版本检查。Linux CI 使用锁定依赖；检查成功仍不代表 PostgreSQL/OIDC 全平台、云端或生产验收通过。
4. 只推送候选分支，核对远端提交等于本地提交。主分支合并、版本标签、云端切换和公网开放有各自证据，不能用推送成功替代。
5. 部署前记录 `idms_spares` 的 capacity=1 能力、备份和恢复结果及回滚方案。旧代码不能仅凭版本字符串被认定能安全管理新数据库；不覆盖当前企业库来试回滚。

`deploy/` 原文保留 2026-10-20 的独立内部试运行资料，尚未为此次代码重新核验。当前普通启动入口仍为“启动IDMS本地网站.cmd”。根 Compose 和旧云端脚本不能直接用作本轮生产安装说明。

## 增量开发与本地空间

后续直接在现有 Git 工作目录维护同一候选分支，逐次提交、普通推送并核对远端提交与同提交 CI，无需为每次更新保留完整的本地源码副本。Git 历史保留已提交版本；开发中的阶段提交应明确尚未接入的接口、页面或迁移，不能将保存源码称作功能已交付。

2026-10-30 的用料计划阶段已加入领域规则、必要工作集、能力 SQL 和版本化审计兼容；同快照洞察、专用迁移入口、页面接入与完整恢复验证仍按实施计划推进。实际企业数据库和运行进程尚未切换此能力。

本地源码快照仅在远端提交核对通过、文件内容可从 Git 恢复且不再被验证任务引用后清理。保留小型清单和发布记录，并记录删除目标、回收量和恢复依据。数据库、私密配置、密钥、必要依赖及用户交付资料继续单独管理，不作为重复源码清理；GitHub 源码仓库不代替这些资料的备份。
