# 维修工作台 v4

维修工作台通过独立 HTTP 与后台 worker 使用现有维修领域内核。当前在隔离 PostgreSQL、Keycloak 和 Flowable 环境完成验证，未接入原4010或云端主站。公网 idms.xin 仍等待备案。

## 使用

按 `scripts/maintenance-console-auth-v4.mjs` 的显式私密运行配置分别启动 HTTP 和 WORKER，在 HTTP 的 `/maintenance/` 登录。HTTP 使用 QI/READER，worker 使用业务 APP 与固定流程配置；不要向浏览器提供数据库、作业密钥或流程服务凭据。

工单列表只显示当前身份可见范围。维修人依次领取、开始、填写维修与复测记录并提交；维修表按批准模板提供数字、布尔、选项和文字字段。另一位审核人核对证据后批准关闭或退回补充。流程待确认时，业务状态等待引擎确认；人工重试继续原执行者命令，原执行者本人可重授授权。

“我的作业”提供命令编号和作业编号恢复。浏览器只保留最多30条编号、摘要、动作和状态，不保存维修正文、结果或登录凭据。接受结果未知时先查询原编号；关闭原命令接受边界后才允许用新编号提交，已经完成的业务不会被关闭动作撤销。刷新页面后，已完成作业可以再次查询以加载当前有权查看的结果。

草稿仅保留在当前页面内存；刷新或离开页面会丢失。断网或维护暂停会禁用提交，恢复后保留当前草稿。账号或权限变化会清除敏感界面和草稿，并拒绝旧请求迟到结果。

## 本阶段验证

最终浏览器证据为 `work/maintenance-console-ui-v4-20261020/320096c5a666/verification.json`，15项通过，执行前保存输入，结束逐SHA复核。Keycloak直接授权关闭，浏览器实际完成PKCE回调。真实共享会话、独立HTTP/worker和Flowable参与：

- 领取、开始、模板校验、提交、退回、重提交与独立关闭；布尔false和true均保留真实值，注入式标题显示为文字。
- 排队时撤权阻止执行，恢复权限后仍需本人明确重授。
- 未知接受请求在刷新后保持原编号；关闭接受边界后释放迟到请求，旧命令无作业且边界已关闭。新编号只推进一次。
- 接受后丢回复时，Edge透明重试同一UUID，服务端保持一个作业；刷新后查询原作业。此用例未让界面实际出现网络错误，不混同独立离线用例。
- 错误流程回执保持原业务版本；异人重试不取得原执行者授权，原人重授后完成真实流程。
- 实际离线及维护暂停保持草稿并禁用提交；恢复提示与按钮更新。第二页切换受限账号后，旧详情迟到不回填。
- 1440、390、320宽度无表单横向溢出，手机卡片列表按钮横排；截图已人工查看，测试后恢复默认尺寸与网络。

早期UI验收迭代均中止并清理：代理曾丢Host导致登录循环，随后修复转发；列表完成后未刷新和字段原键显示已修复；离线恢复旧提示及320按钮竖排已修复。早期证据不替代最终源版本。浏览器等待作业的短locator超时后，只查询原作业，未重复提交。
